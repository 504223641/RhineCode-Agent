跑测试，并把失败解读成可执行的修复方向。

## 1. 找到测试命令

先看项目配置确定用什么跑：`pyproject.toml` / `package.json` / `Makefile` /
`CLAUDE.md` 里通常写了。找不到就按语言的惯例推断，并在执行前说明你的判断依据。

## 2. 运行

跑完整测试套件。若用户指定了范围（见文末），只跑那部分。

## 3. 解读失败

**不要只把报错原样贴回来**——用户自己也能看到报错。对每个失败：

1. 定位到具体的**测试用例**与**被测源码位置**（读文件确认，不要凭堆栈猜）；
2. 说清**期望什么、实际什么**；
3. 判断是**代码错了**还是**测试写错了**——这两种情况的修法相反，
   判断不了就把两种可能都摆出来，让用户决定；
4. 给出修复方向。

## 4. 关于直接改代码

只在以下情况直接改：失败原因明确、修改范围小、且你已经确认不会影响其它用例。
其余情况先说明方案，等用户确认。

**绝不通过修改断言或删除用例来让测试变绿**——那是把问题藏起来，不是修好。
