按以下步骤完成一次提交。

## 1. 看清楚改了什么

- `git status` 看有哪些文件变动、是否有未跟踪文件；
- `git diff` 看已跟踪文件的具体改动；若已暂存，还要看 `git diff --cached`。

不要凭猜测写提交信息，必须先读到实际 diff。

## 2. 学习本仓库的提交风格

`git log --oneline -15` 看最近的提交，判断本仓库用的是哪种约定：

- 是否用 `feat:` / `fix:` / `docs:` 这类 conventional commits 前缀；
- 标题用中文还是英文；
- 是否习惯写多行正文说明「为什么」。

**照抄仓库既有风格**，不要套用你自己偏好的格式。

## 3. 写提交信息

标题一行说清「这次改动做了什么」，动词开头，不超过 50 字。
若改动不止一处，正文分点说明每处**为什么**要改——「是什么」看 diff 就知道，
「为什么」只有你现在知道。

## 4. 提交

- 只提交与本次改动相关的文件，不要 `git add -A` 把无关文件一起带上；
- 提交前再确认一次暂存区内容；
- **不要**推送到远端，除非用户明确要求。
