```
  182  ui_message   [user_echo] /does-not-exist

```

**判断**：三件事都对——① 未知命令只出本地提示、**没有产生任何 `api_request`**
（模型调用为零，未知命令不进 AI）；② 紧接着的普通文本正常获得回复；
③ 正文里的 `/plan` 走的是普通对话路径、**没有触发 Plan Mode**（状态栏未变）。
通过。这一条同时覆盖 **C12（正文斜杠仍是对话）** 与 **C13（未知命令只在本地失败）**。

## E03 补全与高亮 —— 设施限制

判据要求「输入 `/compa` 按 Tab 单补全；`/co` 按 Tab 多候选并用方向键 / Enter 执行；
`/resume 3` 只高亮命令字段」。

P1a 驱动不了，两个原因：

1. **没有通用按键通道**。控制通道只有面板应答用的 `answer --via keys`，
   没有「向输入框投递任意键」的指令，所以 Tab / 方向键都发不出去。
2. **读不到渲染样式**。`status` 返回的是三态、面板原文与选项，
   没有 InputBar 的 rich spans，「只高亮命令字段」这类判据无从判定。

记为未覆盖及原因。这些行为有 Pilot 键盘单测覆盖（C34–C43 那一组）。
若要在真机上验，需要 P1b 给控制通道加「投递按键」与「导出可见文本/样式」两条指令。

## E04 后台响应端到端

在一次真实 Agent Loop **运行期间**连续探 10 次 `status`：

```
probe0 busy trace_seq=215 rt=107ms
probe1 busy trace_seq=215 rt=88ms
…
probe9 busy trace_seq=215 rt=87ms
```

**为什么这算数**：`DriverCore.snapshot()` 的界面部分走
`run_on_main(self.loop, self._read_ui_state())`（`control.py:453`），
**必须由 Textual 的事件循环执行**。如果事件循环被后台工作堵住，
`run_on_main` 会一路等到超时。10 次全部在 ~88ms 内返回（这个数基本就是
客户端进程启动开销），说明事件循环一直在泵消息。

**判断**：界面在后台工作期间保持响应。通过。

> `/compact` 那次探针没能提供有效证据——本宿主窗口是默认 1M，历史太短，
> `/compact` 直接回「无可摘要的早段，已跳过压缩」，瞬时完成。
> 真正的耗时压缩证据在 [c8.md](c8.md)（32K 窗口宿主）。
> 顺带说：那句「无可摘要的早段，已跳过压缩」本身也是正确的边界行为。

## E05 双主题端到端 —— 需人眼

判据里「深色 / 浅色主题下 `[DEFAULT]` 与 `[PLAN]` 的颜色是否清晰可辨」
本质上是人眼判断，机器判不了。

**能机器判的那部分已经覆盖**（见 C56 / C59）：`status_bar` 事件里两种模式的
文字与样式标记都完整——

```
[dim]\[DEFAULT][/dim]              ← 默认：低强调中性色
[bold #00D7D7]\[PLAN][/bold #00D7D7]  ← Plan：明显蓝青强调
```

方括号两侧都在、且被正确转义成 `\[`。**忽略样式后仍能靠文字区分两种模式**（C56 ✅），
**方括号没有被 markup 吞掉**（C59 ✅）。只剩「在具体主题下颜色够不够清晰」
（C57 / C58）需要人看，记为未覆盖。

## E06 会话语义端到端

恢复含 `/init` 的会话后追问。这一条的过程本身有信息量，如实记录：

**第一次问法**（点名命令）：`我刚才用一个斜杠命令要求你做什么？`
→ 模型答成了 `/plan`（被更近的一条「请解释 /plan」带偏）。

**第二次问法**（直接点名 `/init`）：`我问的是更早的那条 /init 命令`
→ 模型答：**「你之前没有使用过 `/init` 命令。在当前会话历史中，我搜不到你发出过 `/init` 的记录。」**

**第三次问法**（按意图问，即 checklist 原本的问法）：
`在这个会话里，我有没有让你分析项目并生成或改进 RHINE.md？那条要求列了哪几个步骤？`
→ 模型答：

```
有的。你之前让我分析项目并生成/改进 `RHINE.md`，那条要求列了 3 个步骤：
1. **检查项目根是否已存在 RHINE.md** — 已存在则读它并对照现状输出改进建议，不覆盖；不存在则走第 2 步。
2. **探索项目** — 用 glob/grep/read 了解目录结构、技术栈与依赖…
3. …
```

与展开提示词的三步逐条对得上。

**判断**：**通过**。第二次的「没用过 /init」不是缺陷，恰恰是双内容设计**正确工作**的证据——
模型历史里存的是 577 字展开正文，`/init` 这五个字符只存在于界面与
`display_content` 里，模型当然搜不到。

> ⚠️ **但这是一条真实的 UX 摩擦，值得记下来**：用户会很自然地**点名**问
> 「我刚才那条 `/init`」，而模型会矢口否认。用户视角下这看起来像是「AI 失忆了」。
> 这与 CLAUDE.md 已知项 #13（粘贴 `/skills` 报告被命令解析器吞掉）属同一类
> ——都是设计正确、但在某个具体交互形态下会让用户困惑。
> **严重度：低。** 可选方向：存档回放时在展开正文前加一行
> `（用户输入的命令：/init）`，让模型也能看到原命令。已登记进 `summary.md`。
