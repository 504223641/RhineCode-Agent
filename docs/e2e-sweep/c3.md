## 场景 1：读取并回答

输入：`读取 README.md 并告诉我它一共有多少行、列出它的四个特性`
（工作区预置了一个 26 行的 `README.md`）

**机器判到了什么**：

```
   68  tool_execute   read_file · executed · ok=True · 0.0ms · 并发 · 读取 26 行 · 622 B
   71  ui_message     [system] 🔄 第 2 轮
   76  ui_message     [assistant] ## README.md 概况 / **总行数：** 26 行 / **四个特性：** …
```

**判断**：三件事都对——① `read_file` 是只读工具，**没有弹确认面板**（trace 里
`tool_execute` 前无 `tool_decision` 的 ask 记录，`wait` 也直接落到 `idle` 而非 `pending`）；
② 标记为「并发」，走的是只读并发通道；③ 结果回灌后**自动进入第 2 轮**并产出最终答案，
行数 26 与预置文件逐字相符。通过。

## 场景 2：确认拒绝

输入：`在项目根新建一个 notes.txt，内容写「hello」`

**机器判到了什么**（面板原文，取自 `status` 的 `panel.display`）：

```
⚠ 确认执行：write_file(path=notes.txt, content=hello)  · 默认模式：无规则命中，交由用户确认
  ✅ 本次放行 / 🟢 本会话放行 / 💾 永久放行 / ❌ 拒绝
```

驱动器应答 `deny` 后：

```
   89  tool_execute   write_file · denied_by_user · ok=False · 0ms · 串行
                      · 用户拒绝了这次 write_file 调用。**这不是技术故障，是用户的决定。** 不要重试…
   97  ui_message     [assistant] 好，不写。我原本打算…你拒绝了这次写入，想问一下具体原因…
```

补充两项硬核对：

- `Test-Path notes.txt` → `False`，**文件确实没被创建**；
- 拒绝后下一轮 `api_request` 的 `tools` 字段为 `None`（seq 93），
  即 `_RoundContext.user_denied → tools=None` 这条**硬约束**在真机上生效。

**判断**：软硬两道防线都验到了——文案让模型停止推进并询问原因（模型照做，
没有重试、没有改参数、没有换工具绕过），硬约束让它在物理上也发不出工具。通过。

> ⚠️ **checklist 措辞过时**：c3 原文写「弹 `ConfirmScreen` 展示……选 Yes/No」，是**三选项**时代的写法。
> C6 已升级为**四选项**（本次/本会话/永久/拒绝）。本次以当前状态为准判定，不算失败。

## 场景 3：edit_file 唯一匹配失败

这条**用自然提示词触发不到**，过程本身是结论的一部分，如实记录：

| 尝试 | 提示词 | 模型实际行为 |
| --- | --- | --- |
| ① | 「直接用 edit_file 把 `## 授权` 换成 `## License`，不要先读文件」 | **拒绝执行**，凭已读内容指出该行不存在 |
| ② | 「立刻 edit_file 改 config.ini，不要先读」 | **拒绝执行**，逐字引用系统提示的「编辑前必须先用 `read_file`」 |
| ③ | 「把 config.ini 里的 `timeout=30` 改成 `timeout=60`」（该片段出现两处） | 自行加上 `replace_all=True`，**合规避开了多次匹配错误** |

**这两条都是上游防御生效的证据，不是测试失败**：②验到了 C5 AC7「关键规则双重强化」
（「编辑前必先读」同时写在系统提示与 `EditFileTool.description` 里）在真机上真的改变了模型行为；
③验到了工具描述里那句「若该片段会重复出现且都要替换，把 `replace_all` 设为 true」被读进去了。

于是改用**确定性手法**：在 `edit_file` 的确认面板挂起期间，从进程外改掉目标文件，
制造一次真实的 TOCTOU，让 `old_string` 必然 0 匹配。

**机器判到了什么**：

```
  166  tool_execute   edit_file · executed · ok=False · 0.0ms · 串行 · 第 1 处未找到原文
  169  ui_message     [system] 🔄 第 2 轮
  172  ui_message     [assistant] 之前改过文件，让我重新确认一下当前内容：
  177  tool_execute   read_file · executed · ok=True · 16.0ms · 并发 · 读取 9 行 · 88 B
  185  ui_message     [assistant] 看起来在我上次修改之后，文件又被改过了——当前 host 的值已经是 localhost…
```

**判断**：错误路径完全正确——`ok=False`、错误信息点明「第 1 处未找到原文」、
**文件内容未被改动**、模型据错误自行重读并如实报告文件被外部改动。通过。

> ⚠️ **checklist 措辞过时（第二处）**：c3 原文写「本轮不自动重试，符合单轮边界」。
> 那是 c3 的**单轮往返**时代约束；C4 引入 ReAct 循环后，模型自动重读并调整**才是正确行为**。
> 本次观测到的正是后者，按当前状态判为通过。

## 顺带产出

1. **正面观察 A**：C5 的「编辑前必先读」强化在真实模型上是**硬生效**的——两次明确要求
   「不要先读」都被模型拒绝，且它引用了规则原文。这条此前只有单测钉着文本存在性，
   没有真机行为证据。
2. **正面观察 B**：`edit_file` 工具描述里的 `replace_all` 指引同样生效，模型在片段重复时
   主动加了该参数。
3. **两处 checklist 措辞过时**（三选项 / 单轮边界），已在上文标注，建议后续更新 `docs/c3/checklist.md`。
