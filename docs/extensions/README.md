# 扩展文档

**这里放的是「工具/能力扩展」，不占章节号。**

`docs/c2` … `docs/c11` 是**主线章节**——每一章引入一个新的能力层级（Agent Loop、权限系统、
MCP 客户端、上下文管理、记忆系统、斜杠命令、Skill 系统），架构表里会多一层，
`CLAUDE.md` 的能力表里会多一行。

本目录放的是**不构成新层级的增量**：在既有层上加一个工具、给既有机制加一种规则、
扩一个已有能力的边界。它们同样走完整 `/spec` 流程（spec → plan → task → checklist），
同样要审批、要验收，只是**不编章节号**。

## 目录约定

```
docs/extensions/
├── README.md              ← 你在这里
└── <扩展名>/              ← 一个扩展一个目录，短横线命名
    ├── spec.md            ← 做什么
    ├── plan.md            ← 怎么做
    ├── task.md            ← 按什么顺序做
    └── checklist.md       ← 做对了没
```

需要留验收记录时，在该扩展目录下加 `acceptance.md` 或 `acceptance/`，
口径与 `docs/c11/acceptance/` 一致（每条判据分「机器判到了什么」与「据此做的判断」两栏）。

## 怎么判断该进这里还是开新章节

| 情况 | 去处 |
| --- | --- |
| 引入一个新的能力层级，架构表要多一层 | 新章节 `docs/cN/` |
| 在既有层上加工具、加规则、扩边界 | 本目录 |
| 跨阶段的测试设施（不属于任何产品能力） | 随其服务的章节走，如 `docs/c11/testing/` |
| 只是「下一步可能做什么」的候选项 | `docs/todo/` |

拿不准时看一条：**`CLAUDE.md` 的能力表要不要多一行？** 要，就是章节；不要，就是扩展。
