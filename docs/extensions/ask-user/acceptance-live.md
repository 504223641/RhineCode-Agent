## 零、先证明工具真的送到了模型面前

**这一步不做，后面所有「没触发」的观测都不成立**——分不清是「它没看见这个工具」
还是「它看见了不用」，而这两件事的修法完全相反（todo-list 那轮的教训）。

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| B 组会话里 8 次 `api_request`，其中 6 次 `scope=main`，**每一次的 `tool_names` 都含 `ask_user`**（工具数 16） | F1 的可见性判据生效：**不在 Plan Mode、不在规划阶段**的普通对话里，工具照常发给模型。这是本扩展的核心改动，一次真机确认 |
| 另 2 次 `scope=memory` 的请求工具数为 0 | 记忆请求强制 `tools=None` 的既有约束没被破坏 |

## 二、触发率：该问的那一侧

| # | 发给模型的话 | 机器判到了什么 | 据此做的判断 |
| --- | --- | --- | --- |
| A1 | 「给这个项目加一个配置文件，把 API 地址和请求超时时间挪进去」 | **未触发**。模型正文原话：「不过这里有一个取舍需要确认。让我先按最合理的默认做法走……配置文件用 JSON 还是 YAML 会影响读取方式。我按 Python 项目最常见的做法来：用 JSON（无需额外依赖）」 | ⚠ **这不算欠触发，是场景设计不够硬。** 模型**明确识别出了取舍点**，然后按「有默认做法的自己定、并在正文里说明」处理——那恰好是我们写进 F20 下限的行为。JSON vs YAML 确有 conventional default，本就不该问 |
| A2 | 「我要把这个项目开源出去，帮我加上开源许可证」 | **触发**，一次调用带 **2 个问题**（串行弹）。Q1 徽章「许可证类型」，4 个候选项，第一项自带「（推荐）」 | 许可证是**没有技术默认值、纯粹用户拍板**的事（法律后果不同、代码里推不出来）。这类才是 F20 想要的触发面 |
| A3 | 「补一批基础设施：CI、单元测试、README、代码格式化都在候选里。我还没想好这次要做哪几样」 | **触发**，2 个问题，Q1 是 **`multiSelect`** | 「做哪几样」是范围问题，模型自己选了多选形态。⚠ 这一条**带了范围暗示**，触发率证据的分量低于 A2 |

**结论**：默认值确实定在「不问」那一侧，且下限（「有默认做法的自己定」）是**真的在起作用**
——A1 是它起作用的正面证据，不是反面。

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| 表头含 `\[许可证类型]` 徽章 + 问题原文 + `（问题 1/2）` | F9 徽章、F13 进度指示都对；进度只在多问题时出现 |

| 答完 Q1 后面板**原地**换成 Q2（表头变「（问题 2/2）」），`state` 仍为 `pending` | F14：多问题串行弹，面板不收、焦点不跳 |

## 四、新键位的端到端验证（本次改动的核心）

驱动器发的是 `answer "0,2" --via keys`——它在**真实面板上按真实的键**：
移到第 1 项按回车、跟着光标自动前进的位置再移到第 3 项按回车、最后落到提交行按回车。

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| 记录第 256 条：`clarify → 多选 · ClarifyReply(kind='multi', labels=('单元测试', 'CI'))` | **新交互全链路成立**：回车勾选 + 自动前进 + 末项跳过「其它…」直达提交行 + 提交行回车结算 |
| 勾中的是**不连续**的第 1、3 项，中间隔着 README | ⚠ **这一条是分辨力所在**。`cursor = target + 1` 的记账若偏一格，勾中的会是 README 与代码格式化。连续两项测不出这个 |
| 模型收工正文：「按你勾选的**单元测试 + CI** 补齐（README、代码格式化按你未勾选，本次未做）」 | 答案不只是被记下来，是**真的改变了模型接下来做的事** |
| Q1 答的 Apache-2.0 出现在它后来写的 `pyproject.toml` 里 | 跨问题、跨轮次的答案回灌成立 |

## 五、Esc 的新语义（F17）

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| 对 A3 的 Q2 发 `answer skip --via keys`（真的按 Esc），记录第 257 条 `clarify → 跳过 · None` | 结算为 `None` 而不是空多选——两者刻意区分 |
| 随后 `state` 走到 `idle` 且 `quiescent`，模型继续执行并完成任务 | **非规划阶段的 Esc = 「我不选，你自己定」并继续跑**，不是整轮停止。这是本扩展改的语义，一次真机确认 |
| 跳过的那题（格式化工具）模型按最佳判断处理：因未勾选格式化，直接不做 | F17 的回灌文案让模型自己拿主意，没有卡住也没有重问 |

## 七、这次没验到的

- **自由输入态（F16）** 与 **跳过熔断（F17）**：真机会话里模型没有走到这两条路。
  两者都有单元与端到端护栏（`test_ask_user_panel.py` / `test_e2e_ask_user.py`），
  但**没有真实模型的实跑证据**。
- **无人值守轮不弹面板（F3）**：要造一次 C15 自动唤起，成本远高于收益，
  且它由「拿不拿得到澄清回调」结构性保证，有单测反证钉着。
- **`deepseek-v4-pro` 的触发率**：只跑了 `flash`。todo-list 那轮实测过两个模型
  **会分叉**（flash 4/4 而 pro 0/4），因此本记录的触发率结论**不能外推到 pro**。
