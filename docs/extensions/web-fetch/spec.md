# 网络访问工具（web_fetch）Spec

> 状态：待批准（2026-07-29，**第 2 轮修订**：已按独立审查的 8 条阻塞级与 16 条重要问题修订）
>
> 性质：**工具扩展，不占章节号**。它在既有的 C6 权限系统上加一层、给工具中心加一个工具，
> 不引入新的能力层级。文档收在 `docs/extensions/web-fetch/`，见
> [`docs/extensions/README.md`](../README.md)。

## 背景

到 C11 为止，RhineCode 的全部工具都是**本地的**：读文件、写文件、改文件、跑命令、glob、grep。
MCP 工具（C7）虽然可能经 HTTP 与远端通信，但通信目标由**用户在 `mcp.yaml` 里显式配置**，
模型无法自行指定一个地址去访问。

这带来两个后果：

1. **能力缺口**——查在线文档、读一个 issue 页面、看一份 API 参考，模型全都做不到。
2. **安全模型的一个空白区**——因为一直没有这类工具，C6 的权限系统在设计时就明确
   把网络限制排除在外（`docs/c6/spec.md`「不做的事」第一条）。

本扩展补上第 1 条，同时必须补上第 2 条——**否则新工具会落进一个没有防御的位置**。

### 为什么这不是「加个工具」

C6 的五层决策管线里，前两层的入口都带种类判断：①危险命令黑名单只对「命令类」生效，
②路径沙箱只对「读路径 / 写路径 / glob 类」生效。一个网络工具两者都不属于，会落进「其它类」。
而「其它类」在③可配置规则层只能被**不带括号的整工具规则**命中——只有「整个放行」与「整个拒绝」
两种粒度。再往下的④权限模式兜底在放行档会直接放行。

结论：照现状直接注册一个网络工具，它的实际安全边界是**空的**。

### 与既有已知项的关系

- **已知后续工程项 #5**「权限系统后续项：网络请求限制」——本扩展**兑现其中的「网络请求限制」一项**，
  该项其余内容（资源配额、审计日志）仍留待后续。**实现完成后需在 `CLAUDE.md` 里划掉该子项。**
- **已知后续工程项 #4**「OS 级沙箱」——**不在本扩展范围**。本扩展建立的是应用层网络边界，
  管得住本扩展新增的工具，管不住 `run_command` 跑起来的 `curl` / `wget`，也管不住 MCP 工具。

## 本扩展对既有代码的已知改造点

集中登记，避免 plan 阶段才发现：

1. **决策管线新增一层**，在②沙箱与③规则之间。插入位置直接决定安全性（F5/F6），不是实现细节。
2. **权限请求的「种类」新增取值**（URL 类），并**新增一个「主机名」字段**——规则匹配、
   确认面板展示、行为记录三处都要它，由工具规范化层统一填好，避免各处重复解析。
3. **规则匹配新增第三种算法**（域名模式匹配）。
4. **④权限模式兜底新增一处按种类的例外**（F7）。这是模式层第一次出现按种类的分支。
5. **规则求值新增「白名单是否已建立」的查询**，且该查询**按规则来源层区分**（F6）——
   这是本扩展对「层级不决定优先级」这条既有哲学的**唯一一处例外**，理由见 F6。
6. **结构化系统提示新增一条固定模块**（F21），属稳定可缓存通道。
7. **权限规则的加载错误需要一条真实的展示路径**。当前这类错误被收集进权限引擎后
   **没有任何消费者**，F13 的警告若不新建展示路径就等于没有（F25）。
8. **Skill 的 `allowed-tools` 词汇表需登记本工具**，否则 Skill 无法为它预授权（F26）。

**Provider 范围**：本扩展及后续所有开发只针对 DeepSeek Provider（工具模式）。

## 目标

- 让模型能读取一个公开网页的正文内容。
- 在同一次改动里建立**应用层网络边界**：把「用户可以配置的域名策略」与「用户不该能关掉的
  结构性硬校验」在决策管线上分成两件事。
- 保证「权限规则能限制它访问哪些域名」这条限制**不可被任何权限模式放开**。
- 把抓回来的内容当作**不可信输入**：明确标注、明确告诉模型它是数据不是指令。
- 保证该能力可被整体关闭，关闭后系统行为与本扩展之前逐字一致。

## 功能需求

### 一、工具形态与接口

- **F1**：提供一个网络抓取工具。输入两项：**目标地址**，以及一段说明「要从该页面提取什么」
  的自然语言描述。返回一段文本作为该次抓取的结果。

  工具名与规则体系名是用户契约（要写进 `permissions.yaml`），因此写死：工具名 `web_fetch`，
  规则体系名 `WebFetch`。后者与既有的 `Bash` / `Read` / `Edit` / `Write` 同级，
  也与 Claude Code 一致，便于用户迁移配置习惯。

- **F2**：**只支持「取回一个地址的内容」这一种语义**。不接受请求体、不接受调用方自定义请求头、
  不接受调用方指定请求方法。**调用方通过参数传入这三类内容时不产生任何效果**——
  它们不在参数表里，多余参数被忽略。

- **F3**：工具声明为**有副作用**（非只读）。它会向外部主机发起真实请求，该请求本身即是一次
  对外可观测的行为，不满足「只读工具默认放行」的前提。

  **已知后果，写在此处让审批者看见**：非只读工具在 Plan Mode 规划阶段**不可见**，
  因此模型在「规划」阶段查不了在线文档，只能在获批进入执行阶段后再查。本扩展接受这个后果——
  另一种选择（声明为只读）会让它在放行档下被直接放行，与 F7 的整个设计冲突。

- **F4**：该能力可被**整体关闭**。关闭时工具不注册、不出现在工具清单里、域名规则语法校验不执行、
  新增的决策层不参与判定、系统提示不含新增模块。关闭后系统行为与本扩展之前**逐字一致**
  （包括不产生任何新增的警告）。缺省为**启用**。

### 二、网络边界层

- **F5**：新增一个专管 URL 类请求的决策层，位于**②路径沙箱之后、③可配置规则之前**。
  该层承担两类职责，第一类是**结构性硬校验**，命中即拒绝，**不可被任何配置、任何权限规则、
  任何权限模式放开**（与①危险命令黑名单同一性质）：

  | 校验项 | 拒绝什么 | 为什么不可放开 |
  |---|---|---|
  | 协议限制 | 除 `http` / `https` 之外的一切协议 | `file://` 会让网络工具变成文件读取工具，绕过②路径沙箱；其余协议无正当用途 |
  | 目标地址限制 | 非**全局可路由**的地址：环回、私有段、链路本地（含云实例元数据地址）、共享地址空间（CGNAT）、组播、保留段、未指定地址；以及各种**封装形式**还原后落入上述范围的地址 | 这类地址上的服务普遍假设「能连上就是自己人」而不设鉴权 |
  | 凭据限制 | 地址中内嵌用户名/密码的形式 | 无正当用途，且会把凭据写进历史与行为记录 |

  **「非全局可路由」是白名单式判据**（默认拒绝、只放行确认可路由的），不是逐条列举黑名单。
  逐条列举必然漏——审查阶段实测确认，按「环回 ∪ 私有 ∪ 链路本地 ∪ 保留 ∪ 未指定」
  这套黑名单，`100.64.0.1`（CGNAT）、`224.0.0.1`（组播）、`2002:7f00:1::`（6to4 封装的环回）
  三者全部漏网。**封装形式必须显式还原后复判**：IPv4-mapped IPv6、6to4、NAT64。

- **F5a**：硬校验分两个执行时机，**语义相同、位置不同**：

  | 时机 | 校验什么 | 结果形态 |
  |---|---|---|
  | **判定期**（每次工具调用前） | 协议、内嵌凭据、以及地址是 **IP 字面量**时的范围 | 权限**拒绝**，走既有的拒绝回灌与行为记录 |
  | **连接期**（每一跳建立连接前） | 上述全部**再跑一次**，外加**域名解析结果**的地址范围 | 抓取**失败**，作为工具结果回报 |

  两个时机必须**共用同一份判断实现**——各写一套是典型的「改一处漏一处」，且漏改不报错。

  **「每一跳都跑一次完整硬校验」是必须的**：同主机重定向会产生新地址，若只在判定期对原始地址
  校验一次，`https://a.com/x` → `Location: http://user:pass@a.com/` 这样的跳转会让协议限制与
  凭据限制对新地址完全失效。

  **连接期的失败不是权限拒绝**，这一点要在结果文案里对模型讲清楚（见 F24）。

- **F6**：该层的第二类职责是**域名策略求值**，对已通过硬校验的请求按以下顺序判定：

  1. 命中任意一条**拒绝**域名规则 → 拒绝。**拒绝优先**，不可被任何放行规则翻案。
  2. 命中任意一条**放行**域名规则 → 放行。
  3. 未命中，但**用户级或项目级配置**中存在至少一条放行域名规则 → **拒绝**。
  4. 否则本层不下结论，交由后续层处理（进入 F7）。

  **第 3 条是本层与③规则层最本质的差别**，也是「限制不可被权限模式放开」的实现根基：
  ③层未命中时是「不下结论、交由④兜底」，而本层在白名单已被建立的情况下，
  「未命中」本身就是一个结论。

- **F6a**：**白名单只由「用户级 / 项目级」两层的放行域名规则建立。**
  本地级、会话级、以及本次执行级（Skill 预授权）的放行规则**只放行、不建立白名单**。

  这是本扩展对「规则层级不决定优先级」这条既有哲学的**唯一一处例外**，必须讲清理由：

  - 用户级 / 项目级 YAML 是**人手写下的策略声明**。在这两处写下「放行 github.com」，
    合理的解读就是「我只打算让它访问这些」。
  - 本地级是**「永久放行」自动写入的授权记录**，会话级与本次执行级是**运行期临时授权**。
    三者都是「我批准这一次/这一个」，不是「我只允许这些」。
  - 若不做这个区分，会出现一个**设计级自锁**：用户在确认面板上点一次「永久放行」，
    就等于建立了只含一个域名的白名单，此后**其它所有域名从「弹确认」变成「硬拒且永不再问」**，
    而界面上没有任何恢复手段。这个后果既不符合用户点那个按钮时的意图，也无从预料。
  - 同样重要的是：Skill 的 `allowed-tools` 走本次执行级规则。若它能建立白名单，
    一个声明了 `WebFetch(domain:x)` 的 Skill 会在执行期间**收紧**其它域名的访问——
    直接违反「`allowed-tools` 只放宽、从不收紧」这条既有的安全承诺。

  **拒绝规则不受此区分影响**：任何层级的 deny 域名规则一律生效、一律优先。
  只有「建立白名单」这一个动作认来源层。

- **F7**：**权限模式对本类请求的兜底行为有一处例外**。当第③层同样未下结论时：

  | 权限模式 | 对其它副作用工具 | 对 URL 类请求 |
  |---|---|---|
  | 严格 | 拒绝 | 拒绝（相同） |
  | 默认 | 交人工确认 | 交人工确认（相同） |
  | **放行** | **放行** | **交人工确认**（例外） |

  理由：放行档的语义是「灰色地带别再烦我」，对文件工具而言其后果被②路径沙箱兜住，
  但 URL 类请求在未建立白名单时**没有等价的兜底边界**。该例外只影响 URL 类请求。

  **已知后果，写在此处让审批者看见**：这意味着**无人值守场景下没有免确认的网络访问路径**，
  除非在用户级或项目级 YAML 里写下放行域名规则（而那会同时建立白名单）。这是刻意的取舍——
  「无人值守 + 任意域名」正是本扩展要防的组合。

- **F8**：**跨主机重定向不自动跟随**。返回「原地址 → 重定向目标」的结果，由模型自行决定
  是否对新地址再发起一次调用（届时重新走一遍完整判定）。同主机重定向可自动跟随，
  但有跳数上限，超限即失败并说明原因。

  **「同主机」定义为「协议、主机名、端口」三者全部相等。** 任一不同即按跨主机处理。
  域名规则本身只匹配主机名（F10），但重定向的自动跟随是**在权限判定之后发生的**，
  因此它的等价判据必须比域名规则更严——否则 `https://a.com` → `http://a.com:8080`
  会在无人复核的情况下被跟随。

  理由：自动跟随跨主机重定向等于给域名策略开后门——放行 `docs.example.com` 之后，
  该主机只要回一个 302 就能把抓取导向任意地址。

- **F9**：判定为「交人工确认」时，沿用 C6 既有的确认面板与四选项。
  面板展示的信息至少包含：完整目标地址、该地址的主机名、本次判定来自哪一层。
  选择「永久」时，写入本地级权限配置的是一条**针对该次请求主机名的放行域名规则**，
  **不得包含路径、查询参数或端口**（查询参数可能含令牌，写进配置文件即是泄漏）。

### 三、域名规则语法

- **F10**：域名规则写作 `WebFetch(domain:<模式>)`，与三层权限 YAML 的既有 `allow` / `deny` 列表
  共用同一份配置文件与同一套加载流程，无新增配置文件。匹配目标是**目标地址的主机名**，
  不含协议、端口、路径与查询参数。匹配**大小写不敏感**，模式与主机名末尾的 `.` 都先行去除。

- **F11**：通配语义（与 Claude Code 逐条一致）：

  | 模式 | 匹配 | 不匹配 |
  |---|---|---|
  | `example.com` | `example.com` | `api.example.com` |
  | `*.example.com` | 任意深度子域：`api.example.com`、`a.b.example.com` | 裸域 `example.com` 本身 |
  | `*` | 一切主机名（等价于不带括号的整工具规则） | — |
  | `example.*` | `example.org`（`*` 取到 `org`） | `example.evil.com`（`*` 需跨越一个点） |

  最后一行是**安全要求而非风格选择**：若非前导位置的 `*` 允许跨点匹配，一条本意为
  「放行 example 各国域名」的规则会连带放行攻击者可自行注册的 `example.evil.com`。

- **F12**：不带括号的整工具规则（`WebFetch`）继续有效，语义为「匹配该工具的一切调用」，
  与 `WebFetch(domain:*)` 等价。`deny: WebFetch` 是「彻底禁用该工具」的写法。

- **F13**：**规则加载容错**。括号内无法识别的写法（例如漏写 `domain:` 前缀）按效果分别处理，
  两支都**偏严**（N1 fail-safe）：

  | 写坏的是 | 怎么处理 | 为什么 |
  |---|---|---|
  | `allow` 规则 | **整条丢弃** | 丢弃一条放行 = 少放行一些，偏严 |
  | `deny` 规则 | **降级为整工具拒绝**（等价于 `deny: WebFetch`） | 丢弃一条拒绝 = 少拦一些，偏松，不可接受。用户意图明确是「要拦」，看不懂拦什么就拦全部 |

  两支都产生一条可读警告，指明文件、原条目与正确写法。**不阻断启动。**

### 四、内容抽取

- **F14**：取回响应后先做**本地转换**：HTML 剥离脚本、样式与标签，转为可读纯文本；
  纯文本类响应原样保留；**二进制类响应不进入上下文**，只回报其内容类型与体量。

- **F14a**：**字节到文本的解码必须有明确的推断链**：HTTP 响应头声明的字符集 →
  文档内声明的字符集 → 兜底 UTF-8 且非法字节替换而非报错。
  「查中文文档」是本扩展的主场景之一，解码错误会让整页变成乱码而不报任何错。

- **F15**：随后做**抽取**：把「本地转换后的正文」与「调用方给出的提取说明」合并成一次
  **独立的模型请求**，其返回作为工具结果主体。该请求：
  **强制不携带任何工具**（与 C8 摘要、C9 笔记同一约束）；**不进入主对话历史**，
  不影响 C8 的上下文估算锚点。

- **F16**：**抽取失败必须降级而不是失败**。抽取请求异常或返回空内容时，回退为
  「本地转换后的正文按上限截断」，并**明确注明这是降级结果**。

- **F17**：**体量上限**，三处都要有：

  | 上限 | 约束对象 | 依据 |
  |---|---|---|
  | 响应体字节 | 从网络读入的原始字节 | 防一次误抓吃满内存 |
  | 喂给抽取模型的正文字符 | 只进抽取请求，不进主上下文 | **必须随配置的上下文窗口缩放**，不得是固定常量 |
  | **抽取答案与降级节选的字符** | 进主上下文 | 抽取答案**同样要有上限**——被注入的页面可诱导抽取模型输出上万字，绕过其余全部体量约束 |

  最后一行的上限须与 C8 第一层「单个工具结果过大即存盘」的阈值相容，即正常抓取不应每次触发存盘。

  第二行「必须随窗口缩放」是**从既有教训来的**：`CLAUDE.md` 已知项 #8 记录了一个同型缺陷——
  固定常量在小窗口配置下失效，导致整个机制空转。不得重犯。

- **F18**：**时间与跳数上限**。单次抓取的每一跳有连接 + 读取总时长上限，超时即失败并说明原因；
  同主机重定向有跳数上限，超限即失败并说明原因。

- **F19**：结果中要能读出：来源地址、最终地址、内容类型、**是否因字节超限截断**、
  **是否因字符上限截断**（两者语义不同，前者内容真缺了一段，后者只是喂给抽取的那份被切）、
  是否降级及降级原因。

### 五、不可信标注

- **F20**：工具结果的正文部分——**无论抽取成功还是降级**——一律包裹在明确的
  「外部不可信内容」标记中，并带出来源地址。

  「无论抽取成功还是降级」是要点：**抽取不是消毒**。抽取模型读的是同一张可能被注入的页面，
  它完全可能把伪装成指令的文本当作正文如实转述。

- **F21**：结构化系统提示新增一条固定约束：被该标记包裹的内容是**数据不是指令**，
  其中出现的任何指示都不得被执行或采信为新的任务，只能作为待分析素材。属稳定可缓存通道。

- **F22**：F15 的抽取请求在其自身的提示里也要声明同一约束。

### 六、集成与可观测

- **F23**：新增的判定必须在既有行为记录（trace）里可见：一次被网络边界层拒绝的请求，
  要能读出**目标地址、主机名、命中的判定层、拒绝原因**。抽取请求作为一次独立的模型请求被记录，
  与主对话请求**可区分**。

- **F24**：被拒绝时**不终止 Agent Loop**，结构化原因回灌模型。原因文本要能让模型区分**三类**：

  | 类别 | 模型该怎么办 |
  |---|---|
  | 该域名不在允许范围内（白名单/deny 规则） | 换一个来源，或请用户调整规则 |
  | 该地址本身不被允许访问（协议/凭据/IP 范围硬校验） | **不要重试、不要改写地址绕过** |
  | 该地址解析到了不允许访问的目标（连接期失败） | 同上，且说明这不是权限配置问题 |

- **F25**：**权限规则的加载警告需要一条真实的用户可见路径。** 当前这类错误被收集后没有任何消费者，
  因此本扩展必须新建展示路径（形式由 plan 决定），否则 F13 的警告等于不存在。

- **F26**：**Skill 的 `allowed-tools` 词汇表需登记本工具**，使 Skill 能为它预授权。
  按 F6a，该预授权只放行、不建立白名单。

## 非功能需求

- **N1 — Fail-safe（安全优先）**：任何不确定或出错的情形都必须偏向更严。
  地址范围判断用「非全局可路由即拒」的白名单式判据；写坏的 deny 规则降级为整工具拒绝；
  地址解析失败 → 拒绝而非放行；F5 的硬校验在任何模式、任何配置下都不可绕过。

- **N2 — 权限由代码强制，不依赖模型**：模型输出、系统提示、RHINE.md、Skill 正文、
  以及**被抓回来的网页内容本身**都无法改变某个地址的放行/拒绝结论。

- **N3 — 轻量与低延迟**：判定期的判断必须轻量（字符串比对、地址范围判断），
  规则在启动时加载一次并缓存。

- **N4 — 判定层零 I/O**：判定期的判定是**纯逻辑**——给定「地址 + 模式 + 规则集」即可判定，
  不发起任何网络请求、不做域名解析、不依赖 TUI。真实的网络访问只发生在工具实现内部。

- **N5 — 可测试性**：全部单元测试**不真连网、不真调模型**。
  抓取与抽取必须提供**可注入的替身入口**（网络客户端与域名解析各一），
  且该入口要能一路透传到装配层，使端到端场景也能离线跑。

  这条同时是安全要求——测试套件不应因为跑测试而向外发出请求。

- **N6 — 兼容性与非破坏**：仅在 `protocol: deepseek` 且启用默认工具注册中心时生效。
  不破坏 C6 既有四层判定、C7 的 MCP 工具规则语义、C8 的上下文压缩、C11 的 Skill 预授权。
  **能力关闭时（F4）系统行为与本扩展之前逐字一致。**

- **N7 — 跨平台正确性**：主机名归一化、地址范围判断在 Windows 与类 Unix 下行为一致。

- **N8 — 中文注释规范**：遵循项目 `CLAUDE.md` 的中文注释规范。

## 安全边界

这是 RhineCode 第一个**能主动向外部发送数据**的工具，安全模型上必须写明：

1. **它把一条外泄链路接通了。** 在本扩展之前，模型读到的任何敏感内容都烂在本地。
   之后，「读文件」与「访问网络」两个能力凑齐，外泄链路成立。真实攻击形态：
   一个被抓取的页面里藏着伪装成系统指令的文本，要求模型读取某个文件并把内容拼进
   下一次抓取的查询参数。

   防御是**三道叠加**：F20/F21 的不可信标注、F6 的域名白名单、F2 的「只取不发」。

   **必须承认的一点：缺省配置下第二道防御不存在。** 用户不写任何域名规则时白名单未建立，
   此时唯一的实际拦截是「每次弹确认」——也就是说，这套防御在缺省配置下的真实强度
   等于**用户面对第 20 次确认面板时的判断力**。想要真正的边界，必须在用户级或项目级
   YAML 里写下放行域名规则。

2. **域名策略只对本扩展的工具成立。** 两条不受约束的旁路：
   - `run_command` 跑起来的 `curl` / `wget` / 自己写的脚本；
   - **MCP 工具**——它们同样落在「其它类」，同样能任意联网，且 `mcp_add_server` 会启动外部程序、
     `mcp_resolve_server` 会访问外部包索引。

   想封死当前唯一手段是用 deny 规则限制命令与 MCP 工具本身，并接受该手段本身是脆弱的。

3. **抓回的内容与工具结果同等敏感**，会进入主对话历史、C9 会话存档、C8 存盘工具结果、
   以及开启 `--trace` 时的行为记录。敏感度纪律沿用既有约定。

其余边界：

- **地址仍是一条窄外泄通道。** F2 关掉了请求体与请求头，但查询参数仍由模型构造。
- **DNS rebinding 无法在本扩展内封死。** 硬校验解析一次域名并校验，随后 HTTP 客户端
  建立连接时会**再解析一次**，两次之间 DNS 记录可以改变。彻底封死需要锁定校验通过的 IP
  再连接（并自行处理 Host 头与 TLS SNI），本扩展不做，列为已知边界。
  其影响被域名白名单大幅限制——攻击者的域名首先要能进白名单。
- **抽取阶段会把网页正文发给 LLM 供应商。** 与正常对话同性质，无额外外泄面，但用户应知悉。
- **抽取请求没有独立的超时上限。** 现有的 Provider 抽象不接受超时参数，加参数要改动三个
  Provider 实现，超出本扩展范围。抽取请求的超时行为与主对话请求、C8 摘要、C9 笔记完全一致
  （依赖底层 SDK 的默认行为），列为已知边界。

## 不做的事

- **网络搜索**——留作后续扩展。
- **发送数据的请求形态**——不支持自定义请求方法、请求体、自定义请求头。
- **认证抓取**——不支持 cookie、Bearer token、Basic 认证。需要登录才能看的页面一律抓不到。
- **代理配置**——不做 HTTP 代理 / SOCKS 配置项。
- **OS 级网络隔离**——同已知后续项 #4。
- **锁定 IP 后连接**——不自行接管连接建立以消除 DNS rebinding 时间窗（见安全边界）。
- **抽取请求的独立超时**——不改 Provider 抽象（见安全边界）。
- **JavaScript 渲染**——不启动浏览器引擎，前端渲染的单页应用可能只抓到骨架。
- **抓取结果缓存**——每次调用都是一次真实请求。
- **`robots.txt` 与抓取礼仪**——不解析、不做速率限制。
- **二进制内容的解析与渲染**——只回报类型与体量。
- **域名规则的可视化管理界面**——规则靠手工编辑 YAML 外加 F9 的「永久放行」自动追加。
- **审计日志**——不持久化独立审计轨迹。
- **扩展到其它 Provider**。

## 验收标准

### 硬校验

- **AC1**（F1）— 给定可访问地址与提取说明，工具返回与该说明相关的文本。
- **AC2**（F2）— 参数集合中不存在请求方法、请求体、请求头三类入口；**传入多余参数不产生任何效果**。
- **AC3**（F3）— 该工具在 Plan Mode 规划阶段不出现在可见工具集里，规划阶段夹带调用被既有阶段守卫挡下。
- **AC4**（F4）— 关闭后：工具不在清单中、系统提示逐字等于关闭前、**写坏的域名规则不产生任何警告**。
- **AC5**（F5·协议）— `file://` 被拒绝，且在放行档 + `allow: WebFetch(domain:*)` 下**仍然**被拒。
- **AC6**（F5·地址·判定期）— IP 字面量形式的环回、私有段、链路本地（含云元数据地址）、
  **CGNAT `100.64.0.1`**、**组播 `224.0.0.1`**、**6to4 `2002:7f00:1::`**、
  **IPv4-mapped `::ffff:127.0.0.1`** 全部被拒；在放行档 + 全域名放行规则下仍被拒。
- **AC7**（F5·凭据）— 地址中内嵌用户名/密码的请求被拒绝。
- **AC8**（F5a·连接期）— 域名解析结果落入禁止范围时**抓取失败**（非权限拒绝），
  结果文案说明这不是权限配置问题；两个时机共用同一份判断实现。
- **AC9**（F5a·逐跳）— `https://a.com/x` 重定向到 `http://user:pass@a.com/` 时**不被自动跟随**
  （协议与凭据在新地址上重新校验并命中）。

### 域名策略

- **AC10**（F6·拒绝优先）— 用户级 `deny: WebFetch(domain:*.example.com)` 叠加项目级同域 allow，
  对 `api.example.com` 的请求被拒绝。
- **AC11**（F6·白名单语义）— **项目级**配置仅有 `allow: WebFetch(domain:github.com)` 时，
  `github.com` 放行、`example.com` **被拒绝而非弹确认**，且在放行档下同样被拒。
- **AC12**（F6a·来源层）— 三条并列：
  - 在**确认面板**点「永久放行 `example.com`」后，**其它主机名仍然弹确认**（而非被硬拒），
    重启后行为不变；
  - 在**项目级 YAML** 写下同一条规则后，其它主机名**被硬拒**；
  - 一个 `allowed-tools` 含 `WebFetch(domain:x)` 的 Skill 执行期间，其它域名的访问**不被收紧**。
- **AC13**（F7）— 无任何用户级/项目级放行域名规则时，同一请求在三档模式下分别为：
  严格→拒绝、默认→确认、**放行→仍然确认**；同一放行档下一次写文件调用仍被直接放行。
- **AC14**（F8）— 跨主机重定向不跟随，结果中同时出现原地址与目标；
  **端口不同亦按跨主机处理**（`https://a.com` → `http://a.com:8080` 不被跟随）；
  对目标地址再次调用时重新走完整判定，可被域名规则拒绝；同主机跳数超限失败并说明原因。
- **AC15**（F9）— 面板展示完整地址与主机名；选「永久」后写入的是针对该主机名的域名放行规则，
  **且用一个带 `?token=abc` 的地址验证：配置文件中不含该查询参数、不含路径、不含端口**。

### 规则语法

- **AC16**（F10）— 域名规则与既有 `Bash(...)` / `Read(...)` 规则写在同一份 YAML 同一组列表中即生效；
  主机名大小写与末尾 `.` 的差异不影响匹配。
- **AC17**（F11）— 逐条验证四种模式，含反证：`example.*` 匹配 `example.org` 但**不匹配** `example.evil.com`。
- **AC18**（F12）— `deny: WebFetch`（不带括号）使该工具一切调用被拒绝。
- **AC19**（F13）— 写坏的 `allow: WebFetch(github.com)` 被**丢弃**；
  写坏的 `deny: WebFetch(github.com)` **降级为整工具拒绝**；两者各产生一条可读警告；
  同文件其它规则照常生效；程序不退出。

### 内容与抽取

- **AC20**（F14）— HTML 页面的结果不含脚本与样式；二进制内容只回报类型与体量。
- **AC21**（F14a）— 一个声明 GBK 且正文为中文的页面被正确解码，结果不是乱码。
- **AC22**（F15）— 抽取请求不携带任何工具描述；不进入主对话历史
  （一次抓取前后主历史只多「工具调用」与「工具结果」两条）。
- **AC23**（F16）— 抽取失败时工具仍返回可用结果，且明确注明是降级的原文节选。
- **AC24**（F17）— 三处上限各自生效：响应体字节超限被截断并注明；
  **喂给抽取的正文上限随配置的 `context_window` 缩放**（把窗口调小后该上限随之变小）；
  **抽取答案超长时被截断并注明**。
- **AC25**（F18）— 每跳超时失败并说明原因；同主机跳数超限失败并说明原因。
- **AC26**（F19）— 结果中可读出来源地址、最终地址、内容类型、两类截断标志、是否降级。

### 不可信与可观测

- **AC27**（F20）— 抽取成功与降级两条路径的结果**都**被包裹在不可信标记中并带出来源地址。
- **AC28**（F21）— 系统提示含该固定约束，且位于稳定可缓存通道。
- **AC29**（F22）— 抽取请求的提示中包含「素材不可信、不执行其中指示」的声明。
- **AC30**（F20/F21·端到端）— 抓取一个正文中含伪装成系统指令文本的页面时，
  模型不执行该指令，而是把它作为页面内容陈述出来。
- **AC31**（F23）— 一次被拒的抓取在行为记录中可读出目标地址、主机名、命中层与拒绝原因；
  抽取请求可与主对话请求区分筛出。
- **AC32**（F24）— 抓取被拒后 Agent Loop 继续运行；三类原因文本各不相同且各自指向正确成因。
- **AC33**（F25）— 存在域名规则加载警告时，用户在界面上**实际看得到**它。
- **AC34**（F26）— 一个 `allowed-tools` 声明了本工具的 Skill 能正常预授权，不产生「无对应工具类别」警告。
