# TUI 显示体系改造 Checklist

> 每一项通过**运行代码或观察行为**来验证，聚焦系统行为而非实现细节。
> 括号里是验证方式。覆盖 `spec.md` 的 AC1–AC32 + `plan.md` 的集成点 + 既有护栏的回归。

## A 组 · 子 Agent 活动区

- [ ] **AC1a** 无任何子 Agent 运行时，界面上不存在活动区，布局与改造前一致
      （验证：起脚本化宿主，`client screen --selector ActivityView` 返回空）
- [ ] **AC1b** 发起一次委派后活动区出现
      （验证：同一宿主发一条触发委派的消息，`screen` 里出现活动行）
- [ ] **AC2** 活动行显示名字与三个数字，且运行期间**三个数字都会变化**
      （验证：`client screen` 采样两次，间隔 ≥2 秒，三个数字至少各变一次）
- [ ] **AC3** 活动行的次数与该任务实际发生的工具调用次数一致
      （验证：单测喂 N 个 `TOOL_RESULT`，断言 `tool_calls == N`；
      并与 `observe --types tool_execute` 的条数交叉核对）
- [ ] **AC4** 活动区数据更新全部发生在主线程，不存在从子 Agent 线程更新界面的路径
      （验证：结构护栏——扫描活动区相关方法，断言不出现 `call_from_thread`；
      且 `TaskManager` 既有的「无 callable 成员」护栏仍通过）
- [ ] **AC5a** 按 `Ctrl+O` 活动区在折叠与展开之间切换，展开时能看到内部最近的工具调用
      （验证：e2e `client keys ctrl+o`，`screen` 里出现 `⎿` 子行；再按一次消失）
- [ ] **AC5b** 切换展开时输入框焦点不丢失
      （验证：`keys ctrl+o` 后 `client status` 显示焦点仍在输入框，随后 `send` 可正常提交）
- [ ] **AC6** 任务结束后活动区那一行转为终态并显示最终成本，随后消失；
      历史区留下一条含**同一组数字**的记录
      （验证：e2e 跑完一次委派，先看到终态行，等待 >5 秒后活动区为空；
      比对历史区那条的三个数字与终态行一致）
- [ ] **AC6b** 历史区那条留痕**只有一条**，没有重复
      （验证：`screen --selector "#history-messages"` 里该任务名的完成行恰好出现一次）
- [ ] **AC7** 完成通知含成本数字，且不依赖模型说任何话
      （验证：用脚本化 Provider——模型剧本里不含任何成本描述——通知仍带数字）
- [ ] **AC8** `/clear` 之后活动区为空
      （验证：e2e 委派后 `send /clear`，`screen --selector ActivityView` 返回空）
- [ ] **AC25a** 并发跑满上限（5）时活动行不超过 5 条
      （验证：单测构造 6 个运行中任务，断言 `activity_rows()` 长度受限）
- [ ] **AC25b** 展开时每条任务的工具调用条数不超过约定上限
      （验证：单测喂 20 条，断言 `recent_tools` 长度 ≤ 上限）

## F 组 · 表情与退出键位

- [ ] **AC19a** 全界面搜不到表情符号

- [ ] **AC20c** 超时后复位，需要重新按两次

- [ ] **AC20d** `Ctrl+Q` 不再退出

- [ ] **AC20e** `/exit` 仍可退出

- [ ] **AC21** **单次 `Ctrl+C` 在任何状态下都不退出**（空闲 / 流式运行中 / 面板挂起中各验一次）
      （验证：三个独立用例，每次单按后断言应用仍在运行）
- [ ] **有选中文本时按两次 `Ctrl+C` 仍不退出**（「不计数」这条设计的唯一判据）

## 端到端场景

- [ ] **场景 1 · 委派全程可见**：发一条触发委派的消息 → 活动区出现并三个数字在跳 →
      `Ctrl+O` 展开看到内部调用 → 收回 → 任务结束后终态行显示成本 → 数秒后消失 →
      历史区留下一条带同样数字的记录
- [ ] **场景 2 · 报告分级**：依次跑 `/agents` `/skills` `/memory` →
      三份报告都呈现出标题 / 条目 / 次级信息的层次，整段不再是同一暗色
- [ ] **场景 3 · 面板交互**：触发一次需要确认的工具 → 面板带序号且高亮项有 `>` →
      按 `2` 选中「本会话放行」→ 工具执行 → 再触发同类调用不再弹面板
- [ ] **场景 4 · 退出**：按一次 `Ctrl+C` 看到提示 → 等待 >2 秒 → 再按一次仍不退出（已复位）→
      连按两次 → 退出；另验 `Ctrl+Q` 无效、`/exit` 有效
- [ ] **场景 5 · 长对话不被撑爆**：连续问几个会打出多个工具调用的问题 →
      历史区无「第 N 轮」行 → 长输出的工具结果被折叠且标出剩余行数 →
      内容短时贴顶、内容长时自动跟随最新
- [ ] **场景 6 · 零回归**：全程不使用子 Agent、不敲报告类命令跑一轮普通对话 →
      界面表现除本 spec 明列的改动外与改造前一致（活动区从未出现）
- [ ] **场景 7 · 真实模型复跑**（留作手测）：用真实 Provider 跑场景 1 与 5，
      确认在真实的多工具、长输出场景下观感成立
