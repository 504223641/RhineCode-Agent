# TUI 显示体系改造（对齐 Claude Code） Spec

> 扩展，不占章节号。判据：`CLAUDE.md` 的能力表**不多一行**——本轮不引入新的能力
> 层级，改的是既有 TUI 层如何呈现**已有**能力。

## 背景

用户的起点是一个具体症状：**子 Agent 在工作时界面上没有任何状态**。派出去之后是
几分钟的静默，直到结论回流。但他要的范围更大——**整个显示体系对齐 Claude Code
的观感**。

其余只有一张待盘点清单。本 spec 的第一步是把那张清单逐个读过一遍
（`tui/widgets.py` 1384 行、`tui/app.py` 1500 行、`subagents/tasks.py`、

### 已核实的三条地基

1. **轮询可行且是设计预期**。`TaskRecord` 的 `turns` / `usage_tokens` /
   `started_at` 是运行期持续更新的可变字段，任务表的快照返回记录对象本身（不深拷贝），
   且其加锁临界区只做纯内存读写。主线程定时读它不会被长时间阻塞。
   ⚠ 本项目**已经死锁过四次**，全部是「在加锁临界区里做跨线程调度」。轮询从结构上
   消掉这一整类问题。
2. **工具行与子 Agent 的生命周期是分叉的**。`background=true` 的委派在发起那一刻
   工具调用就已返回并定终态；工具行按既有护栏必须在拿到结果时摘除。因此活动区
   **必须独立**，不能复用工具行的结算逻辑。
3. **「工具调用次数」是唯一缺的数据**。运行器消费子 Agent 事件流时已在更新轮次与
   用量，同一处即可数工具调用；它本来就**不转发**子 Agent 的事件，加计数不破坏
   「子 Agent 的过程不渲染」这条既有约束。

### ⚠ 一条既有护栏与本轮要求正面相关（必须连着读）

`tests/test_tui_keybindings.py` 有两条**历史回归护栏**：
`test_ctrl_c_is_not_bound_to_quit`（`Ctrl+C` 不得绑定到退出动作）与
`test_placeholder_points_to_ctrl_q_for_quit`（输入框占位符必须写「Ctrl+Q 退出」、
且不得出现「Ctrl+C 退出」）。理由记在 `docs/c2/spec.md` 的 AC9：
**「Ctrl+C 用于复制场景，不应触发退出」**。

本轮要把退出改成**连按两次 `Ctrl+C`**。这不是推翻那条护栏，而是**兑现它的本意**：
单次 `Ctrl+C` 依然不退出（复制场景安全），两次连按才退——这也正是 Claude Code 的做法。
因此护栏**改写而不是删除**（F32），同时 `docs/c2/checklist.md` 的 AC9 那条判据随之过期，
需要同步。

## 对齐依据与确定性分级

⚠ **「对齐 Claude Code」指的是结构、符号、指标口径与交互形态，不是把界面改成英文。**
本项目的界面语言约定是中文，工具名这类专有标签保持英文（既有做法），状态词保持中文。

| 层 | 内容 | 确定性 |
| --- | --- | --- |
| 第 4 层 | 「子 Agent 默认后台运行，完成时**由系统通知你**」「**绝不要编造或预测**尚未完成的子 Agent 的结果——那条通知永远不是你自己写的」 | **确定**：Claude Code 系统提示原文 |
| 第 4 层 | 「子 Agent 的最终报告不展示给用户——把要紧的转述出来」 | **确定**：同上。本项目现状已符合，无需改动 |
| 第 1 层 | 运行中的 agent 行带三个数字：经过时间 / 累计 token / 工具调用次数 | 观察，版本间可能有出入 |
| 第 1 层 | 工具行括号里是**一个主参数的值**（`Read(src/app.py)`），不是 `键=值` 列表 | 观察 |
| 第 2 层 | 默认折叠，快捷键掀开看内部逐条工具调用 | 观察 |
| 第 3 层 | 完成后保留成本信息（次数 / token / 耗时） | 观察 |
| 交互 | 确认类提示用**带序号的选项**，可直接按数字键选中 | 观察 |
| 键位 | 连按两次 `Ctrl+C` 退出 | 观察 |

三个数字的共同点是**不用理解内容就能判断「它在动、动得快不快」**。
刻意不把「子 Agent 正在做什么」翻译成人话展示——那既贵又容易误导。

## 目标

1. 后台子 Agent 全程可见，且按 Claude Code 的三层显示组织：活的进度行 / 可展开的
   内部细节 / 终态留下的成本痕迹。完成通知由**系统**产生，不经模型自述。
2. 工具行的标题与参数呈现方式与 Claude Code 一致——**一眼能看出「在对什么东西
   做什么」**，而不是读一串 `键=值`。
3. 命令报告不再被拍平成一整块暗色文本，内部层级可辨。
4. 系统提示行按**重要性**分级，重要的与可忽略的不再长得一模一样。
5. 四个面板的选项形态统一并对齐 Claude Code：带序号、可按数字键选中、无装饰性符号。
6. 界面上不出现任何表情符号；退出改为连按两次 `Ctrl+C`。
7. 全过程不引入任何从后台线程到界面的推送，不违反已有的加锁与转义护栏。

## 功能需求

### A 组 · 子 Agent 活动区

- **F1 位置与出现时机**：活动区是一块独立区域，位于历史区**下方**、各交互面板与
  输入框**上方**。它在「有正在运行的任务」或「有尚未淡出的终态行」时出现，
  两者都没有时**整块隐藏且不占布局空间**。
- **F2 一条活动行的内容**：形如
  `● <名字> 运行中 (<耗时> · ↑<token> · <次数> 次调用)`。
  名字的口径与 `/agents` 一致——协作启用时显示 `队员名(角色名)`，否则显示角色名；
  分支式委派显示既有的分支占位名。
- **F3 三个数字的语义**：耗时按「起始时刻到现在」实时计算；token 为该任务累计用量；
  次数为该子 Agent 已完成的工具调用总次数。三者都必须**在任务运行期间持续变化**。
- **F4 数据获取一律走轮询**：活动区的一切数据由**主线程**定时从任务表读取快照。
  **不新增任何从子 Agent 线程到界面的推送通道**，也不新增定时器——复用既有的
  子 Agent 轮询节拍（空闲会话的开销与改造前一致）。
- **F5 折叠与展开**：活动区默认折叠，只显示每个任务一行。一个快捷键在「折叠 /
  展开」之间切换**整个区域**；展开时每条任务下方列出它内部**最近若干次**工具调用
  （按 F12 的口径渲染），条数有上限。
  ⚠ 快捷键**不引入焦点切换**——活动区任何时候都不抢焦点，输入框、命令面板与四个
  面板的键位体系一字不动。
- **F6 终态处理**：任务结束时该行原地转为终态样式并显示最终成本
  （`完成 / 失败 / 已取消` + 次数 / token / 耗时），在区内**停留数秒后消失**；
  同时向历史区写入一条**永久留痕**，内容含同一组成本数字。
  两处的成本数字必须同源同口径。
- **F7 完成通知由系统产生**：既有的完成通知继续由界面轮询产出（不经模型），
  文案补上 F6 的成本数字，并按 D 组分级为「事件」级。
- **F8 会话切换清空**：`/clear` 与 `/resume` 之后活动区必须为空。
- **F9 零回归**：未启用子 Agent 能力时活动区**永不出现**，界面与改造前逐字一致。
- **F10 活动区只观测，不操作**：区内不提供取消或任何改变任务状态的入口。
  取消仍走 `/agents cancel`，全量信息仍看 `/agents`。**活动区给概览，`/agents`
  给全量**，本轮不动 `/agents` 的任何一段。

### B 组 · 工具行

- **F11 工具展示标签对齐 Claude Code 的词汇**：既有的「内部工具名 → 展示标签」
  映射按 Claude Code 的工具命名扩充，未登记的工具继续回退到原始名。
  **无对应工具的不硬套**（硬套会造出假的对应关系）。
- **F12 括号里放「主参数的值」，不放键值对列表**。
  现状 `Task(name=explorer, task=调研权限层…)` 里，`name=` `task=` 这些键名对用户
  **零信息量**——它们是给模型看的参数结构，不是人要读的东西；而真正有用的那个值
  被键名挤占了本就不多的横向空间。
  改为**每个工具指定一个主参数，只显示它的值**：
  `Read(rhinecode/tui/app.py)`、`Bash(python -m unittest)`、`Grep(Layer)`。
  规则三条：
  1. 主参数由工具自己声明；未声明的工具**回退到现有的键值对摘要**（安全兜底，
     新增工具忘了声明也不会显示异常）。
  2. **委派是特例**：标签取**角色名**、括号里放**任务描述**
     （`explorer(调研权限层的判定顺序)`）——这与 Claude Code 把 agent 类型作为
     标签的做法一致，也与 F6 的历史留痕行天然同形。
  3. 值仍然截断并转义，口径与现状一致。
- **F13 耗时只在有意义时出现**：工具行终态的耗时**低于一秒时不显示**。
  现状是每一行都写着 `完成 (0s)`——绝大多数工具调用是毫秒级的，那个恒为零的括号
  是纯噪音。执行中的实时计时**保持不变**（它是那段时间里界面上唯一的活体信号）。
- **F14 分支符号与配色单一来源**：工具行、活动区、报告三处的 `⎿` 分支符号与次级
  信息配色取自**同一处定义**，不各写一份。

### C 组 · 命令报告的渲染

- **F15 报告走专用显示通道**：命令产出的多行报告不再经系统提示行通道整段变暗。
- **F16 分级规则在展示层推断**：报告按行判定层级——段落标题、条目行、条目的次级
  信息、空行——并施加不同的亮度与强调。**各报告的文本产出函数一律不改**
  （它们是纯函数，且有大量逐字断言的护栏钉着）。
- **F17 报告首行保留可辨识的前缀**，使它在历史区里仍能一眼看出「这是一次命令的
  结果」，而不是 AI 说的话。
- **F18 单行消息不受影响**：不是报告的普通系统提示继续走 D 组的分级通道。

#### C 组做完的样子

**改造前**——`/agents` 的五段结构被整段包进一个暗色块，只有第一行有前缀：

```
◆ 子 Agent 角色与任务                        ← 以下每一行都是同一个暗色，
                                                段落标题、条目、次级信息
```

### H 组 · 对话区的布局与体量控制

本组解决两件用户实测提出的事：**对话内容贴着视口底部往上长**，以及
**一次提问打出十几个工具调用之后历史区被撑爆**。

#### 已实测的现状（证据，不是推断）

用最小复现量组件的实际坐标（视口 13 行、内容 2 行）：

```
HistoryView       region=(y=0, height=13)   scroll_y=-9   max_scroll_y=0
#history-messages region=(y=10, height=2)   ← 两条消息落在第 10、11 行
```

`anchor()` 在**内容短于视口**时产生一个**负的滚动偏移**，把内容整个推到底部。
这就是「从下到上」的来源。

⚠ **但不能简单删掉 `anchor()`**：它是带实测证据加进去的——
`HistoryView.on_mount` 的注释里记着，不用它时 `mount()` 之后 `scroll_end()` 取到的
是**加新组件之前**的 `max_scroll_y`，于是每次都停在「差最后一条消息」的位置，
用户得自己拨滚轮才看得到刚发的内容。两个需求必须同时满足。

- **F39 内容从视口顶部开始向下排列**：内容短于视口时贴顶，下方留空白，
  **不得出现负的滚动偏移**。
- **F40 内容超出视口时仍自动跟随最新**：新消息到达后无需手动滚动即可看到，
  用户手动往上翻时不被强行拽回底部（现有行为，必须保留）。
- **F41 工具结果与 diff 块有行数上限，超出可展开**：分支行超过上限的部分折叠，
  并在末尾显示**还有多少行**与展开方式（`… +N 行`）。展开走 A 组同一个快捷键，
  **不为它另立一个键**。
  ⚠ 现状的两处缺口：工具结果只取首行截断到 80 字符（长输出**没有「还有 N 行」
  的提示**，用户不知道被省了什么，也没法展开）；改文件的 diff 块**完全没有上限**，
  一次大改动会把整块差异铺进历史。
- **F42 去掉逐轮的「第 N 轮」提示行**：它是 Agent Loop 的内部结构，对用户没有
  可操作信息，而一次十几轮的运行会因此多出十几行。Claude Code 没有对应物。
  循环仍在推进这件事由工具行本身与活动区表达。
  ⚠ 它现在还是一条 `ui_message` 埋点的来源，删除时要确认 trace 侧不依赖它做判据。

## 非功能需求

- **N1 不引入跨线程推送**。活动区的全部数据经主线程轮询读取。理由：本项目已因
  「加锁临界区内做跨线程调度」死锁四次。
- **N2 一切嵌入 markup 的文本必须经本项目自己的转义实现**，不得使用 rich 那一版。
  活动区会嵌入队员名、角色名、工具参数摘要，报告会嵌入路径、错误消息与任务标题
  ——**全都是可能含字面 `[` 的自由文本**。漏转义的后果是布局阶段抛错、整个应用退出，
  没有任何异常处理兜得住。
  ⚠ F12 让**主参数的原始值**直接进入工具行标题（不再被键值对格式包裹），
  这条因此比改造前更要紧。
- **N3 零回归**：不使用子 Agent 的用户，界面表现除本 spec 明列的改动外与改造前一致。
- **N4 不新增行为记录（trace）事件类型**。活动区的终态留痕经既有的界面消息通道
  产出记录即可。新增事件类型会牵动「枚举 + 阅读器摘要表」这个成对维护点。
- **N5 一切展示都有界**：活动行条数以并发上限（5）为界，展开的工具调用条数有上限，
  主参数值仍按现有长度上限截断。
- **N6 端到端可观测**：活动区与分级后的系统行必须能被既有的端到端驱动设施按稳定
  选择器抓到可见文本，`Ctrl+C` 两次退出必须能经既有的按键投递通道驱动。
- **N7 主线程每次轮询只做纯内存读取与组件更新**，不做 IO、不发请求。
- **N8 交互契约不变**：本轮不改变任何面板的结算语义、键位优先级与焦点规则；
  新增的数字键选中与 `Ctrl+C` 计数**不得**与既有的 Esc 取消、Tab 补全、
  上下键导航冲突。

## 不做的事

- **状态栏重排**。既有的 `子Agent:N` 段保持原样，不因为活动区出现了就摘掉它；
  本轮只对它做 F28 的去 emoji。
- **把报告改写成 Markdown 再渲染**。观感更好，但要改十几个带逐字断言护栏的纯函数，
  收益不抵风险。
- **活动区里操作任务**（取消、展开单条、跳转），见 F10。
- **主对话自身的成本显示**（主 Agent 的 token / 耗时）。本轮只做子 Agent 的。
- **历史区的用户消息 / AI 正文 / 思考块的样式改动**（除 F28 去 emoji 外）。
- **子 Agent 的过程事件转发到主界面**。活动区展示的是计数与名字，不是把子 Agent
  的输出喷到主界面——那会抵消掉委派的全部价值。
- **`Ctrl+C` 之外的键位调整**。Esc、Tab、上下键、回车的语义一字不动。
- **面板的交互契约改动**，见 F27。
- **报告文本产出函数的改写**，见 F16。

## 验收标准

- **AC1**（F1/F9）：无任何子 Agent 运行时界面上不存在活动区，布局与改造前一致；
  发起一次委派后活动区出现。
- **AC2**（F2/F3）：委派后活动行显示名字与三个数字，且运行期间**三个数字都会变化**
  （两次采样不相等）。
- **AC3**（F3）：活动行显示的次数与该任务实际发生的工具调用次数一致。
- **AC4**（F4/N1/N7）：活动区的数据更新全部发生在主线程；不存在从子 Agent 线程
  更新活动区的路径。
- **AC5**（F5）：按下约定快捷键，活动区在折叠与展开之间切换；展开时能看到每条任务
  内部最近的工具调用；切换过程中输入框焦点不丢失。
- **AC6**（F6）：任务结束后活动区那一行转为终态并显示最终成本，随后消失；
  历史区留下一条含同一组数字的永久记录。
- **AC7**（F7）：完成通知含成本数字，由界面轮询产出，不依赖模型说任何话。
- **AC8**（F8）：`/clear` 之后活动区为空。
- **AC9**（F11）：工具行标签与 Claude Code 的工具命名一致；无对应工具的保持原名。
- **AC10**（F12）：工具行括号里**不出现 `键=` 形式**，只有主参数的值；
  未声明主参数的工具回退到键值对摘要；委派行显示为 `角色名(任务描述)`。
- **AC11**（F13）：耗时不足一秒的工具调用终态行**不出现**耗时括号；超过一秒的照常
  显示；执行中的实时计时不受影响。
- **AC12**（F14）：三处的分支符号与次级配色取自同一定义（改一处三处同时变）。
- **AC13**（F15/F16/F17）：`/agents` 的报告呈现出分级——段落标题与条目行在视觉上
  可区分，整段不再是同一个暗色；报告文本的产出函数一字未改。
- **AC14**（F19/F20）：每个系统行调用点都有明确级别；「子 Agent 完成」与「笔记已
  更新」在界面上**表现不同**。
- **AC15**（F21）：去掉颜色后仍能区分四个级别（前缀符号不同）。
- **AC16**（F23）：确认 / 澄清 / 会话面板的可选项带序号，按数字键即选中对应项；
  不可选行不占序号。
- **AC17**（F24）：当前高亮项有非颜色的指示符。
- **AC18**（F27/N8）：四个面板的结算语义、Esc 行为、焦点规则与改造前一致；
  数字键不与既有键位冲突。
- **AC19**（F28/F29/F30）：全界面搜不到表情符号；每处被替换的位置语义仍可辨
  （不靠颜色也能读出是危险操作 / 问句 / 锁定项 / 被阻塞）。
