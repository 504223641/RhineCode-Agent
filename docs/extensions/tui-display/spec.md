# TUI 显示体系改造（对齐 Claude Code） Spec

> 扩展，不占章节号。判据：`CLAUDE.md` 的能力表**不多一行**——本轮不引入新的能力
> 层级，改的是既有 TUI 层如何呈现**已有**能力。

## 背景

用户的起点是一个具体症状：**子 Agent 在工作时界面上没有任何状态**。派出去之后是
几分钟的静默，直到结论回流。但他要的范围更大——**整个显示体系对齐 Claude Code
的观感**。

### 开工第一步做的事：逐个盘点现有显示面

`docs/todo/5-tui-display-overhaul.md` 里只有「子 Agent 活动区」一节做过实地调研，
其余只有一张待盘点清单。本 spec 的第一步是把那张清单逐个读过一遍
（`tui/widgets.py` 1384 行、`tui/app.py` 1500 行、`subagents/tasks.py`、
`subagents/report.py`、`team/render.py`、`commands/builtins.py`），结果如下：

| 显示面 | 现状 | 判断 |
| --- | --- | --- |
| **工具行**（`ToolCallWidget`） | 四种视觉状态（参数生成中 / 执行中 / 完成 / 失败）；工具名已映射成展示标签；`⎿` 分支行给结果摘要；改文件带彩色 diff 块；主线程定时器每秒刷耗时 | **本轮改**（细节对齐） |
| **命令报告** | `/agents` `/skills` `/hooks` `/memory` `/context` `/tasks` `/help` 全部经系统提示行通道，**整段被包进一个 dim 块**，只有第一行带 `◆` 前缀 | **本轮改**（问题最大的一处） |
| **子 Agent 运行状态** | 除状态栏一个计数外**零显示** | **本轮改**（新建活动区） |
| 状态栏 | 单行右对齐的管道拼接，各段「无内容即隐藏」 | 本轮不改 |
| 通知与系统提示行 | 子 Agent 完成 / 上下文压缩 / 自动唤起 / 笔记更新 / 轮次提示**全走同一条 dim 通道**，无分级 | 本轮不改（已登记为后续项） |
| 历史区（用户消息 / AI 正文 / 思考） | 用户消息已是整行灰底、AI 正文走 Markdown 渲染、思考灰色斜体 | 本轮不改 |
| 四个面板（确认 / 澄清 / 会话 / 命令补全） | 交互形态一致，橙 / 青分隔线区分语义 | 本轮不改 |

### 已核实的三条地基

1. **轮询可行且是设计预期**。`TaskRecord` 的 `turns` / `usage_tokens` /
   `started_at` 是运行期持续更新的可变字段，任务表的快照返回记录对象本身（不深拷贝），
   且其加锁临界区只做纯内存读写。主线程定时读它不会被长时间阻塞。
   ⚠ 本项目**已经死锁过四次**，全部是「在加锁临界区里做跨线程调度」。轮询从结构上
   消掉这一整类问题。
2. **工具行与子 Agent 的生命周期是分叉的**。`background=true` 的委派在发起那一刻
   工具调用就已返回并定终态；工具行按既有护栏必须在拿到结果时摘除。因此活动区
   **必须独立**，不能复用工具行的结算逻辑。
3. **「工具调用次数」是唯一缺的数据**。运行器消费子 Agent 事件流时已在更新轮次与
   用量，同一处即可数工具调用；它本来就**不转发**子 Agent 的事件，加计数不破坏
   「子 Agent 的过程不渲染」这条既有约束。

## 对齐依据与确定性分级

⚠ **「对齐 Claude Code」指的是结构、符号与指标口径，不是把界面改成英文。**
本项目的界面语言约定是中文，工具名这类专有标签保持英文（既有做法），
状态词保持中文。

| 层 | 内容 | 确定性 |
| --- | --- | --- |
| 第 4 层 | 「子 Agent 默认后台运行，完成时**由系统通知你**」「**绝不要编造或预测**尚未完成的子 Agent 的结果——那条通知永远不是你自己写的」 | **确定**：Claude Code 系统提示原文 |
| 第 4 层 | 「子 Agent 的最终报告不展示给用户——把要紧的转述出来」 | **确定**：同上。本项目现状已符合，无需改动 |
| 第 1 层 | 运行中的 agent 行带三个数字：经过时间 / 累计 token / 工具调用次数 | 观察，版本间可能有出入 |
| 第 2 层 | 默认折叠，快捷键掀开看内部逐条工具调用 | 观察 |
| 第 3 层 | 完成后保留成本信息（次数 / token / 耗时） | 观察 |

三个数字的共同点是**不用理解内容就能判断「它在动、动得快不快」**。
刻意不把「子 Agent 正在做什么」翻译成人话展示——那既贵又容易误导。

## 目标

1. 后台子 Agent 全程可见，且按 Claude Code 的三层显示组织：活的进度行 / 可展开的
   内部细节 / 终态留下的成本痕迹。
2. 完成通知由**系统**产生，不经模型自述。
3. 命令报告不再被拍平成一整块暗色文本，内部层级可辨。
4. 工具行的细节与 Claude Code 的形态对齐，消除既有噪音。
5. 全过程不引入任何从后台线程到界面的推送，不违反已有的加锁与转义护栏。

## 功能需求

### A 组 · 子 Agent 活动区

- **F1 位置与出现时机**：活动区是一块独立区域，位于历史区**下方**、各交互面板与
  输入框**上方**。它在「有正在运行的任务」或「有尚未淡出的终态行」时出现，
  两者都没有时**整块隐藏且不占布局空间**。
- **F2 一条活动行的内容**：形如
  `● <名字> 运行中 (<耗时> · ↑<token> · <次数> 次调用)`。
  名字的口径与 `/agents` 一致——协作启用时显示 `队员名(角色名)`，否则显示角色名；
  分支式委派显示既有的分支占位名。
- **F3 三个数字的语义**：耗时按「起始时刻到现在」实时计算；token 为该任务累计用量；
  次数为该子 Agent 已完成的工具调用总次数。三者都必须**在任务运行期间持续变化**，
  而不是结束时才有值。
- **F4 数据获取一律走轮询**：活动区的一切数据由**主线程**定时从任务表读取快照。
  **不新增任何从子 Agent 线程到界面的推送通道**，也不新增定时器——复用既有的
  子 Agent 轮询节拍（空闲会话的开销与改造前一致）。
- **F5 折叠与展开**：活动区默认折叠，只显示每个任务一行。一个快捷键在「折叠 /
  展开」之间切换**整个区域**；展开时每条任务下方列出它内部**最近若干次**工具调用
  （工具名 + 短参数摘要），条数有上限。展开状态在切换前保持不变。
  ⚠ 快捷键**不引入焦点切换**——活动区任何时候都不抢焦点，输入框、命令面板与四个
  确认面板的键位体系一字不动。
- **F6 终态处理**：任务结束时该行原地转为终态样式并显示最终成本
  （`完成 / 失败 / 已取消` + 次数 / token / 耗时），在区内**停留数秒后消失**；
  同时向历史区写入一条**永久留痕**，内容含同一组成本数字。
  区内与历史区两处的成本数字必须同源同口径。
- **F7 完成通知由系统产生**：既有的完成通知继续由界面轮询产出（不经模型），
  文案补上 F6 的成本数字。
- **F8 会话切换清空**：`/clear` 与 `/resume` 之后活动区必须为空——上一段对话的
  任务行不得留在新对话的界面上。
- **F9 零回归**：未启用子 Agent 能力时活动区**永不出现**，界面与改造前逐字一致。
- **F10 活动区只观测，不操作**：区内不提供取消或任何改变任务状态的入口。
  取消仍走 `/agents cancel`，全量信息（角色定义、加载错误、历史任务、隔离工作区、
  结论预览）仍看 `/agents`。**活动区给概览，`/agents` 给全量**，两者职责不重叠，
  本轮不动 `/agents` 的任何一段。

### B 组 · 工具行细节对齐

- **F11 工具展示标签对齐 Claude Code 的词汇**：既有的「内部工具名 → 展示标签」
  映射按 Claude Code 的工具命名调整，未登记的工具继续回退到原始名。
- **F12 耗时只在有意义时出现**：工具行终态的耗时**低于一秒时不显示**。
  现状是每一行都写着 `完成 (0s)`——绝大多数工具调用是毫秒级的，那个恒为零的
  括号是纯噪音，且与 Claude Code 的形态不符。执行中的实时计时**保持不变**
  （它是那段时间里界面上唯一的活体信号，是刻意做的）。
- **F13 分支符号与配色单一来源**：工具行、活动区、报告三处的 `⎿` 分支符号与
  次级信息配色取自**同一处定义**，不各写一份。

### C 组 · 命令报告的渲染

- **F14 报告走专用显示通道**：命令产出的多行报告不再经系统提示行通道整段变暗，
  改由专用的报告渲染呈现。
- **F15 分级规则在展示层推断**：报告按行判定层级——段落标题、条目行、条目的次级
  信息、空行——并施加不同的亮度与强调。**各报告的文本产出函数一律不改**
  （它们是纯函数，且有大量逐字断言的护栏钉着）。
- **F16 报告首行保留可辨识的前缀**，使它在历史区里仍能一眼看出「这是一次命令的
  结果」，而不是 AI 说的话。
- **F17 单行消息行为不变**：不是报告的普通系统提示（一行的那些）继续沿用既有样式，
  本轮不动。

## 非功能需求

- **N1 不引入跨线程推送**。活动区的全部数据经主线程轮询读取；任何在后台线程里
  调用界面更新的写法都不接受。理由：本项目已因「加锁临界区内做跨线程调度」
  死锁四次。
- **N2 一切嵌入 markup 的文本必须经本项目自己的转义实现**，不得使用 rich 那一版。
  活动区会嵌入队员名、角色名、工具参数摘要，报告会嵌入路径、错误消息与任务标题
  ——**全都是可能含字面 `[` 的自由文本**。漏转义的后果是布局阶段抛错、
  整个应用退出，没有任何异常处理兜得住。
- **N3 零回归**：不使用子 Agent 的用户、以及只发单行系统提示的路径，界面表现与
  改造前逐字一致。
- **N4 不新增行为记录（trace）事件类型**。活动区的终态留痕经既有的界面消息通道
  产出记录即可。新增事件类型会牵动「枚举 + 阅读器摘要表」这个成对维护点，
  而本轮没有需要它承载的新信息。
- **N5 一切展示都有界**：活动行条数以并发上限（5）为界，展开的工具调用条数有上限，
  报告渲染不做无界重排。
- **N6 端到端可观测**：活动区必须能被既有的端到端驱动设施按稳定选择器抓到可见文本，
  否则本轮的验收只能靠人眼。
- **N7 主线程每次轮询只做纯内存读取与组件更新**，不做 IO、不发请求。

## 不做的事

- **通知与系统提示行的分级**（子 Agent 完成 / 上下文压缩 / 自动唤起 / 笔记更新 /
  轮次提示共用一条暗色通道）——用户本轮未选入范围。
- **状态栏重排**。本轮只在活动区出现后不动它，既有的 `子Agent:N` 段保持原样。
- **四个面板的改造**（确认 / 澄清 / 会话 / 命令补全）。
- **把报告改写成 Markdown 再渲染**。观感更好，但要改十几个带逐字断言护栏的纯函数，
  收益不抵风险。
- **活动区里操作任务**（取消、展开单条、跳转），见 F10。
- **主对话自身的成本显示**（主 Agent 的 token / 耗时）。本轮只做子 Agent 的。
- **历史区、用户消息、AI 正文、思考块的样式改动**。
- **子 Agent 的过程事件转发到主界面**。活动区展示的是**计数与名字**，
  不是把子 Agent 的输出喷到主界面——那会抵消掉委派的全部价值。

## 验收标准

- **AC1**（F1/F9）：无任何子 Agent 运行时，界面上不存在活动区，布局与改造前一致；
  发起一次委派后活动区出现。
- **AC2**（F2/F3）：委派一个子 Agent 后，活动行显示它的名字与三个数字，
  且在任务运行期间**三个数字都会变化**（观察两次采样不相等）。
- **AC3**（F3）：活动行显示的次数与该任务实际发生的工具调用次数一致。
- **AC4**（F4/N1/N7）：活动区的数据更新全部发生在主线程；代码中不存在从子 Agent
  线程更新活动区的路径。
- **AC5**（F5）：按下约定快捷键，活动区在折叠与展开之间切换；展开时能看到每条任务
  内部最近的工具调用；切换过程中输入框焦点不丢失。
- **AC6**（F6）：任务结束后，活动区那一行转为终态并显示最终成本，随后消失；
  历史区留下一条含同一组数字的永久记录。
- **AC7**（F7）：完成通知含成本数字，且它由界面轮询产出——不依赖模型说任何话。
- **AC8**（F8）：`/clear` 之后活动区为空。
- **AC9**（F11）：工具行的展示标签与 Claude Code 的工具命名一致；未登记的工具
  显示原始名。
- **AC10**（F12）：耗时不足一秒的工具调用，终态行**不出现**耗时括号；
  超过一秒的照常显示；执行中的实时计时不受影响。
- **AC11**（F13）：三处的分支符号与次级配色取自同一定义（改一处三处同时变）。
- **AC12**（F14/F15/F16）：`/agents` 的报告在界面上呈现出分级——段落标题与条目行
  在视觉上可区分，整段不再是同一个暗色；报告文本的产出函数一字未改。
- **AC13**（F17）：单行系统提示的呈现与改造前逐字一致。
- **AC14**（N2）：活动区与报告渲染中，每一处嵌入自由文本的地方都经过本项目的转义
  实现；构造一个名字或参数里含未闭合 `[` 的场景，应用不崩溃。
- **AC15**（N3）：不使用子 Agent、不敲报告类命令的完整交互流程，界面表现与改造前
  一致。
- **AC16**（N6）：端到端驱动设施能按稳定选择器抓到活动区的可见文本，
  并据此断言任务在跑 / 已结束。
- **AC17**（N5）：并发跑满上限时活动区条数不超过上限；展开时每条任务的工具调用
  条数不超过约定上限。
