# 工具活动归并与回合状态行 Checklist

> 每一项通过**运行代码或观察行为**来验证，聚焦系统行为而非实现细节。
> 覆盖 [`spec.md`](spec.md) 的全部 29 条验收标准，另补 [`plan.md`](plan.md)
> 层面的集成检查与三条真机项。
>
> ⚠ **最后一节「真机验收」不可自动化也不可省**，理由写在那一节。

## 一、实现完整性 · A 组 · 批次归并

- [ ] **一批连续的只读检索调用在历史区只占一行**（AC1）
      验证：跑一个触发 3 次以上检索的场景，数历史区新增的可见行数——
      应为 1 行聚合行，而非「每次调用两行」。
- [ ] **模型输出正文后，其后的检索开一个新批次**（AC1）
      验证：同一场景里正文前后各有检索，观察到两个独立的聚合行，中间隔着那段正文。
- [ ] **确认面板放行过的调用仍留在当前批次里**（AC2）
      验证：让一次检索触发确认面板，放行后观察该调用被折进聚合行，
      **不产生额外的批次断开**。
- [ ] **写文件调用独立成行并带差异块**（AC3）
      验证：一次同时含检索与写文件的运行，写文件那行在折叠状态下**始终可见**，
      且下方有彩色差异块。
- [ ] **执行命令、委派子 Agent、加载 Skill 三类同样独立成行**（AC4）
      验证：分别触发，观察各自独立可见、不进聚合行。
- [ ] **聚合语按动作意图分组，且顺序与实际发生时序一致**（AC5）
      验证：先搜索后读取的场景，聚合语里搜索段在前；
      读到的量词是「搜索内容 N 次」「读取 N 个文件」这类**带宾语**的形态。
- [ ] **单次调用仍用聚合语，且下方有一条从属行放主参数值**（AC6）
      验证：只触发一次检索，聚合行形如「搜索内容 1 次」，
      其下一行显示该次调用搜的是什么。
- [ ] **多次调用时聚合行下方不出现从属行**（AC6）
      验证：触发 3 次检索，聚合行下方无从属行。
- [ ] **运行期间批次显示进行时文案与当前调用的参数**（AC7）
      验证：运行中观察聚合行形如「搜索中…」，从属行是当前正在搜的内容；
      并发多个时显示最近开始的那一个。
- [ ] **批次形态不因后续又发生了几次调用而改变**（AC7）
      验证：运行中形态保持进行时，直到批次封闭才切到完成态。
- [ ] **运行期间批次块内不出现任何耗时数字**（AC8）
      验证：运行中观察批次块，**没有任何秒数**。
- [ ] **并行检索中有一个失败时，聚合行变失败色并写出失败个数**（AC9）
      验证：构造一次失败（如搜索一个不存在的路径）而模型继续运行，
      聚合语末尾出现「N 个失败」；展开后能定位到具体是哪一次。
- [ ] **成功的调用行不含「完成」二字，失败的仍含「失败」**（AC10）
      验证：展开后逐条查看，成功行只有「标签(参数)」与可选耗时。

## 二、实现完整性 · B 组 · 三级密度

- [ ] **连按三次展开键，界面依次经过折叠、逐条、全文并回到折叠**（AC11）
      验证：按三次，观察四个状态（含回到起点）各不相同且循环闭合。
- [ ] **三档的提示文案分别指向「展开 / 看全文 / 收起」，与实际按键效果一致**（AC12）
      验证：每一档读一次聚合行末尾的提示，按下去到达的档位与提示所说相符。
- [ ] **全文档下调用标题包含全部参数且无省略号**（AC13）
      验证：找一个带长路径的调用，全文档下标题里路径完整、参数不止一个；
      同一调用在逐条档下的标题是截断版。
- [ ] **全文档下结果块显示输出原文**（AC14）
      验证：一次读取或搜索，全文档下能看到实际内容行而非仅规模描述。
- [ ] **输出被工具裁剪过时，末行如实注明并指出完整原文的取得方式**（AC14）
      验证：跑一条输出很长的命令，全文档下结果块末行有裁剪说明。
- [ ] **子 Agent 活动区在逐条档与全文档下呈现一致**（AC15）
      验证：有子 Agent 运行时切换这两档，活动区内容不变。

## 三、实现完整性 · C 组 · 回合状态行

- [ ] **运行中输入框上方出现状态行，含旋转标记 / 阶段词 / 耗时 / token / 中断提示**（AC16）
      验证：发一条消息，运行期间观察该行五段齐全。
- [ ] **耗时每秒变化，token 在每轮结束时跳变一次**（AC16）
      验证：连续观察数秒——秒数持续增长，token 数字**阶段性跳变而非持续滚动**。
      ⚠ 两者节奏不同是**预期行为**（Provider 协议限制），不是缺陷。
- [ ] **运行结束后状态行消失，且历史区不留任何痕迹**（AC17）
      验证：运行结束后整屏文本中不含状态行内容；向上翻历史也找不到它。
- [ ] **符号扫描护栏通过，新增字形已登记**（AC18）
      验证：运行符号护栏测试。
- [ ] **有一条护栏断言旋转标记各帧计算宽度两两相等**（AC18）
      验证：临时把其中一帧换成已知不等宽的字符，该护栏**当场失败**；
      改回后通过。（这条反证是护栏有效性的唯一证据）
- [ ] **确认面板弹出期间状态行仍在、耗时继续累计、阶段词为等待语义、不显示中断提示**（AC19）
      验证：走到确认面板，观察状态行——阶段词已切换，秒数仍在涨，
      **中断提示消失**。
- [ ] **并发执行多个工具时，界面上只有一处时间数字在变化**（AC20）
      验证：触发多个并发检索，全屏只有状态行那一个秒数在跳。
- [ ] **会话切换后状态行消失、档位回到默认**（AC21）
      验证：先切到全文档并跑一轮，再清空会话，观察状态行不在、档位已复位。

## 四、集成

- [ ] **归并表经既有通道注入，且在历史回放之前生效**
      验证：用恢复会话的方式启动，首屏回放出来的工具行与其后新产生的
      **形态一致**（不出现「上下两截风格不同」）。
- [ ] **批次容器不参与工具行的登记与摘除**
      验证：既有的 `_do_stream` 接线护栏仍通过——**它是「未破坏该不变量」
      这条论证的唯一证据**，不得为适配本轮改动而修改它。
- [ ] **没等到结果的工具行仍被正确收尾**
      验证：运行中按取消键，观察批次内未定色的行被标记为未执行，
      不留下永远转圈的行。
- [ ] **本轮新增代码中不存在从后台线程直接操作界面的路径**（AC22）
      验证：既有的死锁护栏与活动区轮询护栏全部通过；
      人工确认批次回调均发生在主线程调用链内。
- [ ] **参数值或结果原文含未闭合方括号时界面正常渲染且程序不退出**（AC23）
      验证：构造一个参数含未闭合方括号的调用，
      在**三个档位下各观察一次**，均正常显示。
- [ ] **档位切换与批次的形成/封闭可在行为记录中还原**（AC26）
      验证：开启记录跑一轮，用阅读器读时间线——两类新事件都有**摘要行**，
      不显示为「未登记类型」。

## 五、零回归

- [ ] **不触发任何工具的对话，界面与改造前逐字一致**（AC24）
      验证：纯对话一轮，导出整屏文本与改造前对比。
- [ ] **只触发写文件与执行命令的对话，界面与改造前逐字一致**（AC24）
      验证：同上，用只含这两类工具的场景。
- [ ] **状态行缺省隐藏时不占布局**（AC24）
      验证：空闲状态下整屏文本与改造前逐字一致，历史区高度不变。
- [ ] **批次块与状态行出现期间输入框焦点不变，各面板键位行为不变**（AC25）
      验证：运行中敲字符能正常进输入框；面板弹出时数字键直选仍生效。
- [ ] **历史区仍不可聚焦，展开键不引入焦点切换**（AC25）
      验证：按展开键后继续打字，字符仍进输入框。

      验证：`python -m compileall rhinecode tests`
- [ ] 全量测试通过，跳过数与改造前一致
      验证：`python -m unittest discover -s tests` —— 全绿，skipped 为 4
- [ ] 新增的三个测试文件各自独立通过
      验证：分别运行批次、档位、状态行三个测试模块

## 七、端到端场景

- [ ] **场景 1 · 混合运行**（覆盖 AC1/AC3/AC5）
      操作：脚本化剧本——连发 3 个只读检索 → 输出一段正文 → 发 1 个写文件 → 结束。
      预期：历史区依次是「一个聚合行」「一段正文」「一个独立的写文件行（带差异块）」，
      共 3 个可见块。
- [ ] **场景 2 · 三档巡视**（覆盖 AC11/AC12/AC13/AC14）
      操作：在场景 1 结束后连按三次展开键，每档导出一次整屏文本。
      预期：三份文本互不相同；折叠档最短、全文档最长且含结果内容行；
      每份的提示文案与下一次按键的实际效果相符。
- [ ] **场景 3 · 失败不被藏起来**（覆盖 AC9）
      操作：剧本里让并行检索中的一个失败，模型继续运行不停下。
      预期：折叠状态下就能看出「有东西失败了」——聚合行为失败色且写出个数。
- [ ] **场景 4 · 面板期间的状态行**（覆盖 AC19）
      操作：剧本走到确认面板并停住，导出整屏文本。
      预期：状态行在、阶段词为等待语义、无中断提示。
- [ ] **场景 5 · 清空复位**（覆盖 AC21）
      操作：切到全文档 → 跑一轮 → 清空会话 → 导出整屏文本。
      预期：无状态行、无批次残留、档位回到默认。

## 八、真机验收（不可自动化）

> ⚠ **这三条只能在真实终端里用眼睛验，不可省略。**
> 原因：渲染库与终端**各自计算字符宽度**，而本轮选用的旋转标记属
> Unicode「模糊宽度」——渲染库两侧算出来都是 1 格，
> **单元测试永远看不到终端把它画成 2 格这件事**。
> 这正是 spec F16 明确记录并接受的那条已知风险。

- [ ] **旋转标记每帧切换时，其后的文字不发生左右位移**（AC18a）
      验证：真实终端里发一条会跑数秒的请求，盯住状态行的「处理中」三个字，
      确认它在动画过程中**位置纹丝不动**。
      ⚠ 若发现位移：按 spec F16 记下的退路，把帧表换成全中性宽度的字形组
      （`⬩ ⟐ ✥ ⟐` 或 `✢ ✣ ✤ ✥`，均已实测可用）——
      **只需替换一张常量表，不动任何结构**——然后复验本条。
- [ ] **动画节奏为「明显在动但不干扰阅读」**（AC18b）
      验证：真实终端里观察十秒以上，确认既能一眼看出程序还活着，
      又不会因为闪得太快而分神。
- [ ] **三档循环在真实终端里手感正确**
      验证：真机按三次展开键，确认每次的视觉变化明显、提示文案与结果相符，
      且**焦点始终留在输入框**（按完能直接继续打字）。
