# 工具活动归并与回合状态行 Spec

> 扩展，不占章节号。判据：`CLAUDE.md` 的能力表**不多一行**——本轮不引入新的能力
> 层级，改的是既有 TUI 层如何呈现**已有**能力。
>
> 与 [`tui-display/`](../tui-display/spec.md) 同主题但不重叠：那一轮做的是
> 「让子 Agent 可见 + 符号与键位对齐」，这一轮做的是「压缩过程信息的显示密度」。

## 背景

起点是一个具体症状：**用户让 Rhine「读一下项目」，它调了十几次 `Read` / `Glob` /
`Grep`，这些调用全部平铺在聊天窗口里，把真正要读的结论淹掉了。**

### 现在的样子

一次「读项目结构」在历史区留下的痕迹（20 次调用 = **净增 40 行，全部累积**，
其中 20 行是高饱和绿色）：

```
> 读一下项目结构

● Glob(rhinecode/**/*.py) 完成 (1s)          ← 整行 #5FD75F 亮绿
  ⎿ 共 47 个文件                              ← 整行 #808080 灰
● Read(rhinecode/__main__.py) 完成
  ⎿ 读取 312 行 · 11.2 KB
● Read(rhinecode/bootstrap.py) 完成 (1s)
  ⎿ 读取 428 行 · 18.7 KB
● Read(rhinecode/conversation.py) 完成 (2s)
  ⎿ 读取 1104 行 · 46.3 KB
● Grep(class .*Provider) 完成
  ⎿ 共 4 处匹配
● Read(rhinecode/provider/base.py) 完成
  ⎿ 读取 208 行 · 7.9 KB
   …（再 14 次，共 40 行）…

Rhine：这个项目分为……
```

运行中同一时刻的样子（三个数字**各自**每秒跳一次）：

```
● Glob(rhinecode/**/*.py) 执行中… 3s
● Read(rhinecode/__main__.py) 执行中… 2s
● Read(rhinecode/bootstrap.py) 执行中… 2s
```

### 改好后的样子

历史区：

```
> 读一下项目结构

● 查找 1 次 · 读取 8 个文件 · 搜索 3 次        （Ctrl+O 展开）

Rhine：这个项目分为……
```

运行中：

```
● 读取中…
  ⎿ rhinecode/bootstrap.py

✻ 处理中… (12s · ↑ 2.1k · esc 中断)          ← InputBar 上方，全局唯一一个 spinner
```

### 开工前的现状盘点

逐个读过 `tui/widgets.py` 的 `ToolCallWidget`、`tui/app.py` 的 `_do_stream`、
`tools/display.py`，结果如下：

| 现状 | 判断 |
| --- | --- |
| 工具名已映射成展示标签（`Read` / `Grep` / `Bash`），括号里已是主参数值 | **不改**——tui-display 一期成果，已对齐 |
| 每个工具结果已由工具自报一句规模摘要（`读取 234 行 · 12.3 KB`），不铺原文 | **不改**——已对齐 |
| 每次调用 = 一个组件 = 屏幕两行，**全部平铺进历史区、无归并** | **改**（A 组） |
| 终态标题写「完成」二字 | **改**（A 组） |
| `Ctrl+O` 是全局布尔（关/开），展开只影响结果块行数，**标题永远是折叠时算好的截断版** | **改**（B 组） |
| 每个工具行自带 `set_interval(1.0)` 定时器，并发时多个数字同时跳 | **改**（C 组） |
| 无回合级状态行——`#status-row` 装的是配置态（provider / 模型 / 权限档），不是「此刻在忙什么」 | **改**（C 组，新建） |

### 三条已核实的地基

1. **归并的边界已经存在。** `_do_stream` 里 `reset_text_widgets()` 的四个调用点
   就是「模型输出正文」的语义边界，与批次断开的时机完全一致，**不需要新造判定**。
2. **`USAGE` 事件已存在但不实时。** DeepSeek 的 `stream_options.include_usage`
   只在**每轮流末尾**产出一次用量（`provider/deepseek.py`）。因此状态行的 token
   数字是**每轮跳一次**，不是逐字节滚动——这个差别写进验收标准（AC16），
   免得验收时误判成 bug。
3. **失败的可见性有一大半是免费的。** 批次边界定成「正文断开」之后，失败后模型
   停下来说明这一种情况会自然断开批次，那条调用单独可见。需要专门兜底的只剩
   「并行调用中某个失败、而模型没停下来继续干活」这一种（F6）。

### 一条贯穿全文的安全判据

**只有只读检索类工具参与归并。** 写文件、跑命令、委派子 Agent、加载 Skill 一律
不归并，照旧独立成行。

理由有三条，但结论只有一句——**被折叠的永远只是「读」，「写」和「执行」一行都不会少**：

1. 它们**有副作用**，改变了工作区或会话状态，属于「结果」而非「过程」；
2. 改文件类调用带 diff 块，那正是用户要看的内容（`● Update(app.py)` + 彩色差异）；
3. 它们数量本来就少，不构成刷屏——刷屏的全是只读检索。

这条同时让「折叠会不会藏掉重要信息」这个问题在结构上消解：藏起来的东西**在定义上
就是无副作用的**。

### 两条已拍板的约束

- **整行上色保留不动。** 成功仍是整行绿、失败仍是整行红，本轮不动配色。
- **成功态去掉「完成」二字**（绿色已经表达了状态，文字重复）。失败态的「失败」保留。

## 目标

1. 一轮里连续发生的只读检索调用在历史区**归并成一行**，默认折叠；正文与正文之间
   不再被几十行过程隔开。
2. 折叠 / 逐条 / 全文**三级密度**，由 `Ctrl+O` 循环切换，**当前档位与下一档写在
   屏幕上**，用户不必记。
3. 运行中的活体信号从「每个工具行一个跳动的秒数」收敛为**底部一行**
   （spinner + 本回合总耗时 + 累计 token + 中断提示），运行结束即隐藏。
4. 折叠**不藏失败**：批次内有失败时聚合行变红并写出失败个数。
5. **零回归**：不违反既有的转义护栏、加锁不变量、符号白名单、活动区主线程轮询约束；
   未触发工具调用的对话界面与改造前逐字一致。

## 功能需求

### A 组 · 历史区批次归并

**这一组的前后对照**

```
现在：                              改好后（默认档）：
● Grep(class .*Provider) 完成       ● 搜索 3 次 · 读取 2 个文件    （Ctrl+O 展开）
  ⎿ 共 4 处匹配
● Grep(def create_provider) 完成
  ⎿ 共 2 处匹配
● Grep(protocol) 完成
  ⎿ 共 31 处匹配
● Read(provider/base.py) 完成
  ⎿ 读取 208 行 · 7.9 KB
● Read(provider/deepseek.py) 完成
  ⎿ 读取 336 行 · 13.1 KB
```

- **F1 批次的形成与断开**：一批**连续发生**的只读检索调用归并为**一个批次块**，
  在历史区占一行。断开边界是**模型输出正文**——正文一出现，当前批次即封闭，
  其后的调用开一个新批次。因此对话的结构恒为「正文 → 批次块 → 正文 → 批次块」，
  **两段正文之间永远只隔一行**。
  ⚠ 确认面板弹出**不构成断开**：用户已经在面板上看清楚了那次调用并亲手做了决定，
  历史区不需要再强调一遍。

- **F2 哪些工具参与归并**：只有**只读检索类**工具参与——读文件、查找文件、
  搜索内容、抓取网页。**明确不参与**的四类：写文件与编辑文件（有副作用、带 diff）、
  执行命令（有副作用、输出本身是用户要看的内容）、委派子 Agent（已有活动区与
  历史区留痕，归并会与那套冲突）、加载 Skill（改变会话能力，属于结果）。
  不参与归并的调用**照旧独立成行**，形态与改造前逐字一致。
  ⚠ 未登记的工具（含 MCP 工具）**一律按不参与处理**——偏严方向：漏登记只会
  少折叠一条，反过来会让一个有副作用的外部工具被静默折叠。

- **F3 折叠态的聚合语**：按**动作意图**分组计数，不是按内部工具名统计。
  各组之间用行内分隔符连接，**组的先后按该组第一次调用发生的时序排**，
  使聚合语的顺序与实际发生顺序一致。分组与量词：

  | 意图 | 量词形态 |
  | --- | --- |
  | 查找文件 | `查找 N 次` |
  | 搜索内容 | `搜索 N 次` |
  | 读取文件 | `读取 N 个文件` |
  | 抓取网页 | `抓取 N 个网页` |

  例：`● 查找 1 次 · 读取 8 个文件 · 搜索 3 次`

- **F4 单次调用的批次不套聚合语**：批次内只有一次调用时，折叠态**直接显示该次
  调用的标题行与结果行**（即改造前的形态），不写成「读取 1 个文件」。
  理由：聚合语在数量为一时比原始形态信息更少且措辞别扭。

- **F5 运行中的批次形态**：批次在运行期间显示**进行时**的一行，
  形如 `● 读取中…`，其下的从属行显示**当前正在进行的那次调用的主参数值**。
  多个调用并发时，从属行显示**最近开始**的那一个。
  ⚠ 运行中的批次块**不显示耗时**——耗时统一由 C 组的状态行承担（F13），
  两处各显示一份会让用户去比对两个不相等的数字。

- **F6 失败的兜底表现**：批次内有失败调用时，聚合行的状态点变为失败色，
  且聚合语末尾追加失败个数，形如
  `● 搜索 5 次 · 1 个失败`。要知道是哪一个，按 `Ctrl+O` 展开。
  ⚠ 这是**兜底路径**：真正要紧的失败（模型因此停下来说明的）已经被 F1 的
  正文断开边界报掉了，此处覆盖的只有「并行调用中某个失败、模型没停」这一种。

- **F7 终态文案**：成功的调用行**不再写「完成」二字**（状态已由颜色表达）。
  失败的调用行**保留「失败」二字**——它是脱离颜色也能辨认的唯一依靠。

### B 组 · 三级信息密度

**这一组的前后对照**

```
现在（两态）：                      改好后（三态循环）：

关：                                档 1（默认）：
● Grep(def compose_status_te…) 完成  ● 搜索 3 次 · 读取 2 个文件   （Ctrl+O 展开）
  ⎿ 共 3 处匹配
  ⎿ …（结果块最多 5 行）             档 2（逐条）：
                                     ● 搜索 3 次 · 读取 2 个文件   （Ctrl+O 看全文）
开：                                   ● Grep(def compose_status_text)
● Grep(def compose_status_te…) 完成      ⎿ 共 3 处匹配
  ⎿ 共 3 处匹配                        ● Read(widgets.py)
     …（结果块全文）                     ⎿ 读取 1902 行 · 78.4 KB
                                    
⚠ 标题里的参数**两态都是截断版**       档 3（全文）：
                                     ● 搜索 3 次 · 读取 2 个文件   （Ctrl+O 收起）
                                       ● Grep(pattern: "def compose_status_text",
                                              path: "rhinecode/tui/widgets.py")
                                         ⎿ 共 3 处匹配
                                            1598:def compose_status_text(
                                            1599-    provider: str,
                                            …
```

- **F8 三个档位的定义**：
  - **档 1 折叠**（默认）：批次块只显示聚合行一行。
  - **档 2 逐条**：批次块展开为逐次调用，每次调用显示标题行（主参数值）与结果行
    （工具自报的规模摘要），结果块**仍受行数上限约束**。
  - **档 3 全文**：在档 2 基础上，标题显示**完整参数且不截断**，结果块显示
    工具输出原文、不受行数上限约束。

- **F9 一个键循环三档**：既有的展开快捷键在「档 1 → 档 2 → 档 3 → 档 1」之间
  循环。**不引入第二个快捷键**（沿用 tui-display F41 的既有约束：对齐全局
  verbose 语义，两个键会让用户记两套）。档位是**全局**的，作用于历史区所有批次块。

- **F10 当前档位与下一档写在屏幕上**：批次块的聚合行末尾常驻一段提示，
  内容随当前档位改写为「展开 / 看全文 / 收起」，使三态循环**不需要用户记忆**。
  改造前那句固定的「（Ctrl+O 展开）」由它取代。

- **F11 档 3 的标题不截断**：档 3 显示该次调用的**全部参数**，
  每个值完整、不加省略号。改造前标题在组件构造时一次性算好且恒为截断版，
  展开只影响结果块——本轮必须让标题随档位重算。

- **F12 档 3 的内容来源与上限**：结果块在档 3 显示工具的**输出原文**。
  ⚠ 已被工具主动裁剪过的输出（如执行命令的前 30 + 后 10 行）**显示裁剪后的那份**，
  并在末行如实注明还有多少行、以及完整原文可从行为记录（trace）取得。
  理由：那份裁剪是为「给人和模型看」而做的，展开成完整原文会让一次
  测试套件输出撑爆历史区。

- **F13 活动区没有第三档**：子 Agent 活动区（tui-display 一期建立）只有折叠与展开
  两态，档 2 与档 3 对它而言表现一致。**不为它造第三态**。

### C 组 · 底部回合状态行

**这一组的前后对照**

```
现在：                                  改好后：
（无回合状态行；活体信号散在每个工具行上）  ┌ HistoryView ──────────────┐
                                        │ ● 读取中…                  │
● Glob(rhinecode/**/*.py) 执行中… 3s     │   ⎿ rhinecode/bootstrap.py │
● Read(rhinecode/__main__.py) 执行中… 2s └───────────────────────────┘
● Read(rhinecode/bootstrap.py) 执行中… 2s   ActivityView（有子 Agent 时）
   ↑ 三个定时器各自每秒跳一次              各面板（弹出时）
                                        ✻ 处理中… (12s · ↑ 2.1k · esc 中断)
                                        ┌ InputBar ─────────────────┐
                                        │ >                          │
                                        └───────────────────────────┘
                                         StatusHint | StatusBar
```

- **F14 位置与出现时机**：状态行是一块独立区域，位于各交互面板**下方**、
  输入框**上方**。它**只在一次运行进行中出现**，运行结束即隐藏且**不占布局空间**。
  它**不进历史区**——「跑了 12 秒」这条信息几秒后就过期，写进历史等于灌入过期数据。

- **F15 状态行的内容**：形如 `✻ 处理中… (12s · ↑ 2.1k · esc 中断)`，各段语义：

  | 段 | 语义 |
  | --- | --- |
  | 旋转标记 | 逐帧循环的字形，**「还活着」的视觉证据**——不需要读就能判断 |
  | 状态词 | 当前阶段（处理中 / 思考中 / 等待确认） |
  | 耗时 | **本回合**累计耗时，从用户提交那一刻起算，实时刷新 |
  | token | 本回合累计 token 用量 |
  | 中断提示 | 逃生口（`esc 中断`） |

  各段之间用行内分隔符连接；无数据的段**整段隐藏**（与状态栏各段的既有做法一致）。

- **F16 旋转标记的字形取自符号白名单**：既有白名单里的思考标记是唯一合法的
  「特例」类符号，本轮的旋转标记必须在它的基础上取变体，**并把新增字形登记进
  白名单及其扫描护栏**。不得引入白名单之外的图形符号。

- **F17 token 每轮更新一次，不实时**：受 Provider 协议限制（用量只在每轮流末尾
  抵达），token 段是**跳变式**更新而非持续滚动。这是**已知且如实记录的行为**，
  不是缺陷。耗时段则必须实时刷新。

- **F18 等待用户时的表现**：确认 / 澄清 / 计划审批面板弹出期间，状态行**继续存在**
  但状态词切换为等待语义，且**耗时继续累计**——那段时间确实在这次回合内。
  ⚠ 中断提示在此期间**不显示**：面板有自己的取消方式，两套提示同屏会误导。

- **F19 工具行定时器收敛**：改造后每个工具行**不再各自持有每秒刷新的定时器**。
  运行中的时间显示由状态行统一承担，全界面**同时至多一个**该类定时器。

- **F20 会话切换清空**：`/clear` 与 `/resume` 之后，状态行必须消失、
  展开档位复位为默认档。

## 非功能需求

- **N1 不新增跨线程推送**：状态行与批次块的一切数据更新，要么由主线程定时器
  自行读取，要么沿用既有的 `call_from_thread` 调度路径。
  **不新增任何从后台线程到界面的推送通道**。本项目已因「加锁临界区内做跨线程调度」
  死锁四次。

- **N2 转义护栏不变**：批次块与状态行嵌入的一切纯文本（参数值、路径、结果原文、
  错误消息）必须走项目自有的转义函数，**不得改用第三方库的同名实现**。
  落单的方括号会在布局阶段的主线程抛错，没有任何异常处理兜得住。

- **N3 符号白名单**：界面新增的一切符号必须先进白名单及其扫描护栏。
  除 F16 的旋转标记外，本轮**不引入任何新符号**——分隔、从属、状态点、
  token 标记全部复用既有的六个。

- **N4 零回归**：未触发工具调用的对话、以及只触发不参与归并的工具（写文件 /
  执行命令 / 委派 / Skill）的对话，界面与改造前**逐字一致**。

- **N5 一切展示都有界**：档 1 与档 2 的每一处展示都有明确上限；档 3 的上限
  由工具侧既有的输出约束承担（F12）。任何档位都不得出现「无上限地铺内容」。

- **N6 焦点体系不变**：批次块与状态行**任何时候都不抢焦点**，历史区仍不可聚焦。
  输入框、命令面板与四个交互面板的键位体系一字不动。

- **N7 行为记录可观测**：档位切换、批次的形成与封闭必须能在行为记录（trace）里
  还原，新增字段须同步进阅读器的摘要行，否则等于白记。

## 不做的事

- **Tip 行**（等待期轮播功能提示）——用户明确本轮不做。
- **配色改动**——整行上色保留，不改成「只给状态点上色」。
- **结果摘要口径**——工具自报的规模摘要（`读取 234 行 · 12.3 KB`）一字不动。
- **子 Agent 活动区的任何改动**——它给子 Agent 概览，本轮不碰，
  除 F13 明确的「没有第三档」之外。
- **鼠标交互与单条独立展开**——历史区不可聚焦是既有约束，因此没有「点开某一条」
  的概念，档位只能是全局的。
- **归并写类与执行类操作**——见「一条贯穿全文的安全判据」。
- **token 的实时化**——受 Provider 协议限制（F17），不为此改动 Provider 层。
- **展开档位的跨会话持久化**——每次启动回到默认档，`/clear` 亦复位。
- **其它 Provider**——工具调用仅在 DeepSeek 协议下可用，本轮全部行为同此边界。

## 验收标准

### A 组 · 批次归并

- **AC1**（F1）：一次触发多个连续只读检索调用的请求，历史区**只增加一行**批次块；
  模型输出正文后再次触发检索，历史区出现**第二个**批次块，两块之间隔着那段正文。
- **AC2**（F1）：某次检索调用需要用户确认时，在面板上放行后该调用**仍被归并进
  当前批次**，不产生额外的批次断开。
- **AC3**（F2）：一次同时包含检索与写文件的运行，写文件调用**独立成行并带 diff 块**，
  不出现在批次块内；折叠状态下该行始终可见。
- **AC4**（F2）：执行命令、委派子 Agent、加载 Skill 三类调用同样独立成行。
- **AC5**（F3）：聚合语按动作意图分组计数，各组顺序与实际发生时序一致
  （先搜索后读取时，聚合语里搜索段在前）。
- **AC6**（F4）：批次内只有一次调用时，折叠态显示的是该次调用的标题与结果行，
  **不出现「1 次」「1 个文件」这类措辞**。
- **AC7**（F5）：运行期间批次块显示进行时文案，从属行显示当前调用的主参数值；
  并发多个调用时显示最近开始的那一个。
- **AC8**（F5）：运行期间批次块内**不出现任何耗时数字**。
- **AC9**（F6）：并行发起的检索中有一个失败而模型继续运行时，折叠态的聚合行
  状态点为失败色，且聚合语末尾写出失败个数；展开后能定位到具体是哪一次。
- **AC10**（F7）：成功的调用行不含「完成」二字；失败的调用行仍含「失败」二字。

### B 组 · 三级密度

- **AC11**（F8/F9）：连按三次展开快捷键，界面依次经过折叠、逐条、全文并回到折叠。
- **AC12**（F10）：三个档位下聚合行末尾的提示分别指向「展开 / 看全文 / 收起」，
  与实际按键效果一致。
- **AC13**（F11）：档 3 下某次调用的标题包含其**全部参数且无省略号**；
  同一次调用在档 2 下的标题是截断版。
- **AC14**（F12）：档 3 下结果块显示输出原文；对输出已被工具裁剪过的调用，
  末行如实注明剩余行数与完整原文的取得方式。
- **AC15**（F13）：子 Agent 活动区在档 2 与档 3 下的呈现完全一致。

### C 组 · 状态行

- **AC16**（F14/F15/F17）：一次运行进行中，状态行出现在输入框上方，
  含旋转标记、状态词、耗时、token、中断提示；**耗时每秒变化**，
  **token 在每轮结束时跳变一次**（两者的更新节奏不同，且都符合预期）。
- **AC17**（F14）：运行结束后状态行消失，且**不在历史区留下任何痕迹**。
- **AC18**（F16）：界面符号扫描护栏通过，新增字形已登记进白名单。
- **AC19**（F18）：确认面板弹出期间状态行仍在、耗时继续累计、状态词为等待语义、
  且**不显示中断提示**。
- **AC20**（F19）：并发执行多个工具时，界面上**只有一处**时间数字在变化。
- **AC21**（F20）：`/clear` 与 `/resume` 之后状态行消失、档位回到默认档。

### 全局

- **AC22**（N1）：本轮新增代码中不存在从后台线程直接操作界面的路径；
  既有的死锁护栏与活动区轮询护栏全部通过。
- **AC23**（N2）：参数值或结果原文中含未闭合方括号时，界面正常渲染且程序不退出。
- **AC24**（N4）：一段不触发任何工具调用的对话，界面呈现与改造前逐字一致；
  一段只触发写文件与执行命令的对话同样逐字一致。
- **AC25**（N6）：批次块与状态行出现期间，输入框焦点不变，
  各交互面板的键位行为不变。
- **AC26**（N7）：档位切换与批次的形成/封闭可在行为记录中还原，
  且新增字段出现在阅读器的摘要行里。
- **AC27**：全量测试套件通过。
