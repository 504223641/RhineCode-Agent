### 分发（AC15 / N5）—— 结论与原计划相反

构建 wheel 并检视包内文件清单，**每组都先 `rm -rf build`**：

| 配置 | 包内 `.md` |
| --- | --- |
| 两条模式（`builtin/*.md` + `builtin/*/*.md`） | 5 个，含 `skill-creator/SKILL.md` 与 `reference.md` |
| 仅 `builtin/*.md`（旧写法） | **5 个，同样全进** |
| package-data 整段删掉 | **5 个，同样全进** |
| 整段删掉 + `include-package-data = false` | **一个都没有** |

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| 前三组结果相同，只有关掉 `include-package-data` 才为空 | **真正的开关是 `include-package-data`**——本项目用纯 pyproject.toml 配置，setuptools≥61 在这种配置下它默认为真。原 spec N5 与独立审查都判断「不改 package-data 就打不进包」，**该判断是错的** |
| 第一次实测得到「旧配置也能打进去」但那时未清 `build/` | setuptools 会复用 `build/lib/` 里上一次的产物。**这个陷阱已写进 pyproject 注释**——不清缓存验的是上一次的配置 |
| — | package-data 两条模式**予以保留**，但定位改为「万一有人关掉 `include-package-data` 时的兜底」，注释按实测改写。`CLAUDE.md` 里那条 c11 时期写下的同类说法一并修正 |
