# 首次启动配置向导 Checklist

> 每一项通过**运行代码或观察行为**验证，不靠读代码下结论。
> 括号里是验证方式；`AC*` 指向 `spec.md` 的验收标准。
>
> **分两类**：标 🤖 的可由自动化跑完；标 👁 的必须人眼看真实终端
> （界面观感、粘贴行为、等待态），照本项目一贯的做法留作手测。

## 一、触发与退出

- [ ] 🤖 **删掉用户级配置后启动，出现向导第一屏**（AC1）
      （验证：临时 `HOME` 指向空目录，`stdin` 是 tty 时启动，观察到向导；
      自动化用 `test_setup_entry.py` 断言 `run_setup` 被调用一次）
- [ ] 🤖 **`api_key` 是占位符时同样出现向导**（AC2）
      （验证：写一份 `api_key: YOUR_API_KEY` 的配置，`trigger.classify` 返回
      `PLACEHOLDER`，且入口分支调了 `run_setup`）
- [ ] 🤖 **坏 YAML 时同样出现向导**（AC3）
      （验证：写一份解析不了的配置，`classify` 返回 `INVALID`）
- [ ] 🤖 **配置完好时不出现向导**（AC4）
      （验证：`classify` 返回 `None`，且 `run_setup` **零次调用**）
- [ ] 🤖 **非交互环境下行为与本扩展之前逐字相同**（AC5）
      （验证：`echo "" | python -m rhinecode` 与 `python -m rhinecode < /dev/null`
      的 stdout/stderr 文案与退出码，同改动前的输出逐字比对；
      自动化用 `isatty=False` 断言 `run_setup` **零次调用**）
- [ ] 🤖 **显式 `--config` 指向不存在的文件时按错误处理，不弹向导**（AC6）
      （验证：`python -m rhinecode --config /nope.yaml`，退出码 1、
      输出「配置错误」，且 `run_setup` 零次调用）
- [ ] 👁 **任意一屏按 `Esc` 都写出模板、打印路径、退出码 0**（AC7）
      （验证：真实终端上第 1/2/3/4 屏各按一次 `Esc`，`echo $?` 为 0，
      `~/.rhinecode/` 下四份模板都在）
- [ ] 👁 **第四屏校验失败时可见三个出口，选「跳过验证，直接保存」后进主界面且已写盘**（AC8）
      （验证：故意填错 key 走到第四屏，观察三个出口；选第三个后配置文件已更新）
- [ ] 👁 **向导走完后直接进主界面，进程未退出**（AC9）
      （验证：一路填完，界面变成主对话界面，光标在输入框，可立刻发消息）

## 验收时要记什么

照本项目一贯做法，每条分两栏记：**机器判到了什么**（命令输出、断言、
文件内容）与**据此做的判断**。👁 那几条要写清在什么终端、什么系统上看的。

⚠ **AC28 那条必须在一个真的干净的环境里做**——不能只是把
`~/.rhinecode/config.yaml` 删掉再跑（那时另外三份模板还在，走到的分支不一样）。
整个 `~/.rhinecode/` 目录都要不存在，或用一个临时 `HOME`。
