# 首次启动配置向导 Spec

> **定位：扩展，不占章节号。** 判据只有一条（见 `docs/extensions/README.md`）：
> `CLAUDE.md` 的能力表要不要多一行——不要。它不引入新的能力层级，
> 只是把「已经存在的配置加载」换了个填法。

## 背景

### 现在的首次启动只有一种结局：退出

`rhinecode/__main__.py` 的启动前半段有三条路，**三条都以进程退出告终**：

| 情况 | 现在的行为 | 位置 |
| --- | --- | --- |
| 没有 `config.yaml` | 生成四份模板 → 打印一句话 → `exit(0)` | `__main__.py` 首次运行引导那段 |
| `api_key` 仍是 `YOUR_API_KEY` | 打印一句话 → `exit(1)` | 占位符拦截那段 |
| 配置缺字段 / YAML 坏了 | 打印错误 → `exit(1)` | `load()` 的异常分支 |

于是新用户要做的是：找到那个文件 → 另开编辑器 → 在六十多行注释里翻到那一行 →
替换 → 回终端再敲一次 `rhine`。**而且 key 填错的话，要到发出第一条消息才拿到
401**——那时错误来自 SDK，措辞与「你 key 填错了」相去甚远。

### 开工前核实官方文档，撞出两个已经在生效的错误

**① 模板里的模型名已经停用。** DeepSeek 于 2026-04-24 公告
`deepseek-chat` / `deepseek-reasoner` 两个老别名在 **2026-07-24 停用**；
截至本 spec 落笔（2026-09-02）已过去一个多月，官方定价页不再列出这两个名字。
而它硬写在两处：`config.example.yaml` 与 `rhinecode/config.py` 的
`_CONFIG_TEMPLATE`。

**后果是致命的**：一个新用户装好、填上真 key、照模板跑，第一句话就报模型不存在。

⚠ **这件事本身就是「硬编码模型名」这个做法不可靠的证据，也是本扩展改用
动态拉取的直接依据**：项目自己从年中起所有真机验收（`docs/e2e-sweep/`、
各扩展的 acceptance 记录）用的都是 `deepseek-v4-flash`——**实际在用的和模板里
写的早就分家了，分家了一个多月没人发现**。再写死一次，只是把同一个坑挪个位置。

**② `context_window` 缺省值差 15 倍。** `config.py` 缺省 65536，而 DeepSeek V4
全系是 **1M**（最大输出 384K）。这不报错，但会让 C8 的两层压缩在真实窗口的
**6.5%** 处就开始压历史——白白丢掉上下文，还白花一次摘要的钱。
`docs/e2e-sweep/README.md` 里实测配的正是 `context_window=1000000`。

### 参照系：五个开源 Agent 的首次配置

| 项目 | 形态 | 本次借鉴 |
| --- | --- | --- |
| Claude Code | 全屏分步向导（主题 → 登录 → 安全说明 → 信任目录），跑完直接进对话 | 一屏一问；**跑完不退出** |
| Gemini CLI | 首次问主题 + 认证方式，存 `~/.gemini/settings.json`；`/auth` 可重来 | **判据是「配置里缺哪个字段」而非「是不是第一次」**；留重跑入口 |
| goose | `goose configure` 向导，选 provider → 填 key → **发一次真实请求验证** | **写盘前先验** |
| opencode | `auth login` 交互选 provider，密钥写独立的 `auth.json` | 密钥与配置分家（**本次不做**，属已知项 #1） |
| Codex CLI | 首次进带项目配置的仓库时问信不信任 | 目录信任（**本次不做**，单独立项） |

提炼出五条共性原则，本次做其中四条：**别退出**、**判据是字段缺失**、
**写盘前先验**、**留重跑入口**；第五条「非交互必须能绕过」是硬约束。

## 目标

1. 新用户从安装到能对话，中间**不必离开终端、不必手改 YAML、不必重敲命令**。
2. **把错误提前**——key 错、地址错、模型不可用，在向导里就说清楚。
3. **模型清单不再会过期**——向服务端要，拉不到才退回内置兜底。
4. 顺带**修掉上面那两个已经在生效的错误**。
5. **配置随时可重来**——运行中也能改，不必退出去编辑文件。
6. **非交互场景行为逐字不变**。

## 功能需求

### 一、触发与退出

- **F1 触发条件。** 仅在**缺省流程**（未给 `--config`）且**标准输入是终端**时，
  遇到下列任一情况启动向导：① 用户级配置文件不存在；② `api_key` 仍是占位符；
  ③ 配置加载失败（缺必填字段或 YAML 解析不了）。
  ⚠ 判据是**这三种「配置不可用」的状态**，不是「有没有跑过」——不落任何
  「已完成首次配置」的标记位。有标记位的话，用户手工删掉 key 之后就再也
  引导不出来了（Gemini CLI 的同款判据）。

- **F2 非交互一律退回现行行为。** 标准输入不是终端（CI、管道、重定向），
  或用户显式给了 `--config`，则**逐字保持今天的行为**：生成模板 → 打印 →
  按现有语义退出，退出码不变。
  ⚠ 这条是硬约束不是优化项：破了它 CI 的六格矩阵会全红，且 `rhine` 无法再被
  任何脚本包装。

- **F3 中途放弃。** 任意一屏都能放弃（`Esc`，或首屏的「我自己去改文件」）。
  放弃时写出模板、打印文件路径、退出，退出码 0——**即今天的行为**。
  向导是新增的一条路，不是把老路拆了。

- **F4 校验失败仍可继续。** 第四屏校验不通过时，除「重填 key」「改接口地址」外
  必须提供第三个出口「仍然保存并继续」；选择后按已填内容写盘并进入主界面。
  ⚠ 理由：网络暂时不通、公司代理抽风、服务端临时 5xx 都不该把人锁死在向导里。

- **F5 完成后不退出。** 向导正常走完即写盘并**直接进入主界面**，不打印
  「请重新运行」，不退出进程。**这是本扩展相对现状最大的行为改变。**

### 三、写盘

- **F11 保住注释。** 写盘方式是**在现有配置模板文本上做定点替换**，
  不得用序列化重新生成文件。
  ⚠ 模板里那六十多行注释是本项目重要的文档载体——多数用户只会读它，
  一次 `yaml.dump` 会把它们全部抹掉。

- **F12 向导写入的字段。** `protocol` / `model` / `base_url` / `api_key`，
  外加**按所选模型确定的 `context_window`**。
  ⚠ 显式写出窗口值而不是依赖默认值，是为了让用户**看得见**这个数字，
  将来换模型时知道有这么一项要跟着改。

- **F13 三份可选模板照常生成。** `permissions.yaml` / `mcp.yaml` / `hooks.yaml`
  的生成行为与今天逐字一致（全注释、等价于空、不因它们退出）。

- **F14 密钥不外泄。** `api_key` 除了在它自己那个输入框里回显之外，
  不得出现在任何地方：不打印到标准输出、不进运行日志、不进行为记录。

### 四、重跑入口

- **F15 `/setup` 重跑同一套向导。** 运行中可用 `/setup` 重新走一遍四屏，
  不必退出程序去编辑文件。
  ⚠ **两个入口必须共用同一份界面实现**，不得各写一套——本项目已经在
  「同一件事两处措辞」上踩过五次（Skill 清单表头、角色清单、交付信息、
  消息标记块、待办口径），全部是漏改不报错。

- **F16 `/setup` 预填当前值。** 地址与模型预填当前配置的值；
  **API Key 一栏留空**并提示「留空表示不改」。
  ⚠ 刻意不预填 key：一是没必要把密钥画在屏幕上，二是避免误改。

- **F17 保存后提示重启生效，不做热切换。** `/setup` 写盘后明确告诉用户
  「新配置下次启动生效」。
  ⚠ 这与 `/hooks` / `/agents` 「改了配置要重启」的既有约定一致。热切换要在
  Agent 循环运行期换掉共享的 Provider 实例，属独立评审的改动。

- **F18 `/setup` 放弃时不动任何文件。** 中途 `Esc` 退出面板，配置文件保持原样。

- **F19 改掉已停用的模型名。** 内置配置模板与仓库示例配置里的模型名，

  触发，单次请求更大更贵。

- **F21 同步配置分册文档。** `docs/internals/config.md` 与 `README.md` 里
  涉及这两个值的地方一并更新。
  ⚠ **这是一处已登记的成对维护点**（`config.py` 字段 ↔ `_CONFIG_TEMPLATE` ↔
  `docs/internals/config.md`，护栏 `tests/test_config_timeout.py::TemplateAndDocsTest`），
  向导写盘会让它变成**四处**。

## 非功能需求

- **N1 不引入新的第三方依赖。** 界面用已有的 Textual，网络请求用已有的
  OpenAI 兼容 SDK。
- **N2 纯逻辑与界面分离。** 「有哪几步、每步算不算填好了、怎么写盘、怎么验」
  是纯逻辑，不依赖任何界面框架，可单独测试；界面只负责画和收键。
  这是本项目 `todo/` / `classifier/` 一贯的分法。
- **N3 向导不依赖装配层。** 它跑在装配之前，反向依赖会成环。
- **N4 两次网络请求都要有超时，且可取消。** 卡住时用户按 `Esc` 要能退出，
  不能出现界面静止而无从判断死活的窗口（与 `stream_connect_timeout` 同一条理由）。
- **N5 既有测试与端到端设施不受影响。** e2e 宿主自己构造配置对象、直接调装配层，
  不经命令行入口，因此本扩展对它应当零影响——这一条要有护栏钉住，不能只靠推断。
- **N6 向导任何一步都不得让程序带着「看起来配好了其实没有」的状态继续。**
  要么写下用户确认过的值，要么原样保留旧文件，不存在中间态。

## 不做的事

- **目录信任对话框**（Codex / Claude Code 的「你信任这个项目吗」）。它对本项目
  分量不轻——项目级 `hooks.yaml` 的动作直接执行、不经模型也不经确认面板——
  但它牵动 C12 的加载路径，属安全改动，**单独立项**。
- **老用户迁移提示**（检测到配置里是已停用别名时引导改正）。目前没有老用户；
  本轮实现完成后由作者本人删掉配置重走一遍向导，兼作验收。
- **密钥存进系统钥匙串 / 与配置文件分家**（goose、opencode 的做法）。属已知项 #1。
- **环境变量兜底**（如 `RHINE_API_KEY`）。同属已知项 #1 的范围。
- **主题、编辑器等其它偏好项。** 本项目目前没有这些配置。
- **多 Provider 选择。** 只支持 DeepSeek，选无可选。
- **运行期热切换 Provider。** 见 F17。
- **在向导里编辑 `permissions` / `mcp` / `hooks`。** 它们是可选的、缺省即空，
  首次配置不该被它们撑长。

## 验收标准

### 触发与退出

- **AC1**（F1）删掉用户级配置文件后在终端里启动，出现向导第一屏。
- **AC2**（F1）把 `api_key` 改回占位符后启动，同样出现向导，而不是打印一句话退出。
- **AC3**（F1）把配置文件写成坏 YAML 后启动，同样出现向导。
- **AC4**（F1）配置完好时启动，**不出现**向导，直接进主界面。
- **AC5**（F2）在非终端环境（管道 / 重定向）下启动，输出与退出码与本扩展之前**逐字相同**。
- **AC6**（F2）显式 `--config` 指向一个不存在的文件时，仍按错误处理，不弹向导。
- **AC7**（F3）在任意一屏按 `Esc`，程序写出模板、打印路径、以退出码 0 退出。
- **AC8**（F4）第四屏校验失败时可见三个出口，选「仍然保存并继续」后进入主界面且配置已写盘。
- **AC9**（F5）向导正常走完后**直接进入主界面**，进程未退出，可立即发第一条消息。

### 四屏

- **AC10**（F6）第一屏能看到将要写入的完整文件路径。
- **AC11**（F7）key 为空时无法前进；地址预填为官方默认值。
- **AC12**（F8）第三屏的模型选项来自服务端返回，包含当前官方在售模型。
- **AC13**（F9）把地址改成一个不通的值，第三屏退回兜底清单并**明确标注是兜底**，且提供手动输入入口。
- **AC14**（F10）填入无效 key 时，第四屏给出的是「凭据无效」一类的可读原因，而非原始异常文本。
- **AC15**（F10）成功时列出实际写入的文件清单。

### 写盘

- **AC16**（F11）写盘后打开配置文件，模板里的注释**一行不少**。
- **AC17**（F12）写盘后的文件里 `model` / `base_url` / `api_key` / `context_window` 均为用户所选值。
- **AC18**（F13）首次配置完成后，三份可选模板同时存在且内容全是注释。
- **AC19**（F14）全程开启运行日志与行为记录，事后检索产物中不含明文 key。

### 重跑入口

- **AC20**（F15）运行中执行 `/setup` 出现同一套四屏。
- **AC21**（F16）`/setup` 的地址与模型预填当前值，key 一栏为空并有「留空表示不改」提示。
- **AC22**（F16）`/setup` 中 key 留空并保存后，配置文件里的 key **保持原值不变**。
- **AC23**（F17）`/setup` 保存后能看到「下次启动生效」的提示。
- **AC24**（F18）`/setup` 中途放弃后，配置文件的修改时间与内容均未变化。
