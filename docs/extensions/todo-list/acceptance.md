## 五、真机复核

### 布局几何（机器判到，两轮独立实测）

第一轮是 **T1** 的复刻品（自己搭一个同设定的最小 app），
第二轮是 **T19** 用**产品代码里真实的** `HistoryView` + `TodoPane` + `RhineApp.CSS`。
两轮都做是刻意的：复刻品可能漏抄某个设定，真机上又多了真实消息行与 `#stage` 布局。

| 判据 | 机器判到了什么（T19，80×24，40 条消息） | 判断 |
| --- | --- | --- |
| **钉得住** | 滚到顶与滚到底，待办块 `region.y` **都是 18** | ✅ AC9 |
| **占位** | 块高 4 → 6（+2）时，`max_scroll_y` 23 → 25，实际可见内容 17 → 15（**−2，精确相等**） | ✅ AC11 |
| **不遮挡** | 内容实画 `y 1..15`，待办块 `y 16..21`，**不重叠** | ✅ AC11 |
| **零回归** | 收起后 `HistoryView.region`（`0,0,80,23`）与 `max_scroll_y`（19）**逐字回到基线**，块高 0 | ✅ AC23 / N5 |

⚠ **实测顺带发现一个陷阱**：`scrollable_content_region.height` **恒为 19、
不扣 dock 子节点的高度**。断言「占位」时用它会得出「没占地方」的错误结论
——正确的量是 `max_scroll_y`。已写进 plan 与 CSS 注释。

## ⏳ 待用户复核（必须人眼 / 必须花钱）

机器判不了的六条，**都不是「大概率没问题」，而是「机器根本看不见」**：

1. **框线看起来连不连续** —— 待办块的顶部分隔线与历史区那圈青框接不接得上、
   有没有出现「两个框」的观感。几何对不等于看着对（验收第 8、10、19 条都是
   几何正确而观感错）。
2. **三档颜色分不分得清** —— 橘 / 绿 / 灰在你的终端配色下够不够区分。
   ⚠ 顺便看一眼**待办块的圆点与工具行的圆点会不会混**。
3. **拖选手感** —— 用鼠标拖选待办块里的一行再复制，粘出来对不对。
   机器只验到了「问得出字符偏移」（那是三处失效里的第二处），
   高亮画不画得出来只有眼睛看得到。
4. **确认面板弹出时不打架** —— 待办块显示期间触发一次确认面板。
   预期是面板盖住待办块（已知且可接受），但框线不该乱。
5. **`/help` 与状态行逐字未变** —— 我只对照了整屏导出，你如果留着改造前的截图
   可以逐行比一遍。
6. **真实模型下的触发口径** —— 这是最要紧的一条：给一个**真的需要四五步**的任务，
   看它会不会主动列待办；再给一个**一两步就能做完**的，看它会不会多此一举地列。
   ⚠ 本项目在委派上踩过「欠触发 → 过触发」的来回，而这次的提示词是照那次的
   经验写的（下限写成可数的「三步」），**但没有实测过**。
