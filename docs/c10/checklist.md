# C10 斜杠命令注册与分发 Checklist

> 状态：已批准（2026-07-14，含修订）
> 基线：已批准的 `spec.md`、`plan.md`、`task.md`
> 使用方式：实现完成后逐项执行；只有拿到实际输出或可观察结果后才能勾选

## 1. 验收证据规则

- 自动化项必须记录执行命令、测试数量与退出码。
- 手工项必须记录输入、观察到的文字或界面状态，以及是否符合预期。
- “代码看起来正确”“应该没问题”不算通过证据。
- 一项失败时先保留未勾选状态，修复后重新执行该项及受影响回归。
- `/compact` 的专用摘要调用和 `/resume` 可能触发的上下文压缩，不算“命令误入 Agent Loop”。

## 2. 注册、启动与单一事实来源

- [ ] **C01 单一登记驱动全部入口** — 登记一条非隐藏测试命令后，它无需修改其它清单即可被执行、出现在帮助中并参与补全。（验证：运行注册表、分发器集成测试；期望三个入口都命中同一个定义。）
- [ ] **C02 描述同步传播** — 修改测试命令的描述后，帮助与补全候选同时显示新描述。（验证：只改测试命令的一处注册信息后重新查询两处输出；期望不存在第二份旧文案。）
- [ ] **C03 规范名撞规范名快速失败** — 两条命令使用相同规范名时，启动在界面出现前以非零状态退出，并指出冲突标识和双方命令。（验证：运行启动冲突测试。）
- [ ] **C04 规范名撞别名快速失败** — 一条规范名占用另一条别名时，启动在界面出现前失败并给出双方来源。（验证：运行启动冲突测试。）
- [ ] **C05 别名撞别名快速失败** — 两条命令声明相同别名时，启动在界面出现前失败并给出双方来源。（验证：运行启动冲突测试。）
- [ ] **C06 大小写冲突快速失败** — 仅大小写不同的名称或别名被视为冲突。（验证：用 `/Help` 与 `/help` 构造冲突；期望非零退出。）
- [ ] **C07 冲突注册保持原子性** — 批量注册的后项冲突时，前项不会残留在正式注册表。（验证：捕获冲突后查询前项；期望未注册。）
- [ ] **C08 失败发生在昂贵资源之前** — 命令冲突时 Provider、工具注册中心、MCP 连接、会话锁和 Textual App 均未创建。（验证：用测试替身记录构造调用；期望计数均为零。）

## 3. 解析、分流、别名与参数

- [ ] **C09 空输入无副作用** — 空串和纯空白输入不回显、不报错、不改状态、不写会话且模型调用为零。（验证：用 Fake Controller 提交两类输入并比较全部调用计数。）
- [ ] **C10 命令字段大小写不敏感** — 输入 `/ReSuMe AbC123` 命中 `/resume`，参数仍严格等于 `AbC123`。（验证：运行解析器与分发器测试。）
- [ ] **C11 首空白切分准确** — 空格、Tab 或换行都能分开命令字段；连续分隔空白不进入参数。（验证：运行参数化解析测试。）
- [ ] **C12 正文斜杠仍是对话** — 输入 `请解释 /plan` 只进入普通 AI 对话路径，不触发 Plan Mode。（验证：Fake Controller 记录一次普通消息发送，模式切换计数为零。）
- [ ] **C13 未知命令只在本地失败** — 输入 `/does-not-exist` 显示 `/help` 引导，模型调用、Agent Loop 和会话新增消息均为零。（验证：分发器测试与会话计数对比。）
- [ ] **C14 全部首批别名生效** — `/quit`、`/continue`、`/permissions`、`/allowed-tools`、`/ctx`、`/h`、`/reset`、`/new` 分别执行对应规范命令。（验证：参数化内置命令测试。）
- [ ] **C15 混合大小写别名生效** — 例如 `/QuIt`、`/CtX` 和 `/NeW` 与小写别名行为一致。（验证：参数化别名测试。）
- [ ] **C16 参数保持普通文本** — 参数中的引号、分号、管道符、反斜杠和连续空白不被 Shell 解析或拆词。（验证：提交包含 `"a b"; x|y C:\\tmp` 的测试命令；期望处理函数收到同一字符串且没有外部进程启动。）
- [ ] **C17 无参命令忽略多余参数** — 输入 `/clear now` 仍清空对话并开启新会话存档。（验证：比较执行前后历史与会话 ID。）
- [ ] **C18 可选参数保持兼容** — `/resume 3` 以完整字符串 `3` 恢复；无参 `/resume` 打开选择面板。（验证：Fake MemoryManager 与 Textual 集成测试。）
- [ ] **C19 必需参数缺失显示用法** — 登记一条 `requires_argument=True` 的测试命令后，无参调用显示该命令用法和参数提示，不执行处理函数、不进入 AI。（验证：分发器测试。）
- [ ] **C20 解析结果确定** — 对同一注册内容与同一输入重复解析和分发，规范命令、参数与候选顺序一致。（验证：循环执行同一测试至少三次并比较结构化结果。）

## 4. 三类执行模式与界面边界

- [ ] **C21 本地命令绕过 Agent** — `/help`、`/mcp`、`/context`、`/memory` 不启动 Agent Loop，也不作为用户消息写入模型历史。（验证：Fake Provider/Agent 调用计数与 JSONL 消息数保持不变。）
- [ ] **C22 界面命令绕过 Agent** — `/think`、`/plan`、`/perm`、`/resume`、`/clear`、`/exit` 不作为普通用户消息发送给 Agent。（验证：逐条执行后检查模型调用与会话内容；恢复自身既有压缩例外单独记录。）
- [ ] **C23 手动压缩保持专用路径** — `/compact` 不新增普通用户消息，只调用既有上下文压缩流程并显示结果。（验证：比较历史中的 user 消息，允许专用摘要 Provider 调用。）
- [ ] **C24 提示词命令进入 Agent** — `/init` 在工具可用时启动正常 Agent 路径，工具不可用时只显示原有能力限制提示。（验证：分别使用工具开启和关闭的 Fake Manager。）
- [ ] **C25 控制器可被替身实现** — 代表性命令可通过 Fake Controller 观察显示消息、发送用户消息、模式切换、状态查询、状态刷新、清空、恢复和退出调用，无需启动真实终端或网络。（验证：运行内置命令和分发器测试。）
- [ ] **C26 命令层不依赖渲染框架** — 在不导入 Textual App、不开终端的测试进程中，注册、解析、帮助、补全和命令处理测试全部可运行。（验证：运行六个命令纯逻辑测试模块。）
- [ ] **C27 耗时压缩不阻塞界面** — 给摘要流程加入人为延迟时执行 `/compact`，界面事件循环与重绘保持响应，完成后显示结果；本项不要求 Esc 中断专用摘要调用。（验证：Textual `run_test()` / Pilot 集成测试。）
- [ ] **C28 耗时恢复不阻塞界面** — 给恢复后的压缩流程加入人为延迟时执行 `/resume`，界面仍响应且工作在后台完成。（验证：Textual Worker 集成测试。）
- [ ] **C29 命令失败可恢复** — 测试命令主动抛错后显示本地错误、不显示堆栈、不发送 AI，随后普通输入仍可正常提交。（验证：分发器错误测试后紧接一次普通消息。）
- [ ] **C30 本地查询不触发外部 I/O** — 解析、别名、帮助和补全在把磁盘、网络和模型入口替换为“调用即失败”的替身后仍成功。（验证：纯逻辑测试；期望外部入口调用为零。）

## 8. 现有 11 条规范命令兼容性

| 编号 | 检查项 | 验证方式与预期 |
|---|---|---|
| C60 | [ ] `/think` | 在支持的 Provider 中按 off → high → max → off 循环；不支持时显示原能力限制提示。 |
| C61 | [ ] `/plan` | 工具模式下切换 Plan Mode 并刷新状态；不支持时保持关闭并显示原提示。 |
| C62 | [ ] `/perm` | 默认 → 严格 → 放行 → 默认循环不变，既有权限规则与确认流程不变。 |
| C63 | [ ] `/mcp` | 显示 Server、传输、工具数与失败原因；未配置时显示原提示且不改状态。 |
| C64 | [ ] `/context` | 显示估算用量、窗口、余量、存盘数和熔断状态；不支持时显示原提示。 |
| C65 | [ ] `/compact` | 不新增用户消息；有可压缩早段时摘要，无早段时显示原“无可摘要”结果。 |
| C66 | [ ] `/resume` | 无参打开可跳过锁定/当前项的面板；编号或 ID 直达恢复；失败不清屏。 |
| C67 | [ ] `/memory` | RHINE.md、笔记、会话和锁状态报告字段保持完整。 |
| C68 | [ ] `/init` | 仅工具模式生效；写盘仍走原权限管线；已有 RHINE.md 时不覆盖、只给建议。 |
| C69 | [ ] `/clear` | 清空历史，复位上下文状态并开启新会话档，旧档保留。 |
| C70 | [ ] `/exit` | 正常退出应用，并执行现有会话锁与 MCP 资源清理。 |

**兼容验证：** 对 C60–C70 运行对应自动化回归；需要真实 Provider/MCP 的部分用现有测试替身验证控制流，再进行一次本地手测。

## 9. 安全、回归与范围边界

- [ ] **C71 权限确认链未削弱** — 命令触发的工具调用仍经过危险黑名单、路径沙箱、规则、模式和人工确认。（验证：运行全部 permission 与 loop 测试。）
- [ ] **C72 Plan 审批链未削弱** — 计划展示、拒绝停止、批准后逐项确认行为保持不变。（验证：运行现有 Plan Mode 回归。）
- [ ] **C73 取消与交互优先级未削弱** — 流式运行中 Esc 取消有效；确认、澄清、审批和会话面板显示时由当前面板优先处理。（验证：TUI 键盘与 Review 回归。）
- [ ] **C74 上下文与记忆机制未削弱** — 自动/手动压缩、工具结果存盘、RHINE.md 注入、自动笔记、会话锁和历史恢复测试全部通过。（验证：运行 context、memory、resume 测试组。）
- [ ] **C75 普通对话和流式输出未回归** — 普通文本只回显一次，流式正文、思考、工具行和完成状态照常渲染。（验证：现有 Agent/TUI 回归与端到端场景。）
- [ ] **C76 恢复不会偷偷恢复模式** — 恢复旧会话不会根据历史正文中提及的 `/plan`、`/perm` 或 `/think` 改变当前临时模式。（验证：恢复前记录三种当前模式，载入包含这些文字的会话后逐项比较。）
- [ ] **C77 无新增命令权限模型** — 别名复用规范命令原有权限与 Provider 限制，没有单独放宽路径沙箱或工具权限。（验证：同一操作分别经规范名和别名执行，权限决策一致。）
