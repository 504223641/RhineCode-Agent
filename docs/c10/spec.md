# C10 斜杠命令注册与分发 Spec

> 状态：已批准（2026-07-14，含修订）

## 背景

RhineCode 已有 `/think`、`/plan`、`/perm`、`/mcp`、`/context`、`/compact`、`/resume`、`/memory`、`/init`、`/clear`、`/exit` 共 11 条斜杠命令，但命令执行、补全展示和状态栏刷新分别维护，新增或修改命令时容易遗漏关联位置。

当前命令识别还存在以下问题：

- 命令名区分大小写，不支持别名。
- 未知斜杠输入可能被当成普通对话发送给 AI，浪费 Token 且行为不确定。
- 补全元数据与执行逻辑不是同一来源。
- 缺少统一的 `/help` 入口和明确的参数提示。
- 不具备启动阶段的名称、别名冲突检测。
- 输入框不能区分完整命令名与普通文字。
- 提示词型命令在即时显示和会话恢复时可能呈现不一致。
- 模式状态仍以普通文字展示，缺少醒目的 `[DEFAULT]`、`[PLAN]` 标记。

## 目标

- 建立单一、权威的命令注册来源，统一管理命令名称、别名、描述、用法、执行类型、参数提示、隐藏状态和处理行为。
- 在用户输入入口优先识别斜杠命令，使本地操作和界面状态操作绕过 Agent，获得快速、确定且尽量不消耗模型 Token 的响应。
- 将命令划分为本地操作、界面状态操作和提示词操作三类，并通过与渲染框架无关的界面控制能力执行。
- 保留现有 11 条命令的名称和行为，在兼容基础上增加 `/help`、Claude Code 风格别名、大小写不敏感解析及 Tab 补全。
- 未知命令不得进入 AI 对话，必须给出 `/help` 引导。
- 提示词型命令在界面和恢复回放中显示原始命令，AI 内部获得展开后的完整预设提示词。
- 输入完整命令后，仅高亮命令名；参数继续使用普通文本样式。
- 状态栏保留现有信息，以不同字体颜色展示 `[DEFAULT]` 和 `[PLAN]`。

## 功能需求

### 注册与启动校验

- **F1**：系统必须提供唯一的命令注册来源。每条命令登记规范名称、别名、简短描述、用法示例、命令类型、可选参数提示、隐藏标记和处理行为。
- **F2**：所有内置命令必须在接受用户输入前完成注册。规范名称和别名按大小写不敏感规则检查；任何名称与名称、名称与别名、别名与别名的冲突都必须导致启动失败，并显示冲突标识及涉及的命令。
- **F3**：命令执行、帮助列表和补全候选必须来自同一份注册信息，不再分别维护命令清单。

### 解析与分流

- **F4**：输入去除首尾空白后为空时直接返回，不显示错误、不改变状态、不调用 AI。
- **F5**：只有去除首尾空白后以 `/` 开头的输入才进入命令解析。命令名为第一个空白字符前的内容；命令名与参数之间连续的分隔空白不属于参数。
- **F6**：命令名和别名按小写匹配；参数去除首尾空白后，内部内容与大小写保持不变。例如 `/ReSuMe AbC123` 应命中 `/resume`，参数仍为 `AbC123`。
- **F7**：普通文本中的斜杠不触发命令。例如 `请解释 /plan 的作用` 仍作为普通对话发送给 AI。
- **F8**：未知命令不得发送给 AI，必须显示类似“未知命令 `/foo`，输入 `/help` 查看可用命令”的本地提示。
- **F9**：用户提交输入时先经过分流器；命令由命令系统处理，非命令才进入普通 AI 对话流程。

### 别名

- **F10**：首批提供以下别名，别名与规范命令共用完全相同的处理行为：

| 别名 | 规范命令 | 示例结果 |
|---|---|---|
| `/quit` | `/exit` | 输入 `/quit` 退出 RhineCode |
| `/continue` | `/resume` | 输入 `/continue 3` 恢复第 3 个会话 |
| `/permissions` | `/perm` | 输入后循环切换权限模式 |
| `/allowed-tools` | `/perm` | 与 `/perm` 行为一致，不新增权限管理界面 |
| `/ctx` | `/context` | 查看上下文用量 |
| `/h` | `/help` | 显示命令帮助 |
| `/reset` | `/clear` | 清空对话并开启新会话存档 |
| `/new` | `/clear` | 与 `/clear` 行为一致 |

### 参数行为

- **F11**：命令处理行为接收命令名之后的完整参数字符串，不进行类似 Shell 的引号、转义或多参数拆分。
- **F12**：不需要参数的命令忽略额外参数并照常执行。例如 `/clear now` 仍执行 `/clear`。
- **F13**：支持参数的命令按现有行为处理参数。例如 `/resume 3` 以 `3` 作为会话编号；`/resume` 无参数时打开会话选择面板。
- **F14**：需要参数但未提供时，命令必须显示自身用法和参数提示，不得进入 AI 对话。

### 执行类型与界面边界

- **F15**：命令按执行模式分为三类：

| 类型 | 本阶段命令 | 行为 |
|---|---|---|
| 本地直执行 | `/help`、`/mcp`、`/context`、`/compact`、`/memory` | 直接执行固定逻辑，不进入 Agent Loop |
| 界面状态 | `/think`、`/plan`、`/perm`、`/resume`、`/clear`、`/exit` | 改变会话或界面状态，并按需刷新显示 |
| 提示词 | `/init` | 展开预设提示词后作为用户请求交给 AI |

“本地直执行”表示绕过 Agent Loop，不代表绝对不访问模型；例如 `/compact` 仍保留现有的专用摘要调用。

- **F16**：命令处理行为不得依赖具体渲染框架，只能通过统一的界面控制能力完成显示消息、发送用户消息、切换模式、查询 Token 状态和刷新状态栏。
- **F17**：本地直执行与界面状态命令不得作为普通用户消息发送给 Agent。
- **F18**：执行时间较长的既有命令必须继续在后台运行，不能阻塞界面。例如 `/compact` 和可能触发上下文压缩的 `/resume`。

### 帮助、补全与高亮

- **F19**：新增 `/help`，按稳定顺序列出所有非隐藏命令，并展示规范名称、别名、简短描述、用法、类型及参数提示。
- **F20**：隐藏命令仍可被直接调用，但不出现在 `/help`、自动补全或候选菜单中。
- **F21**：命令补全同时匹配规范名称和别名，匹配过程大小写不敏感。选择别名后仍执行对应规范命令。
- **F22**：按 Tab 时只有一个匹配项则直接补全命令字段；存在多个匹配项时显示稳定排序的候选菜单。
- **F23**：候选菜单已经显示时，按回车执行当前高亮项，即使用户只输入了命令前缀。例如输入 `/co` 后回车，执行当前高亮的匹配命令。
- **F24**：输入框只在命令字段已经完整匹配规范名称或别名时高亮该字段。参数保持普通文字样式，未完整匹配的前缀保持普通样式。例如 `/resume 3` 只高亮 `/resume`，`/res` 不高亮。

### 提示词命令与会话恢复

- **F25**：提示词型命令必须区分“用户原始命令”和“发送给 AI 的展开提示词”。
- **F26**：即时界面和会话恢复回放均显示用户原始命令。例如始终显示 `/init`，不展示内部的长提示词。
- **F27**：模型历史和会话存档必须保留展开后的完整提示词，使后续对话、上下文压缩和会话恢复仍具有完整语义；同时保留足够的原始命令信息用于界面回放。
- **F28**：本阶段只有内置、静态的预设提示词，不支持用户定义或运行时动态生成提示词。

### 状态栏模式标记

- **F29**：状态栏保留 Provider、模型、思考模式、权限模式、MCP 和上下文等现有信息，用 `[DEFAULT]` 或 `[PLAN]` 替换原有“计划模式：开/关”文字。
- **F30**：`[DEFAULT]` 使用中性、低强调字体色；`[PLAN]` 使用醒目的蓝青色。两种模式在深色和浅色终端主题下都必须能够明显区分。
- **F31**：执行 `/plan` 或其他会改变计划模式的既有流程后，状态栏必须立即刷新正确的模式文字与颜色。

### 兼容现有行为

- **F32**：现有 11 条命令的用户可见行为必须保持兼容，包括 Provider 能力限制、模式循环顺序、会话选择与恢复、上下文压缩、清理状态和退出行为。
- **F33**：命令注册重构不得削弱现有权限、上下文、记忆、会话锁、后台 Worker 或取消机制。

## 非功能需求

- **N1（响应速度）**：命令识别、别名解析、帮助生成和补全匹配必须完全在本地内存中完成，不得进行磁盘、网络或模型调用，并应在一次界面事件处理中完成响应。
- **N2（Token 节省）**：本地直执行和界面状态命令不得启动 Agent Loop 或产生普通对话请求。`/compact` 的专用摘要调用及 `/resume` 恢复时可能触发的既有上下文压缩属于明确例外。
- **N3（确定性）**：在命令注册内容和用户输入相同的情况下，解析结果、别名归一化、候选顺序和执行路径必须一致，不得依赖模型判断。
- **N4（快速失败）**：命令名称或别名发生冲突时，程序必须在界面开始接受输入前终止，返回非成功退出状态，并提供可定位冲突来源的错误信息。
- **N5（错误隔离）**：已识别命令执行失败时不得回退为普通 AI 对话。可恢复错误应显示本地错误信息并允许继续使用；明确的退出命令除外。
- **N6（界面线程安全）**：耗时操作不得阻塞输入与渲染；所有界面更新必须通过统一界面边界回到安全的界面执行上下文。
- **N7（可维护性）**：新增普通内置命令时，只需登记一份完整命令定义并提供处理行为，不应再同步修改补全列表、帮助列表或状态栏命令白名单。
- **N8（可测试性）**：注册、冲突检测、解析、别名、分流和补全逻辑必须能够脱离真实界面与真实模型独立验证；界面控制能力可以由测试替身代替。
- **N9（可访问性）**：模式不能只依靠颜色表达，必须同时保留 `[DEFAULT]` 与 `[PLAN]` 文字；两种颜色需要在常见深色和浅色终端主题下保持可辨认。
- **N10（安全兼容）**：命令参数不得被隐式解释为 Shell 命令；别名不得改变规范命令原有的权限、路径沙箱、会话锁或 Provider 能力限制。
- **N11（回归控制）**：重构后现有普通对话、流式输出、取消、确认、澄清、计划审批、会话恢复和历史回放流程必须继续工作。
- **N12（演进边界）**：本阶段的注册和分发能力应允许后续 Skill 系统接入新命令来源，但不得提前引入插件订阅、事件总线或命令级权限模型。

## 不做的事

- 不支持用户通过文件或配置创建自定义命令。
- 不扫描、加载或热更新 Skill、插件、MCP Prompt 等外部命令来源。
- 不实现运行时动态生成提示词、变量替换或模板脚本；仅支持代码内置的静态预设提示词。
- 不增加命令级权限规则。命令触发的既有工具调用仍走现有权限系统。
- 不引入事件总线、发布订阅机制或插件监听接口。
- 不增加 Claude Code 的完整命令集合，例如 `/model`、`/config`、`/doctor`、`/export`。
- 不增加 `!` Shell 快捷模式、`@` 文件引用、反向历史搜索或 Shift+Tab 模式切换。
- 不删除、重命名或重新定义现有 11 条命令的核心行为。
- 不扩展 Provider 的工具调用能力，也不改变各命令现有的 Provider 支持范围。
- 不实现用户自定义状态栏主题或颜色配置；本阶段只提供固定且可辨认的 `[DEFAULT]`、`[PLAN]` 样式。
- 不新增通用命令操作日志。除提示词型命令需要保存原始命令以便恢复回放外，本地直执行和界面状态命令不作为对话消息写入模型历史。
- 不恢复命令执行时的临时模式状态。例如恢复旧会话时，不因历史中曾执行 `/plan` 而自动进入 Plan Mode。
- 不重新设计会话、上下文、记忆、权限或 MCP 子系统；只完成命令系统接入所需的最小适配。

## 验收标准

- **AC1（F1、F3）**：登记一条测试命令后，它无需在其他位置重复登记，即可被执行、出现在 `/help` 中并参与补全；修改其描述后，帮助与补全同时显示新描述。
- **AC2（F2）**：分别构造“规范名称撞名”“规范名称撞别名”“别名撞别名”“仅大小写不同”四种冲突，程序均在接受输入前退出，并指出冲突标识与涉及的命令。
- **AC3（F4–F6）**：空输入无任何副作用；输入 `/ReSuMe AbC123` 能命中 `/resume`，并把 `AbC123` 原样作为参数。
- **AC4（F7–F9）**：输入 `请解释 /plan` 会进入普通 AI 对话；输入 `/does-not-exist` 只显示 `/help` 引导，模型调用次数保持不变。
- **AC5（F10）**：`/quit`、`/continue`、`/permissions`、`/allowed-tools`、`/ctx`、`/h`、`/reset`、`/new` 均执行对应规范命令；混合大小写的别名也能命中。
- **AC6（F11–F14）**：`/resume 3` 收到完整参数 `3`；`/clear now` 忽略 `now` 并执行清理；登记一条需要参数的测试命令后，无参数调用会显示用法且不进入 AI 对话。
- **AC7（F15、F17）**：通过模型调用计数观察，本地直执行和界面状态命令不启动 Agent Loop；`/init` 会把预设提示词交给 Agent。
- **AC8（F16）**：使用测试界面控制器执行代表性命令，可以观察到显示消息、发送用户消息、切换模式、查询 Token 和刷新状态等调用；命令测试不需要启动真实终端界面。
- **AC9（F18）**：使用人为延迟的摘要或恢复流程执行 `/compact`、`/resume` 时，输入和渲染保持响应，耗时工作在后台完成。
- **AC10（F19、F20）**：`/help` 按稳定顺序显示所有非隐藏命令的名称、别名、描述、用法、类型和参数提示；隐藏测试命令不出现在帮助或补全中，但直接输入完整名称仍可执行。
- **AC11（F21–F23）**：输入 `/compa` 后按 Tab 直接补全为 `/compact`；输入 `/cont` 后按 Tab 显示包含 `/context` 与 `/continue` 的稳定排序候选，选择 `/continue` 后执行 `/resume` 行为；候选菜单可见时按回车执行当前高亮项。
- **AC12（F24）**：输入 `/resume 3` 时只有 `/resume` 使用命令强调色；`3` 保持普通颜色；输入未完成的 `/res` 时不高亮；完整别名 `/continue` 同样高亮。
- **AC13（F25–F28）**：执行 `/init` 后，即时界面显示 `/init`，模型收到完整内置提示词；恢复该会话后仍显示 `/init`，模型历史与上下文压缩输入仍包含展开后的完整语义。
- **AC14（F29、F30）**：普通模式状态栏显示中性颜色的 `[DEFAULT]`，不再显示“计划模式：关”；Provider、模型、权限、MCP 和上下文等其他字段仍然存在。
- **AC15（F31）**：执行 `/plan` 后状态栏立即变为蓝青强调色的 `[PLAN]`；再次执行后立即恢复 `[DEFAULT]`。两种模式即使忽略颜色，也能通过文字区分。
- **AC16（F32）**：逐一执行现有 11 条规范命令，其模式循环、能力限制、报告内容、压缩、恢复、清理、提示词和退出行为与重构前一致。
- **AC17（F33）**：现有权限确认、计划审批、取消、上下文压缩、会话锁、历史恢复和自动笔记相关测试全部通过。
- **AC18（N1–N3）**：帮助、解析、别名和补全使用测试模型运行时，模型调用次数为零；相同注册内容和输入重复执行，得到相同解析结果与候选顺序。
- **AC19（N5）**：让一个测试命令主动失败后，界面显示本地错误且仍可继续输入；失败命令不会被重新发送给 AI。
- **AC20（N6–N8）**：注册、冲突检测、解析、分流和补全均有不依赖真实界面或网络的自动化测试；耗时命令的界面线程安全行为有集成测试覆盖。
- **AC21（N9）**：分别在深色与浅色终端主题下检查状态栏，`[DEFAULT]` 与 `[PLAN]` 的文字和颜色均可辨认，方括号不会被误解析为样式标签。
- **AC22（N10）**：命令参数中的引号、分号、管道符和反斜杠均作为普通参数文本传递，不会被命令系统当作 Shell 语法执行。
- **AC23（N11）**：完整自动化测试通过，并手工走通“普通对话 → 本地命令 → 模式切换 → 提示词命令 → 会话恢复”的端到端流程。
