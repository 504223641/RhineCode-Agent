# C7 MCP 客户端 Spec

## 背景

RhineCode 目前的工具能力由内置的 6 个核心工具（读文件、写文件、编辑、执行命令、glob、grep）提供，全部在代码库里硬编码注册。工具集是封闭的：想扩展能力必须改 RhineCode 源码、继承 `Tool`、在 `ToolRegistry.default()` 里加一行。

[MCP（Model Context Protocol）](https://modelcontextprotocol.io) 是一套开放协议，让外部程序（MCP Server）以标准化方式对外暴露工具、资源等能力。业界已有大量现成的 MCP Server（文件系统、数据库、搜索、第三方 API 等）。如果 RhineCode 能作为 MCP 客户端接入这些 Server，用户就能不改 RhineCode 源码、仅通过配置声明，把任意 MCP Server 的工具接进来给 Agent 使用。

本章（C7）实现一个 **MCP 客户端**：启动时按配置连接外部 MCP Server，发现其提供的工具，包装成 RhineCode 已有的 `Tool` 接口注册进工具中心。对 Agent Loop 而言，MCP 工具与内置工具完全无差别——同样走权限系统、同样在流式循环里被调用与回灌。

## 目标

- 让用户仅通过配置文件声明外部 MCP Server 列表，即可把其工具接入 RhineCode，无需改动源码。
- 支持两种主流传输方式：本地子进程（stdio）与远程服务（Streamable HTTP）。
- 发现到的远端工具对 Agent、权限系统、TUI 完全无感——复用现有 `Tool` / `ToolRegistry` / 权限管线，不为 MCP 开特例通道。
- 单个 Server 连接或发现失败不影响其它 Server，也不影响 RhineCode 正常启动与内置工具。
- 让用户能在运行时从界面看到 MCP 的连接状态。

## 功能需求

### 配置

- **F1**：从两层 YAML 配置文件读取 MCP Server 列表——用户级（跨项目全局默认）与项目级（随仓库走）。两层按 Server 名字（map 的 key）合并，同名 Server 项目级覆盖用户级（后者盖前者）。
- **F2**：每个 Server 以其名字为 key 声明。支持两种类型：
  - **stdio 型**：声明启动子进程所需的 `command`（可执行文件）、`args`（参数列表）、`env`（环境变量 map）。
  - **HTTP 型**：声明 `url`（Server 地址）与 `headers`（请求头 map）。
  - 类型由字段自动判定：含 `command` 视为 stdio，含 `url` 视为 HTTP。
- **F3**：`env` 与 `headers` 的值支持 `${VAR}` 形式的环境变量展开，从进程环境读取。引用的环境变量不存在时展开为空字符串，不因此崩溃。
- **F4**：配置容错（fail-safe）——配置文件缺失视为「无 Server」正常启动；YAML 解析失败或单个 Server 条目结构非法时，跳过该问题项并收集可读错误，绝不因配置坏掉而崩溃或阻断启动。

### 连接与协议

- **F5**：对每个已声明的 Server 建立连接——stdio 型拉起子进程并通过其标准输入/输出管道通信；HTTP 型通过 Streamable HTTP 与远端通信。
- **F6**：按 JSON-RPC 2.0 收发消息。请求携带唯一 id，响应按 id 与发出的请求配对；一次工具执行从发出请求到拿到对应响应表现为一次阻塞调用（对上层 `Tool.execute` 屏蔽底层异步收发细节）。
- **F7**：每个 Server 的会话按三步进行——① 初始化握手（`initialize`，交换协议版本与能力）；② 列出工具（`tools/list`，拿到工具名、描述、输入参数 schema）；③ 调用工具（`tools/call`，传工具名与参数、拿回结果）。
- **F8**：把工具调用结果（MCP 的结果结构，含文本内容块与错误标志）转换为 RhineCode 的统一工具结果——文本内容拼接为回灌模型的正文；非文本内容（如图片）以占位说明代替；结果标记为错误时按失败处理。

### 工具注册与接入

- **F9**：把每个 Server 发现到的工具包装成 RhineCode 的 `Tool` 接口注册进工具中心。注册名采用 `mcp__<server>__<tool>` 前缀命名，从而与其它 Server 的工具、与内置工具天然隔离，不会重名冲突。
- **F10**：包装后的工具向模型暴露其原始描述与输入参数 schema；被调用时把参数透传给对应 Server 的 `tools/call`，把结果按 F8 转换后回灌。
- **F11**：MCP 工具一律视为**非只读**（`read_only=False`）——默认权限模式下每次调用都要经过人在回路确认；用户可通过权限规则（如 `allow: mcp__server__*`）自行免确认。MCP 工具与内置工具走同一套五层权限管线，未在权限适配层特殊映射时按 `other` 分支处理（按工具名匹配规则 + 权限模式兜底）。

### 生命周期与隔离

- **F12**：多个 Server 的连接做缓存与统一生命周期管理——连接在启动发现阶段建立并持有，供后续多次 `tools/call` 复用；程序退出时统一关闭所有连接、回收子进程。
- **F13**：单个 Server 在连接、初始化、列出工具任一步失败时，只跳过该 Server（记录失败原因），不影响其它 Server 的接入，也不影响内置工具与 RhineCode 启动。

### 发现时机与可观测

- **F14**：Server 发现与工具注册在 RhineCode 启动阶段自动完成，Agent 首次使用工具时 MCP 工具已就绪，用户无需手动触发。
- **F15**：底部状态栏展示 MCP 连接状态（如「MCP 服务已连接」及已连接的 Server 数量 / 注册的工具总数），让用户在界面上直接看到 MCP 是否接入成功。
- **F16**：提供 `/mcp` 斜杠命令，运行时列出每个已声明 Server 的连接状态、传输类型、注册的工具数量与失败原因（启动阶段的连接/发现错误也在此可见）。命令需成对维护（`conversation.py` 逻辑 + `CommandPanel.COMMANDS` 补全列表）。

## 非功能需求

- **N1**：对 Agent Loop 与权限系统零侵入——MCP 工具通过既有 `Tool` 抽象接入，`loop.py`/`engine.py` 的核心决策与执行流程不为 MCP 增加分支特例。
- **N2**：健壮性——任何 Server 的 I/O 异常、协议错误、超时都被捕获并转成对模型可读的失败结果或跳过该 Server，绝不向上抛出使 Agent Loop 或 TUI 崩溃。
- **N3**：MCP 工具调用带超时上限，避免某个 Server 无响应时无限期挂起阻塞 Agent Loop。
- **N4**：教学可读——新增代码遵循项目中文注释规范，关键流程（异步收发配对、传输差异、生命周期）注释清楚设计意图与边界。
- **N5**：可扩展——传输方式（stdio / HTTP）以统一抽象封装，未来新增传输方式时上层发现/注册逻辑无需改动。

## 不做的事

- 不实现 MCP 的**资源（resources）、提示词（prompts）、采样（sampling）** 等非工具能力，本章只接工具。
- 不做 Server **健康检查与自动重连**——连接在启动时建立，中途断开不自动恢复（后续章节再议）。
- 不做 MCP 工具的**细粒度权限映射**（不在 `permission/adapter.py` 的 `_TOOL_MAP` 为 MCP 工具加专门映射），统一走 `other` 分支即可。
- 不做 stdio 之外的**旧版 HTTP+SSE 传输**，远程仅支持 Streamable HTTP。
- 不做 MCP 工具结果里图片/二进制内容的实际渲染，只以占位文本代替。
- 不改变「工具仅在 `deepseek` 协议 + 启用默认工具注册中心时生效」这一现状，MCP 工具随内置工具一同仅在该模式下暴露。

## 验收标准

- **AC1（配置合并）**：用户级与项目级 `mcp.yaml` 各声明若干 Server，加载后得到合并列表；同名 Server 以项目级为准。对应 F1。
- **AC2（两种类型解析）**：一份配置同时含 stdio 型（有 `command`）与 HTTP 型（有 `url`）Server，加载后各自被识别为正确的传输类型。对应 F2。
- **AC3（环境变量展开）**：`env`/`headers` 值写 `${VAR}`，设置了该环境变量时展开为其值，未设置时展开为空字符串且不崩溃。对应 F3。
- **AC4（配置容错）**：配置文件缺失时正常启动且无 MCP 工具；某个 Server 条目结构非法时该项被跳过并有可读错误，其余 Server 正常。对应 F4/F13。
- **AC5（三步会话）**：连接一个真实/模拟 stdio Server，可完成 `initialize` → `tools/list` → `tools/call` 全流程，`tools/list` 返回的工具出现在注册中心。对应 F5/F6/F7。
- **AC6（JSON-RPC 配对）**：连续发出多个带不同 id 的请求，每个响应按 id 正确配对回对应调用，不串包。对应 F6。
- **AC7（工具接入无感）**：发现到的工具以 `mcp__<server>__<tool>` 命名出现在 `ToolRegistry.schemas()` 中，Agent 可像调用内置工具一样调用它并拿到回灌结果。对应 F9/F10。
- **AC8（结果转换）**：`tools/call` 返回文本内容时被拼接为工具结果正文；返回错误标志时结果为失败。对应 F8。
- **AC9（权限接入）**：MCP 工具被识别为非只读，默认权限模式下调用触发人在回路确认；配置 `allow: mcp__<server>__*` 后免确认。对应 F11。
- **AC10（单 Server 隔离）**：配置一个必然连接失败的 Server 与一个正常 Server，启动后正常 Server 的工具可用，失败 Server 被跳过且记录原因，RhineCode 正常运行。对应 F13。
- **AC11（生命周期）**：程序退出时所有 MCP 连接被关闭、stdio 子进程被回收，无残留进程。对应 F12。
- **AC12（状态栏）**：启动接入若干 MCP 工具后，底部状态栏显示「MCP 服务已连接」及 Server 数 / 工具数。对应 F15。
- **AC13（/mcp 命令）**：运行时输入 `/mcp`，列出各 Server 的连接状态、传输类型、工具数与失败原因；且 `/mcp` 出现在输入 `/` 的补全面板中。对应 F16。
