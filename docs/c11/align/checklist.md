# C11 对齐 Agent Skills 开放标准 Checklist

> 每一项通过**运行代码或观察行为**验证，聚焦系统做什么，不检查代码写法——
> 重构文件、改名函数但行为不变时，本清单应依然适用。
>
> 标记 **【自动】** 的可由单元测试覆盖；**【驱动】** 的用 P1a 端到端驱动设施跑；
> **【手测】** 的需人眼观察。

---

## 一、定义格式与发现

- [ ] **一份只有正文、没有 frontmatter 的 Markdown 文件能作为 Skill 加载**，命令名等于文件名，
      说明取自正文第一个非空段落（验证：造 `notes.md` 只写两段正文，看 `/skills` 列表；AC1）【自动 + 驱动】
- [ ] **命令名来自路径而非 frontmatter**：`foo/SKILL.md` 内写 `name: bar` 时，
      短命令是 `/foo`、列表显示名是 `bar`（验证：造该样本后看 `/skills` 与 Tab 补全；AC2）【自动 + 驱动】
- [ ] **连字符与下划线两种键名写法结果一致**（验证：造两份只有键名写法不同的样本，
      断言解析结果逐字段相等；AC3）【自动】
- [ ] **同一逻辑键的两种写法同时出现时以标准写法为准**，并给出一条提示（验证：单测；AC3）【自动】
- [ ] **命令名含路径分隔符或为保留子命令词时加载失败**并给出可读原因（验证：单测；AC5）【自动】
- [ ] **含大写字母、空格或超过 32 字符的 `name` 不再导致加载失败**——它只是显示标签
      （验证：造 `name: My Very Long Display Name` 的样本，断言加载成功；AC5）【自动】
- [ ] **三层同名按项目级 > 用户级 > 内置整份覆盖**，判定依据是命令名
      （验证：三层各放一个同目录名的 Skill，看 `/skills` 标注的来源层级；AC2 相关）【自动】
- [ ] **同目录下不再有「层内重名」这一失败原因**（验证：旧用例删除后其余全绿）【自动】

## 二、清单与两阶段加载

- [ ] **清单条目同时包含 `description` 与 `when_to_use` 的内容**（验证：`/skills prompt`
      观察第一阶段清单段；AC6）【自动 + 驱动】
- [ ] **清单仍不含任何 SOP 正文**，且仍注入稳定可缓存通道（验证：`/skills prompt` 对照，
      并断言清单长度远小于任一正文）【自动】
- [ ] **清单超上限时截断并标注省略条数**（验证：造超量样本后看 `/skills prompt`）【自动】

## 三、执行模式与可调用性

- [ ] **`context: fork` 的 Skill 执行后主历史恰好新增两条配对消息**，
      子对话的工具调用不在主历史中（验证：跑一次后读会话存档 JSONL 行数与角色；AC7）【自动 + 驱动】
- [ ] **不写 `context` 的 Skill 留在主对话执行**，全过程出现在主历史中（验证：同上对照）【自动 + 驱动】
- [ ] **缺省情况下模型可自行发起 `context: fork` 的 Skill**，子对话完整执行，
      其结论作为该次发起动作的工具结果回灌（验证：让模型自行加载一个 fork Skill，
      观察工具结果是结论文本而非一句确认；AC14）【自动 + 驱动】
- [ ] **`disable-model-invocation: true` 的 Skill，模型自行发起时被拒绝**并得到用户可用的入口；
      同一个 Skill 用户敲斜杠命令仍照常执行（验证：两条路径各跑一次；AC15）【自动 + 驱动】
- [ ] **`user-invocable: false` 的 Skill 不出现在斜杠命令菜单与补全候选中，
      但模型仍可自行发起**，且它仍出现在 `/skills` 列表里（验证：Tab 补全观察 + 模型发起；AC16）【自动 + 驱动】
- [ ] **子对话中加载工具不可见**；强行构造一次调用时被拒绝且子对话继续
      （验证：单测构造该调用，断言工具结果是拒绝原因且循环未终止）【自动】
- [ ] **`background: true`、`agent`、`effort`、`hooks`、`paths`、`shell` 各触发一条可读警告**，
      且 Skill 仍正常加载与执行（验证：造一份六个字段齐全的样本，看 `/skills` 的提示段；AC8）【自动 + 驱动】

## 四、工具权限

- [ ] **声明在 `allowed-tools` 里的操作在 Skill 执行期间不弹确认面板，直接执行**
      （验证：跑一个声明了某写操作的 Skill，观察该操作无面板；AC9）【自动 + 驱动】
- [ ] **未声明的操作照常弹确认面板**（验证：同一次执行中触发一个未声明的操作；AC9）【自动 + 驱动】
- [ ] **预授权在本次执行结束后失效**——用户发出下一条消息后，同一操作重新弹面板
      （验证：执行 Skill → 再发一条普通消息触发同一操作 → 观察面板出现；AC10）【自动 + 驱动】
- [ ] **预授权放行不了危险命令**：即使声明了放行全部命令，危险命令仍被第①层黑名单拒绝
      （验证：造该样本后让模型执行一条危险命令；AC11）【自动 + 驱动】
- [ ] **预授权放行不了越界路径**：越界读写仍被第②层沙箱拒绝（验证：同上；AC11）【自动】
- [ ] **执行被取消时预授权被撤销**（验证：执行中途取消后，同一操作重新弹面板；AC12）【自动】
- [ ] **执行因出错或达到迭代上限终止时预授权同样被撤销**（验证：单测构造两种终止路径，
      断言预授权列表为空；AC12）【自动】
- [ ] **无法识别的预授权项跳过并警告，不阻断启动**（验证：造一份声明了本系统没有的工具名的样本，
      观察程序正常启动且 `/skills` 有警告）【自动 + 驱动】
- [ ] **任何 Skill 激活状态下模型收到的工具集都是注册中心全量工具**
      （验证：读行为记录里 `api_request` 的工具名列表，与注册中心对比；AC13）【自动 + 驱动】
- [ ] **Plan Mode 规划阶段的只读限制不受影响**（验证：开计划模式后看工具名列表仍只含只读工具
      加两个交互工具；AC13）【自动】

## 五、迁移与兼容

- [ ] **含 `allowed_tools`（下划线）的 Skill 加载后出现一条明确说明语义已变更的警告**，
      且该字段按预授权生效（验证：造该样本后看 `/skills`；AC4）【自动 + 驱动】
- [ ] **该警告措辞明确指出「语义已变更」**，不与其它警告合并淡化（验证：断言警告文本含关键措辞）【自动】
- [ ] **三个内置样板按新格式与新语义工作**，且模型可自行发起（验证：全新环境启动后
      `/skills` 列出三条、来源为内置、各含 `when_to_use`；AC17）【自动 + 驱动】
- [ ] **一份未经修改的外部 Skill 放入目录后六项行为逐项成立**：能被发现、命令名等于目录名、
      两段说明进清单、`allowed-tools` 按预授权生效、`context: fork` 按子对话执行、
      无法支持的字段各有警告（验证：用真实的外部 Skill 原样搬入后逐项观察；AC18）【驱动】

## 六、集成与分层

- [ ] **`ToolPolicy` 已从代码库消失**（验证：全库搜索无残留，且编译通过）【自动】
- [ ] **`history_messages` 与 `mode` 已从代码库消失**（验证：同上）【自动】
- [ ] **Skill 层仍是叶子包**，不反向依赖命令层、协调层或界面层；权限层不依赖 Skill 层
      （验证：导入关系检查，任一方向出现反向依赖即失败；N4）【自动】
- [ ] **`SkillManager` 的加锁不变量护栏仍在且仍通过**——回调桩另起线程读状态并 join，
      用完成计数而非布尔标志（验证：该用例单跑通过；同线程版本会静默通过，故不可简化）【自动】
- [ ] **加载工具在串行段执行，不进只读并发桶**（验证：模型同轮发起加载工具与另一只读工具，
      观察行为记录中两者的并发标记）【自动】

## 八、编译与测试

- [ ] 项目编译无错误（验证：`python -m compileall rhinecode tests`）
- [ ] 全量单元测试通过（验证：`python -m unittest discover -s tests`）
- [ ] 删除的两个测试文件不再被导入，也没有留下「已废弃但仍断言」的用例（验证：全量无导入错误）
- [ ] 打包后内置样板仍在（验证：构建 wheel 后解包，`skills/builtin/` 下三个 `.md` 都在）

## 九、端到端场景

> 用 P1a 驱动设施跑，真实模型。每条记录实际观察结果。

- [ ] **场景 1（外部 Skill 原样可用）**：把一份未经修改的 Claude Code 格式 Skill 放进项目级目录 →
      启动 → `/skills` 看到它，命令名等于目录名 → `/skills prompt` 确认两段说明都进了清单 →
      用短命令带参执行 → 观察它按 SOP 行事、声明的操作免确认
- [ ] **场景 2（预授权的边界）**：执行一个声明了写操作的 Skill → 写操作无面板直接执行 →
      同一次执行中触发一个未声明的操作 → 面板照常弹出 → 执行结束后再发一条普通消息
      触发同一个写操作 → **面板重新出现**（授权已失效）
- [ ] **场景 3（预授权翻不过前三层）**：造一个声明「放行全部命令」的 Skill → 执行它并让模型
      跑一条危险命令 → 观察仍被第①层黑名单拒绝，确认面板一次都没弹
- [ ] **场景 4（模型自行发起 fork）**：不用短命令，直接提一个匹配某 fork Skill 的需求 →
      观察模型自行调用加载工具 → 子对话完整执行且进度可见 → 结论作为工具结果回灌 →
      主历史只留那对配对消息
- [ ] **场景 5（两个可调用性开关）**：造一个 `disable-model-invocation: true` 的 Skill →
      提一个会匹配它的需求 → 模型被拒绝并建议用户手动触发 → 用户手动触发成功；
      再造一个 `user-invocable: false` 的 → Tab 补全里没有它 → 但模型能自行发起
- [ ] **场景 6（旧格式迁移提示）**：把一份 C11 时代写的、含 `allowed_tools` 的 Skill 原样放进去 →
      启动 → `/skills` 出现「语义已变更」警告 → 确认该字段现在按预授权生效（原本会收窄的工具
      现在照常可见）
- [ ] **场景 7（无能力字段告知）**：造一份同时声明 `background: true`、`agent`、`effort`、
      `hooks`、`paths`、`shell` 的 Skill → 启动 → `/skills` 出现六条各自的说明 →
      执行它，确认仍能正常跑完
