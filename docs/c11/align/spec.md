# C11 对齐 Agent Skills 开放标准 Spec

> 本文修订 `docs/c11/spec.md` 的 F1–F5、F14–F17、F20、F22、F24、F29 若干条。
> 未被本文覆盖的 C11 条款继续有效。

## 背景

C11 的 Skill 系统是自研格式：`name` 决定命令名、`mode: shared/isolated` 表达执行模式、
`allowed_tools` 收窄模型可见的工具集。这套设计在自研范围内自洽，43 项端到端判据
以真实模型跑通、产品代码一行未改。

问题出在**外部来源**。真实使用中把一份 Claude Code 的 Skill 原样搬进来，
四个问题当场全中，其中最严重的一条是**语义相反**：

> Claude Code 的 `allowed-tools` 是**预授权**——「列出的工具本轮免确认」，
> 文档明确写着「It does **not** restrict which tools are available」。
> 而 RhineCode 把它当**收窄**——「只有列出的工具可见」。
>
> 于是一份写着 `allowed-tools: Read Grep` 的 Skill，作者本意是「这两个别烦我确认」，
> 搬到 RhineCode 变成「只有这两个能用」。实测中模型因此不断往白名单里加工具，
> 直到它覆盖了全部工具、收窄彻底失效——而这个过程对用户完全不可见。

同时，Claude Code 与 Codex 都遵循 **Agent Skills 开放标准**（`SKILL.md`），
两边的 Skill 可以互换。RhineCode 不兼容这套标准，意味着用户既不能拿现成的 Skill，
也不能把自己写的 Skill 拿去别处用。

本次改造的目的是**让外部 Skill 原样可用**，代价是放弃若干自研语义。

## 目标

- 一份为 Claude Code 或 Codex 编写的 Skill，原样放进 RhineCode 的 Skill 目录即可使用，
  行为与作者预期一致，不需要任何人工适配
- 消除「同一字段两种语义」这类**静默且相反**的失败——它比功能缺失危险得多
- 保留 RhineCode 三处经实测确认更优的行为，不为对齐而对齐
- 对无法支持的标准字段，**明确告知**而不是静默忽略

## 功能需求

### 一、定义格式与发现

- **F1**：frontmatter 字段表按下表重定义。**全部字段可选**——一份只有正文、
  没有 frontmatter 的 Markdown 文件也是一个合法 Skill。

  | 键名 | 含义 | 缺省 |
  |---|---|---|
  | `name` | **仅作显示标签**，出现在列表与清单中 | 取命令名（见 F2） |
  | `description` | 用途说明，进第一阶段清单 | 取正文第一段 |
  | `when_to_use` | 触发说明，拼接在 `description` 之后进清单 | 无 |
  | `allowed-tools` | 本轮预授权免确认的工具（见 F11） | 不预授权 |
  | `context` | 取值 `fork` 时开子对话执行（见 F9） | 留在主对话 |
  | `disable-model-invocation` | 为真时模型不得自行发起该 Skill（见 F8） | 假（模型可自行发起） |
  | `user-invocable` | 为假时不进斜杠命令菜单（见 F8） | 真（可被用户触发） |
  | `model` | 子对话使用的模型，仅 `context: fork` 生效 | 沿用全局配置 |

  未知键忽略（向前兼容）。键值类型不符按 F5 记为加载失败。

  连字符与下划线两种写法均接受（`allowed-tools` 与 `allowed_tools` 等价），
  因为标准用连字符而 YAML 使用者常写下划线。**唯一例外见 F6**。

- **F2**：**命令名来自文件系统路径，不来自 frontmatter**。目录型取目录名，
  单文件型取去掉扩展名的文件名。frontmatter 的 `name` 只影响列表显示。

  这条是「原样可用」的基础：从任何来源拉一个 Skill 目录丢进去，
  命令名就是目录名，不必检查也不必修改 frontmatter。

- **F3**：三层加载位置与优先级不变（项目级 > 用户级 > 内置），同名整份覆盖。
  「同名」的判定依据随 F2 变为**命令名**。

- **F4**：命令名合法性只做最低限度校验——不得为空、不得含路径分隔符、
  不得为管理命令的保留子命令词。长度与字符集不再校验：文件系统已经保证了
  名字是合法的文件名，再叠一层自定义规则只会让合法的外部 Skill 被拒。

- **F5**：加载容错语义不变——单个 Skill 加载失败只跳过它自己，记录可读原因，
  不阻断启动，原因可通过状态查询看到。失败原因清单随 F1/F4 调整。

- **F6**：**旧语义字段的显式失效**。`allowed_tools`（下划线写法）在旧版本中是
  「收窄」语义，本次改为「预授权」。为避免同一份文件在新旧版本下行为相反而
  用户毫不知情，加载时若发现该字段，**必须产出一条明确警告**，说明语义已变更、
  当前按预授权处理。这条警告不可省略，也不可与其它警告合并淡化。

  这是本次改造中唯一「静默会造成实际损害」的迁移点，故单列一条需求。

### 二、两阶段加载

- **F7**：第一阶段清单的每条由「命令名 + `description` + `when_to_use`」组成，
  后两者拼接后共享同一字符预算。清单仍不含任何 SOP 正文，仍注入稳定可缓存通道。

- **F8**：**「在哪执行」与「谁能触发」是两个正交维度**，各由独立字段决定。
  C11 把两者捆在一起（子对话模式硬编码为只能用户触发），本次拆开。

  | | 模型可自行发起 | 用户可用斜杠命令触发 |
  |---|---|---|
  | 缺省 | 是 | 是 |
  | `disable-model-invocation: true` | 否 | 是 |
  | `user-invocable: false` | 是 | 否（不进菜单） |

  模型自行发起一个 `context: fork` 的 Skill 时，该 Skill 在子对话中完整执行，
  **其结论作为这次发起动作的结果回灌**给模型。模型自行发起一个非 fork 的 Skill 时，
  行为不变（正文进动态槽位，返回一句简短确认）。

  被 `disable-model-invocation` 挡下时返回结构化错误，并给出用户可用的入口。

### 三、执行模式

- **F9**：`context: fork` 取代 `mode: isolated`——开一条子对话执行，跑完只把结论
  回流主历史，主历史**恰好新增两条配对消息**。不写 `context` 即留在主对话执行
  （原 `mode: shared` 的行为）。

  子对话固定只带那一条自包含调用消息，不再支持从主历史尾部带入若干条
  （原 `history_messages` 字段随之删除）。

  **`context: fork` 不再隐含「只能由用户触发」**——那由 F8 的字段单独表达。

- **F10**：**无对应能力的标准字段必须明确告知**。解析到 `background`（取 `true` 时）、
  `agent`、`effort`、`hooks`、`paths`、`shell` 时，各产出一条说明「本版本不支持该字段
  及其实际行为」的警告，然后按本版本的固定行为继续。

  静默忽略是不可接受的：作者写 `background: true` 的预期是「后台跑、不阻塞」，
  实际却同步阻塞跑完，两者差异用户必须知道。

### 四、工具权限

- **F11**：`allowed-tools` 采用标准语义——**列出的工具在本次执行中免于人工确认**，
  但**不限制**模型可以调用哪些工具。未列出的工具照常走完整的权限管线。

  取值词汇与既有权限规则一致（工具类别名加可选的参数模式，如「Bash 加命令前缀模式」
  「Read 加路径模式」）。标准中把只读检索拆成多个工具名的写法，映射到本系统对应的
  只读类别上。

- **F12**：预授权的有效期是**触发它的那一次执行**。用户发出下一条消息即失效，
  再次触发同一个 Skill 会重新授权。Skill 正文的常驻与否不影响授权有效期。

- **F13**：**工具集收窄能力整体移除**。模型在任何时候都能看到工具注册中心的
  全部工具（Plan Mode 的只读限制不受影响，它是另一套机制）。随之移除的还有
  「模型调用了本轮未提供的工具」这一兜底分支——不收窄之后该情形不再可能发生。

  安全影响：无。收窄从来不是安全边界（C11 spec 已载明），实际约束一直由
  危险命令黑名单、路径沙箱、可配置 deny 规则与人在回路四层承担。

### 五、迁移

- **F14**：随程序分发的内置样板按新格式重写，其 `allowed-tools` 按新语义声明
  （即「这些操作免确认」而非「只能用这些」）。样板不声明
  `disable-model-invocation`，即采用标准缺省——**模型可自行发起**。
  这是相对 C11 的行为变化（原本子对话模式的样板只能用户触发），如实登记。

- **F15**：一份为 Claude Code 或 Codex 编写、未经修改的 Skill，放入任一 Skill 目录后：
  能被发现、命令名等于其目录名、`description` 与 `when_to_use` 正确进入清单、
  `allowed-tools` 按预授权生效、`context: fork` 按子对话执行、
  无法支持的字段各有一条警告。

## 非功能需求

- **N1**：改造集中在 Skill 定义的解析、发现与命令注册，以及权限层新增的
  「本次执行内有效的临时放行」。Agent 循环、上下文管理、记忆系统不受影响。

- **N2**：权限层新增的临时放行**不得**成为绕过前三层防线的通道。它等价于用户
  在确认面板上选择放行，因此危险命令黑名单与路径沙箱依然先于它生效。

- **N3**：临时放行的注册与撤销必须成对，且在执行异常终止（取消、出错、
  达到迭代上限）时同样撤销。任何一条泄漏到下一次执行都属缺陷。

- **N4**：分层不变——Skill 层仍是叶子包，不反向依赖命令层、协调层或界面层。
  权限层不依赖 Skill 层。

- **N5**：本次移除的能力（工具收窄、越界兜底、带入尾部历史）对应的既有测试
  一并移除，不保留「已废弃但仍断言」的用例。

## 安全边界

- 预授权**扩大**了模型在一次执行内的自由度：它把原本需要逐次确认的操作变成免确认。
  因此 Skill 文件的可信度要求随之提高——一份项目级 Skill 可以为自己授予
  相当宽的操作权限。既有的「发现项目级 Skill」提示继续保留并适用。
- 预授权只影响第④层（模式兜底）与第⑤层（人在回路），前三层不受影响。
- 移除工具收窄不降低安全性（见 F13）。

## 不做的事

- **无参调用文本的措辞**：指导型 Skill 无参触发时，自包含调用文本
  「执行 Skill /x（说明）参数：（无）」语义空转，实测会让模型误读成「加载」
  并浪费一轮。修它要改自包含文本的契约（三个消费者要求逐字一致），本次不动，登记为后续。
  注意这与 `disable-model-invocation` **无关**——那次是用户手动触发的。
- **`disallowed-tools`**：本次不支持。它是标准中真正的「限制工具」字段，
  支持它等于换个极性把收窄能力拿回来；本次先把语义拉直，不同时引入新能力。
- **命名位置参数与序号替换**（`arguments` 字段、按序号或名字取参）：本次不支持，
  全量参数替换的既有行为不变。
- **清单字符预算按上下文窗口比例缩放**：标准实现按窗口的固定比例分配，
  本系统仍用固定阈值。与既有的「保留区阈值不随窗口缩放」属同类问题，一并登记。
- **插件与市场式分发**：不做。
- **从网络安装 Skill**：不做，留待独立立项（它有独立的威胁模型）。
- **Skill 的创建、导入与体检辅助**：不做。本次对齐之后，外部 Skill 原样可用，
  该需求的紧迫性显著下降。

## 验收标准

- **AC1**：一份无 frontmatter、只有正文的 Markdown 文件能作为 Skill 加载，
  命令名等于文件名，说明取自正文第一段（对应 F1）
- **AC2**：frontmatter 的 `name` 与目录名不一致时，命令名取目录名，
  列表显示取 `name`（对应 F2）
- **AC3**：连字符与下划线两种键名写法解析结果一致（对应 F1）
- **AC4**：含 `allowed_tools`（下划线）的 Skill 加载后，状态查询中出现一条
  说明语义已变更的警告，且该字段按预授权生效（对应 F6）
- **AC5**：命令名含路径分隔符或为保留子命令词时加载失败并给出原因；
  含大写字母或超过既有长度限制的名字**不再**失败（对应 F4）
- **AC6**：清单中每条同时包含 `description` 与 `when_to_use` 的内容（对应 F7）
- **AC7**：`context: fork` 的 Skill 执行后主历史恰好新增两条配对消息，
  子对话的工具调用不在主历史中（对应 F9）
- **AC8**：`background: true`、`agent`、`effort`、`hooks`、`paths`、`shell`
  各自触发一条可读警告，且 Skill 仍正常加载与执行（对应 F10）
- **AC9**：声明了某操作的 Skill 执行期间，该操作不弹确认面板直接执行；
  未声明的操作照常弹面板（对应 F11）
- **AC10**：预授权在本次执行结束后失效——用户发出下一条消息后，
  同一操作重新弹确认面板（对应 F12）
- **AC11**：预授权不能放行危险命令黑名单或路径沙箱拦截的操作（对应 N2）
- **AC12**：执行被取消或出错终止时，预授权同样被撤销（对应 N3）
- **AC13**：任何 Skill 激活状态下，模型收到的工具集都是注册中心的全量工具
  （Plan Mode 规划阶段除外）（对应 F13）
- **AC14**：缺省情况下模型可自行发起 `context: fork` 的 Skill，子对话完整执行，
  其结论作为该次发起动作的结果回灌模型（对应 F8）
- **AC15**：声明 `disable-model-invocation: true` 的 Skill，模型自行发起时被拒绝
  并得到用户可用的入口；用户用斜杠命令触发仍照常执行（对应 F8）
- **AC16**：声明 `user-invocable: false` 的 Skill 不出现在斜杠命令菜单中，
  但模型仍可自行发起（对应 F8）
- **AC17**：内置样板按新格式与新语义工作，且模型可自行发起（对应 F14）
- **AC18**：一份未经修改的外部 Skill 放入目录后，F15 列出的六项行为逐项成立
