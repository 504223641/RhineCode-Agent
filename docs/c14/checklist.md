# C14 子 Agent 工作区隔离 Checklist

> 每一项通过**运行代码或观察行为**来验证，聚焦系统行为而非实现结构。
> 括号里是验证方式；方括号里是对应的 spec 验收标准编号。
>
> **验收纪律：先有证据再下结论。** 先跑命令、看输出，再标记通过。
> 报告实际结果，不是预期结果。

---

## 一、工作目录的显式传递

- [ ] 一次含隔离子 Agent 的完整会话前后，进程的当前工作目录不变
      （验证：会话前后各执行一次「打印当前目录」的命令，两次输出相同）[AC1]
- [ ] 主对话的文件读写始终发生在主项目根
      （验证：会话中让主 Agent 写一个相对路径文件，确认它出现在主项目根）[AC1]
- [ ] 隔离子 Agent 读写其工作区内的相对路径成功
      （验证：委派它创建并读回一个文件，文件出现在隔离工作区内）[AC2]
- [ ] 隔离子 Agent 读写主项目根内、其工作区之外的路径被拒，原因为路径越界
      （验证：委派它以绝对路径读主项目根的某文件，观察被拒及原因）[AC2]
- [ ] 工作目录参数缺失或非法时，路径判定为**拒绝**，而非按主项目根放行
      （验证：单测直接构造该情形，断言判定为拒绝）[AC3]
- [ ] 隔离子 Agent 执行命令查询当前目录，返回其隔离工作区路径
      （验证：委派它执行打印当前目录的命令，比对输出与工作区路径）[AC4]
- [ ] 隔离子 Agent 可读用户级记忆目录中的文件，但向该目录写入被拒
      （验证：分别委派一次读与一次写，观察两个结论）[AC5]
- [ ] 未启用隔离时，子 Agent 与主对话的路径判定、权限结论、结论渲染与改造前一致
      （验证：全量测试中既有的权限、子 Agent、Hook 用例全绿，且未修改其断言语义）[AC6]

## 二、隔离工作区的创建

- [ ] 委派给声明隔离的角色后，`<主项目根>/.rhinecode/worktrees/<名字>` 出现
      （验证：委派后列出该目录）[AC7]
- [ ] 该目录被版本控制忽略
      （验证：创建后 `git status --short` 输出为空）[AC7]
- [ ] 名字含上级引用、非法字符、超长、或某段为 `.`/`..` 时创建失败，
      且文件系统上**没有产生任何目录**
      （验证：逐个非法构造调用创建，捕获异常后列出工作区根目录确认为空）[AC8]
- [ ] 含 `/` 的合法嵌套名字创建成功
      （验证：用形如 `a/b` 的名字创建，确认嵌套目录出现）[AC8]
- [ ] 未给出名字时系统生成一个合法名字并创建成功
      （验证：委派时不传名字，观察产出的工作区名）[AC9]
- [ ] 隔离工作区的分支基于当前 HEAD
      （验证：比对创建前的 HEAD 短哈希与交付信息段里的基点）[AC10]
- [ ] 主项目根中未提交的改动在隔离工作区中不可见
      （验证：主项目根改一个文件不提交，在隔离工作区读同一文件，内容是旧版本）[AC10]
- [ ] 目标分支名已存在时创建仍成功，交付信息中报告的是实际使用的分支名
      （验证：先手工建同名分支，再创建，观察最终分支名）[AC11]
- [ ] 对一个已存在且已登记的目录再次创建时走快速恢复，**不产生任何 git 调用**
      （验证：单测中替换掉创建命令的实现，断言它未被调用）[AC12]
- [ ] 隔离工作区继承主仓库的 Git 钩子
      （验证：在主仓库配置一个会写标记文件的提交钩子，在隔离工作区提交后
      确认标记文件出现）[AC15]

## 三、环境初始化

- [ ] 配置一条复制条目后创建，隔离工作区中出现一份**独立**副本
      （验证：修改副本后确认主项目根的源文件未变）[AC13]
- [ ] 配置一条软链条目后创建，隔离工作区中出现指向主项目根的链接；
      若因平台限制降级为复制，则产生一条说明降级的警告
      （验证：观察目标类型与初始化警告列表）[AC13]
- [ ] 清单中指向主项目根之外的条目被跳过并产生警告，其余条目照常生效，
      创建本身仍成功
      （验证：清单里混入一条越界条目与一条正常条目，观察结果与警告）[AC14]
- [ ] 清单为空时不产生任何额外文件
      （验证：缺省配置下创建，比对工作区内容与一次纯 checkout 的差异）[AC14]

## 四、失败与不降级

- [ ] 在非 Git 仓库目录中启动，委派给声明隔离的角色时失败，
      失败原因明确指出当前目录不是 Git 仓库
      （验证：在临时非仓库目录启动，发起委派，读失败消息）[AC16]
- [ ] 同一非 Git 环境中，委派给未声明隔离的角色照常成功，启动过程无报错
      （验证：同一会话中再委派一次，观察结论）[AC16]
- [ ] 创建失败后主 Agent 的循环继续运行，可就该失败继续对话或改派其它角色
      （验证：失败后主 Agent 仍产出正文并可再次委派）[AC17]
- [ ] 隔离创建失败时**没有**退化为在主项目根中运行
      （验证：失败后确认没有任何文件被写入主项目根）[AC16/G2]

## 五、声明与触发

- [ ] 角色定义中声明隔离字段后，不再产生「本项目不支持该字段」的警告
      （验证：加载后查看角色报告的警告段）[AC18]
- [ ] 角色报告中显示该角色的隔离声明；未声明的角色不显示该项
      （验证：查看角色报告）[AC18]
- [ ] 角色已声明隔离时，委派方在本次调用上要求不隔离**无效**，仍创建隔离工作区
      （验证：委派时显式关闭隔离，观察工作区仍被创建）[AC19]
- [ ] 角色未声明隔离时，委派方在本次调用上要求隔离**有效**
      （验证：对一个未声明的角色显式要求隔离，观察工作区被创建）[AC19]
- [ ] 隔离子 Agent 被问及自身工作目录时，回答与实际工作区路径一致
      （验证：委派一个只需回答工作目录的任务，比对结论与实际路径）[AC20]

## 六、结束与交付

- [ ] 隔离子 Agent 未产生任何变更时，其工作区目录与分支在结束后均不存在
      （验证：委派一个纯只读任务，结束后列出目录并查询分支）[AC21]
- [ ] 隔离子 Agent 产生了变更时，其工作区目录在结束后仍存在
      （验证：委派一个写文件的任务，结束后目录仍在）[AC22]
- [ ] 主历史中该子 Agent 的结论末尾含交付信息段，其中的分支名、提交数与
      变更文件清单与直接查询版本库所得一致
      （验证：读主历史中的结论，逐项与 git 查询结果比对）[AC23]
- [ ] 模型在自己正文中写了**错误**的分支名时，交付信息段中仍为实际值
      （验证：用会写错分支名的假模型驱动一次，比对两处）[AC23]
- [ ] 主 Agent 对一个同时存在于主项目根与某隔离工作区中的字符串做内容检索，
      结果只来自主项目根
      （验证：制造同名内容后执行检索，检查结果路径）[AC24]

## 七、清理

- [ ] 超过阈值且无变更的残留工作区在启动后被删除，并在启动报告中列出
      （验证：手工制造一个过期空工作区，启动后观察目录与报告）[AC25]
- [ ] 未超过阈值的同类工作区不被删除
      （验证：同上，用一个新鲜的工作区做对照）[AC25]
- [ ] 待删路径为空、含上级引用或指向工作区根目录之外时删除被拒，
      文件系统无变化
      （验证：单测穷举这三种构造，断言拒绝且目标仍在）[AC26]
- [ ] 工作区目录下一个手工创建的普通目录不被清理
      （验证：手工建一个未被 git 登记的目录，启动后确认它仍在）[AC27]
- [ ] 超过阈值但含未提交改动的工作区**不被删除**，并在启动报告中列出原因
      （验证：制造该情形，启动后确认目录仍在且报告有说明）[AC28]
- [ ] 超过阈值、无未提交改动但含新增提交的工作区：目录被删除、**分支仍存在**，
      且能从版本库取回其提交内容；启动报告中列出该分支名
      （验证：制造该情形，启动后查询分支并取回内容）[AC29]
- [ ] 「版本库已不登记但磁盘目录仍在」的残留能被清理掉且不报错
      （验证：先注销登记再保留目录，启动后确认目录消失）[AC30]
- [ ] 清理过程中的任何异常都不阻断启动
      （验证：制造一个会让状态查询失败的条目，确认启动照常完成）[N-fail-safe]

## 八、观测

- [ ] 任务列表中隔离任务显示其工作区路径与分支名，非隔离任务不显示这些字段
      （验证：并存一个隔离任务与一个非隔离任务时查看任务列表）[AC31]
- [ ] 一次隔离委派的行为记录中可依次找到创建、初始化、结束决定三类事件
      （验证：开启行为记录跑一次委派，按类型过滤查看）[AC32]
- [ ] 一次启动清理的行为记录中可找到清理结果
      （验证：同上，查看清理事件）[AC32]
- [ ] 新增的行为记录事件在阅读器中显示为可读摘要，**不是**「未登记类型」
      （验证：用阅读器读取上述记录，逐条查看摘要）[AC32]

## 九、自动化钩子

- [ ] 工具级钩子中执行打印当前目录的命令，由隔离子 Agent 触发时打印其工作区路径
      （验证：配置该钩子后委派一次隔离任务，读钩子输出）[AC33]
- [ ] 同一钩子由主对话触发时打印主项目根
      （验证：同一会话中让主 Agent 调一次同类工具）[AC33]
- [ ] 一条会拦截某类工具调用的钩子规则，对隔离子 Agent 的同类调用同样生效
      （验证：配置拦截规则，委派隔离子 Agent 做该类操作，观察被拦截）[AC34]

## 十、并发

- [ ] 三个隔离子 Agent 同时委派：三个工作区与三个分支全部创建成功、互不干扰，
      各自的交付信息段指向各自的分支
      （验证：一次发起三个委派，结束后逐个比对）[AC35]
- [ ] 其中一个的创建失败不影响其余两个的运行与交付
      （验证：其中一个用非法名字，观察另外两个照常完成）[AC35]

## 十一、安全边界

> 本项目的安全论证不能只靠代码审阅，必须有可运行的反证。

- [ ] 隔离子 Agent 的危险命令仍在第①层黑名单被拦下
      （验证：委派它执行一条黑名单命令，观察被拦及命中层）
- [ ] 隔离子 Agent 无法通过任何路径写到主项目根
      （验证：分别用相对上级路径、绝对路径、符号链接三种方式尝试，三次都被拒）[N1]
- [ ] 隔离子 Agent 拿不到委派工具与 Skill 加载工具（无限嵌套防护仍成立）
      （验证：查看其最终工具集）[C13 既有约束]
- [ ] 隔离工作区的删除必须先通过三层过滤——绕过过滤的删除路径不存在
      （验证：全项目检索文件系统删除调用，确认工作区目录的删除只有一处入口）
- [ ] 权限管线的层序未因本章改变
      （验证：既有的层序护栏测试全绿，含「全域名放行 + 禁止地址」那条构造）
- [ ] 隔离工作区目录被版本控制忽略，其内容不会被误提交
      （验证：建工作区并在其中写文件后 `git status --short` 为空）[N8]

## 端到端场景

> 以下九个场景在真实终端中跑通，对照观察结果。
> 涉及真实模型的场景记录在 `docs/c14/acceptance/`。

- [ ] **场景 1（本章的核心承诺）· 并行不覆盖** [AC36]
      主 Agent 修改文件 A 且不提交，同时委派一个隔离子 Agent 修改文件 B。
      → 期望：子 Agent 看不到 A 的未提交改动；子 Agent 结束后主 Agent 手上
      A 的改动完好无损；B 的改动不在主项目根出现；主 Agent 按交付信息段里的
      分支名执行合并后，A 与 B 的改动同时存在。

- [ ] **场景 2 · 只读任务不留垃圾**
      委派一个隔离子 Agent 做纯调研（只读不写）。
      → 期望：结论正常回流；工作区目录与分支在结束后都不存在；主项目根无变化。

- [ ] **场景 3 · 非 Git 环境明确失败**
      在一个非 Git 仓库的临时目录中启动，委派给声明隔离的角色。
      → 期望：委派失败且原因明确；主 Agent 能继续对话；改派未声明隔离的角色成功；
      整个过程没有任何文件被写入。

- [ ] **场景 4 · 单向加严**
      对一个声明了隔离的角色，在委派时显式要求不隔离。
      → 期望：仍然创建隔离工作区，且这一点在任务列表中可见。

- [ ] **场景 5 · 启动清理的三种结局**
      预置三个过期工作区：① 干净无提交、② 干净有提交、③ 有未提交改动。
      重启程序。
      → 期望：①被完全删除；②目录删除但分支保留且内容可取回；③保持不动；
      三者的结局都在启动报告里说明。

- [ ] **场景 6 · 交付信息不被模型污染**
      让子 Agent 在结论正文里写一个与实际不符的分支名。
      → 期望：交付信息段中的分支名为实际值，主 Agent 依它执行合并成功。

- [ ] **场景 7 · 主 Agent 的搜索不被污染**
      在隔离工作区存在的情况下，让主 Agent 检索一个两边都有的字符串。
      → 期望：结果只来自主项目根，不出现重复命中。

- [ ] **场景 8 · 环境初始化**
      配置一条复制条目（配置文件）与一条软链条目（大目录），委派一次隔离任务。
      → 期望：副本独立（改副本不影响源）；链接生效或降级为复制并有警告；
      子 Agent 能用上这些文件完成任务。

- [ ] **场景 9 · 钩子在隔离下的行为**
      配置一条打印当前目录的工具级钩子，以及一条拦截某类命令的规则。
      → 期望：隔离子 Agent 触发时打印工作区路径、主对话触发时打印主项目根；
      拦截规则对隔离子 Agent 同样生效（主 Agent 无法通过委派绕过它）。
