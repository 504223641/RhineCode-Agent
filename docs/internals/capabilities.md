# 当前能力细节

> 本文件是 `CLAUDE.md` 的分册，**按需读取**，不随会话自动注入。
> 主文件只保留索引与「必须不请自来」的内容，细节在这里。

> 逐条描述各章能力的**实际行为与边界**（阈值、降级路径、哪些 Provider 生效）。
> 主文件的能力表只回答「有什么」，这里回答「具体怎么表现」。

- **Hook 系统**（c12）：独立 `hooks/` 层。一条规则 = `event`（必填）+ `if`（可省，省略即无条件）+ `action`（必填），另有可选的 `name` 与三个执行控制字段。从**两层 YAML** 加载（用户级 `~/.rhinecode/hooks.yaml` + 项目级 `<项目根>/.rhinecode/hooks.yaml`，**没有本地级**），两层规则全部生效不按层级覆盖，执行顺序固定为「用户级 → 项目级 → 层内声明序」，**不提供优先级字段**。

  **十二个事件**：会话级 `session_start` / `session_end`；回合级 `turn_start` / `turn_end`（主对话与子对话都触发，由 `scope` 区分）；消息级 `user_message`（含斜杠命令）/ `assistant_message`；工具级 `pre_tool_use` / `post_tool_use` / `post_tool_use_failure`；系统级 `pre_compact` / `post_compact`（LLM 摘要前后）/ `notification`（四种 `kind`）。

  **`user_message` 与 `turn_start` 不是重复事件而是来源不同**：`/help` 触发前者不触发后者（命令不进 AI），模型自行发起的 fork 子对话则相反。

  **后置事件只挂在「真的执行了」之后**：未知工具、参数非法、`out_of_scope`、`plan_blocked`、权限 DENY、用户拒绝、Hook 自己拦下——七种情形一个后置事件都不产。其中前四种连 `pre_tool_use` 都不触发（它们在进入执行判定之前就被挡下），后三种会触发前置。

  **条件**：`if` 下写 `all`（全部满足）或 `any`（任一满足），**二选一、不混用、不嵌套**。每项是「字段: 模式」，四种匹配形态——精确（`tool: run_command`）、glob（`command: "git *"`，命令类带词边界、路径类是 gitignore 风格、其余是确定性的 `fnmatchcase`）、正则（`/^git (push|reset)/`，**非锚定**）、反向（值前缀 `!`，可与前三种叠加）。工具级事件的 `tool_input` 逐字展开成顶层字段名，故可直接写 `command:` / `file_path:`；与公共字段（`event`/`session_id`/`cwd`）或事件字段（`tool`/`tool_call_id`/`is_read_only`/`scope`）重名时**后者优先**。

  **四种动作**：`command`（事件负载以 JSON 从 **stdin** 喂入，配置里不做任何插值；退出码 0 通过 / 2 拦截 / 其它失败；stdout 可给决策 JSON）、`prompt`（注入 `<system-reminder>`，**一次性**，下一次请求可见后即清）、`http`（响应不参与任何决策）、`agent`（**本版本仅占位，不会真的运行**）。

  **执行控制**：`once`（本次进程内只跑一次，**不持久化**）、`async`（后台不等结果，`pre_tool_use` 上**禁止**）、`timeout`（command 缺省 60 秒、http 缺省 10 秒）。

  **拦截语义**：只有 `pre_tool_use` 能拦截，结论三选一——deny / ask / 不表态，**没有 allow**。多条命中时按最严合并（deny > ask > 不表态）。`ask` 只把权限管线的 ALLOW 升级为 ASK，**绝不降级 DENY**。

  **失败语义**：`pre_tool_use` 上 Hook 自身失败（超时 / 崩溃 / 退出码非 0 非 2 / stdout 非法 JSON）一律**按拦截处理**（fail-closed），文案含「Hook 自身执行失败」以便与「工具执行异常」区分；其余全部事件只记 trace 与一行提示，不影响任何流程。

  **缺省零行为**：两层配置都不存在时装配出的是 `NullHookManager`——不读文件、不构造负载、不产任何 trace 事件，运行时行为与 C11 逐字一致。

  **可观测**：`/hooks` 报告已加载规则（来源层 / 事件 / 条件 / 动作 / 触发次数 / 最近结论）+ 加载警告 + 配置位置；trace 新增 `hook_dispatch`（**零命中也记**——那是排查「我的 hook 为什么没跑」的第一现场）与 `hook_execute` 两类事件。**本章不做 `/hooks reload`**，改了规则要重启。

- **Skill 系统**（c11，已对齐 **Agent Skills 开放标准**）：独立 `skills/` 层（对标 permission/context/memory/commands：纯逻辑 + 单点接入，不依赖 Textual）。单个 Skill = 可选的 YAML frontmatter（`name`/`description`/`when_to_use`/`allowed-tools`/`context`/`disable-model-invocation`/`user-invocable`/`model`，**全部可选**）+ Markdown SOP 正文；一份只有正文的 `.md` 也是合法 Skill，说明从正文第一段提取。连字符与下划线两种键名写法等价。支持单文件型（`x.md`）与目录型（含 `SKILL.md` 入口 + 随附资源）。

  **命令名来自文件系统路径**（目录名 / 去扩展名的文件名），`name` 只是显示标签——这是「外部 Skill 原样可用」的地基：从 Claude Code 或 Codex 拉一个目录丢进 `.rhinecode/skills/` 就能用，不必检查也不必修改 frontmatter。**三级存放**：项目 > 用户 > 内置，同名整份覆盖。

  **两阶段加载**：启动时清单（命令名 + `description` + `when_to_use`）进 priority 140 稳定槽位；模型调 `load_skill` 后完整正文进 priority 120 动态槽位，**每轮重建**、多个可同时激活、重复激活幂等。正文超单体上限截断（TRUNCATED）、超总量上限整段丢弃（DROPPED），措辞不同且对用户可见。

  **「在哪执行」与「谁能触发」是正交两维**（C11 曾把它们捆在一起）：`context: fork` 开子对话跑完只回流结论（主历史**恰好新增两条配对消息**）；`disable-model-invocation` 决定模型能否自行发起；`user-invocable: false` 则不进斜杠菜单但模型仍可发起。子对话固定只带那条自包含调用消息，工具集**同时排除 `load_skill` 与 `run_agent`**——不变量是「已经是一层子对话的东西，不许再往下开一层」，子 Agent 那一侧（`GLOBAL_DENIED_TOOLS`）挡的是同样两个。⚠ **fork 子对话因此派不了活**，这是 2026-09-02 定的语义：它**刻意不接**子 Agent 闸门（主对话那次 `run()` 是接了的），因为闸门底下的 `TaskManager.take_deliverables()` 不按发起方分桶，接上去会让主对话委派出去的结论被 fork 那份用完即弃的历史取走并标成「已交付」。两种语义只落地一种，理由见 `skills/manager.py` 的 `fork_excluded_tools()`。

  **`allowed-tools` 是预授权，不是收窄**：列出的操作在**本次执行内**免于人工确认，**不限制**模型能调用什么。取值词汇与 `permissions.yaml` 的规则名一致（`Bash(git *)` / `Read` / `Write` / `Edit`，标准里的 `Glob`/`Grep` 映射到 `Read`），实现为权限引擎第③层的 `turn_rules`，排在①黑名单②沙箱**之后**——因此翻不过前两层。用户发出下一条消息即失效。无法识别的项跳过 + 警告，**不 fail-fast**（外部 Skill 里出现 `Task` / `TodoWrite` 这类名字是正常现象；`WebFetch` 自 web_fetch 扩展起是**真工具**，可以写，但括号里必须是 `domain:` 前缀）。

  **无对应能力的标准字段逐条告知**（`background`/`agent`/`effort`/`hooks`/`paths`/`shell`），不静默忽略。每个 Skill 自动注册 `/<name>` 短命令（与内置命令冲突则跳过并提示 `/skills run <name>`），`/skills` 五形态，状态栏 `Skill:N`。

- **Skill 体检**（作者期扩展）：`/skills` 报告里的**第四类反馈**（前三类是加载失败 / 警告 / 字段提示，都只说「发生了什么」；这一类说「那我该怎么改」）。纯函数零 IO、**每次现算不缓存**、排在前三类之后、**无建议时整段不出现**、有建议时段尾指向 `/skill-creator`。八项检查与各自阈值：

  | # | 判定 | 阈值 / 口径 |
  |---|---|---|
  | 1 | `description` 过长 | **> 100 字符**（按字符数不按字节数，否则中文说明比英文早三倍命中）。建议里**必须**写明「挪进 `when_to_use` 不省清单预算」——两者在清单里拼成同一行、共享预算，真正受益的是 `/skills` 列表与 `/help` 菜单 |
  | 2 | 写了 `when_to_use` 却没写 `description` | 判 `SkillSpec.description_explicit`（解析期派生事实），**不是**判「是否为空」——`description` 经解析后永不为空。**刻意不查「说明是自动提取的」本身**：无 frontmatter 的 Markdown 是刻意支持的合法写法 |
  | 3 | `description` 缺时机线索（**弱提示**） | 未声明 `when_to_use` **且** 作者显式写了 `description` **且** 该说明不含时机类词语（`TRIGGER_HINT_WORDS`）。**两处收窄都必要**：作者压根没写说明时也不查，否则与「无 frontmatter 的 Skill 不报建议」直接冲突。建议措辞**自称弱提示并明说可忽略** |
  | 4 | 正文无 `$ARGUMENTS` | 建议里**必须**写明「参数不会丢、只是被追加到末尾」，否则把「位置不对」误导成「功能失效」 |
  | 5 | 预授权过宽 | 非 MCP：工具名不在 `READ_ONLY_GRANT_TOOLS`（现仅 `Read`）**且**（无 pattern **或** pattern 是纯通配 `*` / `domain:*`）。**MCP 另判**：按工具名含不含通配符——引擎对 `other` 分支要求 `pattern == ""`，套用前一支不仅每条必误报，改法「加参数模式」还会让预授权**永远匹配不上** |
  | 6 | 预授权全军覆没 | 有声明但翻译出的规则数为 0。**部分生效不报**（单条认不出已有警告，这里报的是整体误解） |
  | 7 | 逼近注入上限 | **渲染后的注入段**（含边界标识、说明行、资源清单）达 `BODY_MAX_*` 的 **80%**（240 行 / 9830 字节）。已被截断时直接命中且措辞区分。渲染**传空参数**，是刻意偏松 |
  | 8 | 覆盖了内置样板 | `(命令名, BUILTIN) in SkillCatalog.shadowed`。**收窄到只报覆盖内置**，项目级盖用户级不报。措辞中性、含「若是有意定制请忽略」 |

  **第一阶段清单的召回率（R 系列）**：清单表头是**指令**而非公告——「动手前先扫清单 /命中则**替代你自己的默认做法** / 用户不必点名 Skill / 拿不准就加载」四句齐全，`load_skill` 的工具描述同口径。超预算时**降级成只有名字**而不是整条丢弃（降级顺序：内置 → 用户级 → 项目级；显示顺序仍按名字排）。⚠️ 「模型欠触发 Skill」是**已知的系统性偏差**，不是配置错误。

  内置样板**应当**零建议（实测四个样板均 0 条），但这是**设计约束不是硬判据**——刻意不建自动化断言，否则日后样板的正常调整会被无关测试拦住。

- **`skill-creator`**（作者期扩展的内置样板，目录型）：三种用途共用一个入口——**创作**（把一段流程封装成 Skill）、**适配**（检查外部 Skill 在本系统的差异）、**修复**（按体检建议改）。留在主对话执行（三种用途都要与用户往复确认，而子对话一次性跑完只回流结论）。随附 `reference.md` 完整字段手册作**随附资源**（255 行 / 9853 字节，塞进正文会让这个样板自己触发检查 6），不占清单与正文预算，模型按需读取。`allowed-tools` **只预授权只读调研**，写入与编辑刻意不给。**只能创建项目级**——用户级与内置目录在工作区外，写类判定被第②层沙箱拒（只读白名单不覆盖写类），被要求装用户级时须如实说明做不到。

- **斜杠命令系统**（c10）：独立 `commands/` 层（对标 permission/context/memory：纯逻辑 + 单点接入，不依赖 Textual）。`CommandSpec` 单一注册来源登记规范名/别名/描述/用法/类型/参数提示/隐藏标记/处理函数；命令分**本地直执行**（`/help`·`/mcp`·`/context`·`/compact`·`/memory`，绕过 Agent；`/compact` 的专用摘要调用是明确例外）、**界面状态**（`/think`·`/plan`·`/perm`·`/resume`·`/clear`·`/exit`）、**提示词**（`/init`，展开静态内置提示词交给 Agent，界面/存档回放显示原命令）三类；处理函数只面向 `CommandController` 协议（RhineApp 实现），可用 Fake 替身独立测试。解析大小写不敏感（casefold）、参数只按首空白切分不做 shell 分词；未知命令本地提示不进 AI；启动早期 `build_builtin_registry()` 原子注册，名称/别名冲突（含仅大小写不同）抛 `CommandRegistrationError` 以退出码 1 fail-fast（先于 Provider/MCP/会话锁创建）。别名：`/h`→`/help`、`/ctx`→`/context`、`/continue`→`/resume`、`/permissions`·`/allowed-tools`→`/perm`、`/reset`·`/new`→`/clear`、`/quit`→`/exit`。Tab 补全（单候选直补、多候选稳定排序菜单、参数区不拦截）、菜单回车执行高亮项、完整命中命令字段高亮（Textual `Input.highlighter` 公开扩展点）、状态栏 `[DEFAULT]`（dim）/`[PLAN]`（加粗青色）模式标记。
- **ReAct Agent Loop**：自动执行“调用模型 → 执行工具 → 回灌结果 → 再调用模型”的多轮循环。
- **流式输出**：正文与思考内容逐块渲染，后台 Worker 不阻塞 TUI 主线程。
- **DeepSeek 工具系统**：支持读文件、glob 找文件、grep 搜内容、写文件、精确编辑文件、运行命令；`read_file` 对大文件强制范围读取，`glob_files` / `grep_content` 会逐文件应用 `Read(...)` deny 过滤。
- **MCP 客户端**（c7）：启动时按两层 `mcp.yaml` 连接外部 MCP Server（stdio / Streamable HTTP），走 JSON-RPC 2.0（请求带 id、响应按 id 配对）完成 `initialize → tools/list → tools/call` 三步，把远端工具包装成 `mcp__<server>__<tool>` 风格的工具注册进工具中心；非法 function name 会规范化，真实远端名仍用于 `tools/call`；stdio stderr 后台 drain 防止 Server 大量写日志时阻塞；多 Server 连接缓存与隔离（单个失败不影响其它），退出统一回收；支持用户通过自然语言添加 MCP，Agent 先用 `mcp_resolve_server` 解析候选，再用 `mcp_add_server` 写入配置并单 Server 重载；MCP 工具一律非只读，且**缺省预设下每次调用都弹确认面板**（adapter 映射成 `remote` 类，第④层在放行档下判 ASK；判据是工具自己声明的 `Tool.remote_origin`）——面板另列「哪台 Server 提供的」与完整参数。⚠ 这条承诺在 auto-plan 换缺省档到 S2 修复之间**曾整整失效**，那段时间是 `allow @ mode`、零面板。`allow`/`deny` 规则形状与此前完全一致（整工具通配 `mcp__<server>__*` 照常可用），③层命中即短路④层。`/mcp` 命令与状态栏展示连接状态。仅接工具能力，不做资源/提示词/采样与健康检查/自动重连。
- **记忆系统**（c9）：独立 `memory/` 层（对标 permission/mcp/context：纯逻辑 + 单点接入）。三套机制按依赖分级生效——**RHINE.md 项目指令**与**会话存档/恢复**对所有 Provider 生效，**自动记忆**与 `/init` 仅 DeepSeek 工具模式（F21）。① RHINE.md：三层加载（`~/.rhinecode/RHINE.md` → `<项目根>/.rhinecode/RHINE.md` → `<项目根>/RHINE.md`，越具体越靠后利用近因效应），`@相对路径` include 原地展开（相对引用文件所在目录、嵌套上限 4 层、visited 防环、越出宿主层边界不展开、围栏代码块跳过），拼接结果填 c5 预留的「自定义指令」槽位（priority 110、c9 起 cacheable=True 进稳定通道）；`/init` 用内置指令走普通 Agent Loop 探索项目生成项目根 RHINE.md（已存在只提改进建议，写盘走完整权限管线）。② 会话存档：每会话一个 `<项目根>/.rhinecode/sessions/<YYYYMMDD-HHMMSS-xxxx>.jsonl`，惰性建档、逐条追加写（记录 c8 压缩**前**的原始消息流）、无独立 meta 文件（列表信息扫 JSONL 现算）；`/clear` 开新档；`/resume` 弹交互式选择面板（上下键/回车/Esc，锁定与当前项置灰跳过），载入成功产 `HISTORY` 事件、聊天区清空并回放全部历史（切换 session 语义），`rhine --continue` 恢复最近未锁定会话（启动同样回放）；容错载入（坏行跳过——**按二进制读、逐行自己解码**，故编码坏掉的行同样只算一条坏行、不掀翻整份载入；不成对工具调用丢组、恢复后若逼近窗口先跑一次 c8 压缩并 reset 锚点、超 24h 登记一次性时间跨度提醒并入下次 dynamic reminder）；启动时静默清理 30 天前存档。③ 自动记忆：Agent Loop 自然停止（FINISHED=COMPLETED）后异步 daemon 线程调一次 LLM（禁用工具、高水位只审视新增段），LLM 只产出 JSON 动作（filename 白名单 `[a-z0-9_-]+\.md` 防路径注入），程序在锁临界区内写盘并全量重建索引；用户相关存 `~/.rhinecode/memory/`、项目相关存 `<项目根>/.rhinecode/memory/`，每目录一份 `MEMORY.md` 索引（注入截断 200 行/25KB）填「长期记忆」槽位（priority 130）；用户级 memory 目录经 path_guard 只读白名单放行模型按需读取。④ 并发防护：锁文件 `O_CREAT|O_EXCL` 原子创建、拿不到即退让（记忆跳过本轮/会话拒绝载入）、mtime 过期自愈（阈值 600 秒）；会话锁靠追加时 touch + TUI 每 2 分钟心跳保鲜。`/memory` 只读报告全部状态（索引状态是**三态**：存在 / 读取失败 / 不存在）。⑤ 坏编码容错：`MEMORY.md` 与记忆正文读不出来时**跳过那一份继续**（记忆是「有更好、没有也能跑」的增强项），并经启动提示与 `/memory` 两条既有通道说明；⚠ 此前 `except OSError` 接不住 `UnicodeDecodeError`（它继承自 `ValueError`），而 `memory_index()` 每次构建系统提示都会调，一份 GBK 的 `MEMORY.md` 会让**每一轮对话都炸**。
- **上下文管理**（c8）：独立 `context/` 层（对标 permission/mcp：纯逻辑 + 单点接入），仅在 DeepSeek 工具模式生效。每轮请求前经 `loop.py` 单点调用——**估算**用「锚点（上次 API `usage.prompt_tokens`，精确）+ 增量（锚点后新增消息按字符估）」，误差只积累在增量小段；**估算逼近窗口**时调 LLM 生成五段式结构化摘要。触发线 = `窗口 − 余量`，而余量由两条规则取大：小窗口「比例 0.21 夹 13K」，大窗口「比例 0.03」（对齐 Claude Code 的 ~97%：它在 1M 模型上约 967K 触发；Codex 是窗口 × 90%）。两者在窗口 ≈ 433K 处交接，**该点以下逐字维持 2026-07-29 那次改造后的取值**（64K → 80.2%，1M → 97.0%）。⚠ 大窗口侧**刻意不夹上限**——余量必须随窗口等比放大，因为近似估算的误差**绝对值**随历史长度增长；加上限等于把「不跟着窗口走」这个缺陷换个数字造回来。摘要，保留边界回退到最近 `user`（不拆散 `assistant(tool_calls)↔tool`），重构为 `[摘要, 边界提示, 近期原文]`。摘要 Prompt 禁用工具、要求先草稿后正文（`<<<正式摘要>>>` 分隔、草稿丢弃）；连续失败 3 次熔断，`/clear` 复位。`/context` 只读报告、`/compact` 手动压缩（**无余量阈值，主动触发即尝试摘要**，无够旧早段时如实回「无可摘要的早段」），状态栏常驻「上下文：19% · 12.3K/64K」（≥80% 或熔断橘色高亮）。

  ⚠ **2026-09-17 删掉了原来的「第一层·工具结果存盘」**（把单个 >4K token 或合计 >16K token 的工具结果存盘到 `.rhinecode/context/<id>.txt`、历史留占位）。三条理由：① 那两个阈值是**绝对值**，定于「约 64K 窗口」的年代，而 `context_window` 现在缺省 1 000 000——相当于**用量到 1.6% 就开始删历史**；② 它动手的时机在「结果已落进历史、请求尚未组装」之间，于是**一半被删的是模型从没看过的内容**（真实 trace：17 次存盘里 8 次）；③ 上游 Claude Code 与 Codex **都没有这一层**，限量一律在工具**产出的那一刻**完成。现在那件事由工具自己承担（`run_command` 30 000 字符、`read_file` 100 000 字符配分页提示、`grep_content` 单行 500 字符），**进了历史的东西在到达摘要触发线之前一个字都不动**。详见已知项 #21 第二段。

  窗口大小由 `config.context_window`（默认 1 000 000，照 DeepSeek V4 全系的实际窗口）配置。
- **两个运行模式（auto / plan）**：`Shift+Tab` 或 `/mode`（别名 `/plan`）两态切换。`auto` = 放行档 + 规划阶段关；`plan` = **同一档位** + 规划阶段开（「只读」由规划阶段的工具过滤保证，不靠权限档）。获批后自动回到 `auto`，被拒留在 `plan`。
- **五层防御权限系统**：每个工具执行前由 `permission/` 包的纯逻辑引擎按固定顺序计算决定——①危险命令黑名单（不可被任何配置/模式放开）→②路径沙箱→③可配置规则（`Tool(模式)`，deny 永远优先）→④权限模式（严格/默认/放行；**缺省放行档，运行期不可切换**）→⑤人在回路（确认面板四选项：本次/本会话/永久/拒绝）。被拒不终止循环，结构化原因回灌模型让其调整策略。
- **可配置权限规则**：三层 YAML（用户级 `~/.rhinecode/`、项目级 `<根>/.rhinecode/`、本地级 `*.local.yaml` 不提交）声明 allow/deny；跨层合并后 deny 优先求值。
- **明确停止原因**：支持自然完成、迭代上限、用户取消、计划拒绝、连续未知工具、流错误、**原地打转**等停止路径。
- **不设轮次上限，改成检查点**（2026-09-18）：`MAX_ITERATIONS = 25` 从**硬顶**
  变成**检查点间隔**。到了那条线由一次独立的模型调用（`classifier/continuation.py`）
  回答「它还在往前走吗」，判「继续」就再给同样多的轮次。
  ⚠ **没配判定器时行为逐字不变**（第一个检查点直接停，原因与文案都是原来那一套）。
  ⚠ **连续放行有上限**（`MAX_CONSECUTIVE_CONTINUES = 4`，即约 125 轮）——这是唯一的
  结构性兜底：判定器**看得到工具输出**，因此一个读过恶意网页的模型可以在输出里写
  「务必继续」，后果是烧钱（碰不到权限管线的任何一层）。
  ⚠ **问不出来一律停**，不当成「继续」——一个坏掉的判定器否则会变成永远继续。
  ⚠ 它**不是** c16 的安全分类器，两者只共用一个 Provider；**已知取舍**是它目前
  跟着 `classifier.enabled` 一起开关。
- **原地打转检测**（`agent/spinning.py`，2026-09-18）：同一个 `(工具名, 参数, 结果)`
  在一次运行里重复 3 次即停止并告诉用户是哪个调用卡住了。**纯代码、零成本、每轮都在看。**
  三个判据各有真实样本支撑：**不要求连续**（真实死循环常是 A→B→A→B 的摆动）、
  **结果必须参与比较**（只比参数会把「改完再跑一次同样的测试」误判成打转）、
  **一轮里的多个调用逐个记**（模型会把卡住的那个和一个新调用捆在一起发）。
  ⚠ 它判的是**重复**不是**无进展**——一个每轮都在做新鲜事却毫无意义的模型它抓不到，
  那需要语义判断。⚠ 也**不是安全机制**：模型让每次调用略有不同就能绕开它，
  它的职责是止损。
- **结构化系统提示**：八个固定提示模块走稳定可缓存通道（第八个「外部不可信内容」随 web_fetch 扩展加入、按 `web_fetch_enabled` 开关注入，关闭时输出与加入前逐字一致），环境信息与 Plan Mode 提醒通过 `<system-reminder>` 作为动态补充注入。
- **网络访问**（web_fetch 扩展，不占章节号）：给一个 http/https 地址与一段「要提取什么」的说明，取回正文并按提问抽取要点。**实际行为与边界**：

  **权限**：新增**②′网络边界层**，排在②路径沙箱之后、③可配置规则**之前**。它做两件事——
  ① **结构性硬校验**（不可被任何配置或权限模式放开）：协议只许 http/https（`file://` 会绕过路径沙箱）、拒绝内嵌凭据、拒绝非全局可路由地址（判据是**白名单式**的 `not is_global` + 显式还原 IPv4-mapped/6to4/NAT64 + 补判组播与保留段——黑名单式枚举实测漏 CGNAT `100.64.0.1`、组播 `224.0.0.1`、6to4 封环回 `2002:7f00:1::` 三类）；② **域名策略求值**：deny 优先 → allow 命中放行 → **白名单已建立但未命中即拒**。

  **规则语法**：`WebFetch(domain:模式)`，与 `Bash(...)`/`Read(...)` 写在同一份 YAML 的同一组 allow/deny。`example.com` 不含子域；`*.example.com` 任意深度子域但不含裸域；`*` 全匹配；**非前导位置的 `*` 不跨点**（`example.*` 匹配 `example.org` 但不匹配 `example.evil.com`——跨点会让一条本意放行「各国域名」的规则连带放行攻击者可注册的域名）。写坏时按效果分两支、**两支都偏严**：allow 整条丢弃、deny **降级为整工具拒绝**。

  **⚠ 白名单只由「用户级 / 项目级」两层建立。** 在那两处写下任何一条 `allow: WebFetch(domain:...)`，就等于声明「只许访问这些」——此后未列出的域名一律被直接拒绝，`/perm` 切到放行档也翻不过来。而**本地级**（确认面板选「永久放行」自动写入的那份）、会话级、Skill 预授权**只放行、不建立白名单**。这是本项目对「层级不决定优先级」的**唯一一处例外**，理由：不区分的话，用户点一次「永久放行」就等于建立了只含一个域名的白名单，其它域名从「弹确认」变成「硬拒且永不再问」且界面上无从恢复；且 Skill 的 `allowed-tools` 会反向**收紧**，违反「只放宽从不收紧」这条既有承诺。
  **必须知道的一处不直觉**：本地级也是可手编的个人策略文件。同一条规则写进 `permissions.yaml` 会建立白名单、写进 `permissions.local.yaml` 不会。**要建立白名单，请写用户级或项目级。**

  **权限模式的例外**：放行档对 URL 类请求**不生效**（未建立白名单时仍弹确认）。理由是放行档对文件工具的后果被②沙箱兜住，而 URL 类在未建白名单时没有等价边界。连带后果：**无人值守场景下没有免确认的网络访问路径**，除非写文件级域名规则。

  **抓取行为**：只 GET（无请求体、无自定义头、无认证）；跨主机重定向**不跟随**（返回目标地址由模型再发一次，使每一跳都过完整判定），「同主机」判据是 `(scheme, host, port)` 三元组全等；**每一跳都重跑完整硬校验 + 域名解析结果校验**（否则 `https://a/x → http://user:pass@a/` 这类跳转会让协议与凭据限制对新地址失效）；单跳超时 30 秒、同主机跳数上限 5（即最多 6 次请求、上界约 180 秒——但**域名解析不在该上界内**，标准库解析函数无超时参数、`Esc` 也打断不了）；响应体上限 5 MiB；二进制类型**先看响应头就不读正文**，只回报类型与体量；字符集推断链为「响应头 → 文档内 `<meta>`（只扫前 2KB）→ 兜底 UTF-8」。

  **抽取与降级**：抓回正文截断到 `window // 4` 字符（夹在 4 000–100 000，**随 `context_window` 缩放**）后，发一次**独立的**模型请求按提问摘要（强制 `tools=None`、不进主历史、trace 作用域 `web_extract`）。抽取答案另有 8 000 字符上限（防被注入的页面诱导超长输出绕过前两道体量约束）。抽取超时/异常/空返回一律**降级**为「本地转换后的正文节选」（8 000 字符，低于任一工具自己的输出预算），并在结果里如实注明「这是原文节选而不是回答」。

  **不可信标注**：工具结果的正文——**无论抽取成功还是降级**——一律包在 `<untrusted-content source="...">` 里，元信息（来源/最终地址/内容类型/两类截断标志/是否降级）在标记**外**。「抽取不是消毒」：抽取模型读的是同一张可能被注入的页面，它完全可能把伪装成指令的文本如实转述出来。

  **总开关**：`config.yaml` 的 `web_fetch_enabled`（缺省 true）。关闭后工具不注册、系统提示不含那条约束、域名语法不校验也不产生警告——行为与本扩展之前逐字一致。

## 子 Agent 工作区隔离（c14）

- **什么时候会隔离**：角色 frontmatter 写了 `isolation: worktree`，或委派时传了
  `isolation: true`。合并方向是**单向加严**——角色声明了，模型在调用时关不掉。
- **位置与基点**：`<项目根>/.rhinecode/worktrees/<名字>`，分支 `agent/<名字>`
  （撞名自动追加 `-2`、`-3`……，**回报的是实际用的名字**），基于**当前 HEAD**。
  ⚠ **主项目根里未提交的改动不会带进去**——派活前该先把手头的东西提交掉。
- **名字**：目前一律由系统生成（`<角色名>-<8 位随机>`）。安全校验已备好
  （`/` 可嵌套，每段只许字母数字与 `.`/`_`/`-`，总长 ≤ 64，任何一段不得为 `.` 或 `..`），
  但模型给名字那条通路暂未开放。
- **隔离到什么程度**：它的路径沙箱根是那个工作区，因此读写主项目根内、工作区之外
  的任何路径都会在权限管线**第②层**被拒（相对上级、绝对路径、符号链接三种写法一致）。
  **例外只有只读白名单**（用户级记忆与 Skill 目录）——它们在任何工作目录下都可读，
  子 Agent 因此没有多拿到任何东西。
  ⚠ **两处管不住**：MCP 工具（落 `kind="other"`，无路径判定，且 Server 以主项目根启动）、
  `run_command` 子进程内部用绝对路径的访问。与已知项 #4 同源。
- **建不出来怎么办**：委派**直接失败**，回灌的文案里点名原因（非 Git 仓库 / git 不可用 /
  名字非法）并明确写「不要重试」。**绝不降级为在主项目根里跑**。
- **环境初始化**：只按 `config.yaml` 的 `worktree.copy` / `worktree.link` 清单执行，
  缺省为空。来源必须在主项目根内且存在，否则跳过并记警告；`link` 建符号链接失败时
  **降级为复制并留警告**（Windows 上常需额外权限，静默降级会让「配了 link 却复制了
  500MB」无处可查）。单条失败从不导致创建失败。
- **git hooks**：原生共享（实测主项目根与工作区的钩子目录是同一个），本章不做任何配置。
- **结束时**：无任何变更（无未提交改动**且**无新增提交）→ 目录与分支一并回收；
  否则保留。结论末尾由**系统**追加一段交付信息（分支名、基点、路径、提交数、
  改动文件、有无未提交改动），取自对版本库的实际查询而非模型自述。
- **启动清理**：只在启动时扫一次（无后台定时器、无手动命令）。过期以「目录内文件的
  最近修改时间」计，阈值 `worktree.cleanup_days` 缺省 7 天、0 或负数为关闭。
  ⚠ **过期只决定「要不要考察」，不决定「能不能删」**：有未提交改动的**永远不删**；
  有提交、无未提交改动的删目录、**保留分支**，并在启动提示里列出分支名。

## C16 命令与网络的分类器审查

**在哪一格生效**：权限管线跑完之后，只有同时满足三条才调分类器——分类器已启用、
工具声明了 `classifier_scope`、**结论来自第④层**。其余全部请求逐字不变。

- **覆盖哪五类**：`run_command`（命令）、`web_fetch`（网络）、`send_message`（队友消息）、
  `web_search`（**网络搜索**，web_search 扩展新增）、
  `mcp_add_server`（**MCP Server 启动**，2026-09-01 新增）。
  文件的读写查搜、**MCP Server 提供的工具**（`mcp__<server>__<tool>`）、委派、
  Skill 加载、共享任务清单**一律不进**。
  ⚠ 最后那一类的审查口径与其余四类**不同**：其余四类问的是「这个动作本身危不危险」，
  而 `mcp_add_server` 的 `command` 通常是一条人畜无害的 `npx -y <包名>`——真正要判的是
  **「用户有没有在对话里要求过引入这个 Server」**，即那个包名是不是助手自己编的。
  为此它的待判段落**显式撤销**了共用系统提示里那条「『这个动作和用户要的不完全一样』
  不是拦截理由」——那条对其余四类都对，对这一类恰好把唯一的判据关掉了。
- **`deny` 与 `allow` 的效力**：③层排在④之前，所以 `deny` 压得过分类器；
  `allow` 命中时**分类器零次调用**（连模型请求都不会发出）。只读工具走只读短路，
  同样零次调用。
- **两阶段**：第一阶段要求只输出一个词，判「不可疑」即放行、**第二阶段零次调用**；
  判可疑或**输出解析不出来**才进第二阶段做带理由的复核。
  ⚠ 第一阶段解析不出来**不算失败**——第二阶段是一次真正的补救，而放行的路径
  仍然只有「明确返回不可疑」一条。
- **喂什么**：用户消息（全部，**不截断**）+ 模型发起过的工具调用及其参数（**不截断**）
  + 待判动作 + 工作目录。**不喂**模型正文与任何工具输出。
  提示词排布是「系统提示 → 用户消息 → 历史工具调用 → **待判动作（最后）**」，
  使连续两次判定的前缀逐字相同、可命中 Provider 的前缀缓存。
- **子 Agent**：与主对话**共用同一个分类器实例**（熔断计数因此是全局的），
  但**用户消息取自主对话历史**——子 Agent 自己的「任务描述」是主模型写的，
  当成用户的话等于让模型给自己签授权书。隔离子 Agent 的工作目录如实传入。
- **五类的落点**：

  | 分类器 | 命令 | 网络 | 消息 | 搜索 | Server 启动 |
  | --- | --- | --- | --- | --- | --- |
  | 放行 | 照常执行 | **不再弹面板**、直接执行 | 照常投递 | **不再弹面板**、直接执行 | **不再弹面板**、直接执行 |
  | 拦下 | 拒绝、不弹面板 | 拒绝、不弹面板 | **不投递**、不弹面板 | 拒绝、不弹面板 | 拒绝、不弹面板 |
  | 失败（未熔断） | 拒绝 | 拒绝 | 不投递 | 拒绝 | 拒绝 |
  | 失败（已熔断） | **弹面板** | **弹面板** | **一律投递** | **弹面板** | **弹面板** |

  ⚠ 网络、搜索、Server 启动那三格的「放行」是**放宽**：它们的④层基线本来就是 ASK。
  这三类的基线取 ASK 而不是 ALLOW 正是为了让最后一行成立——基线若是 ALLOW，
  熔断后会退回**一律放行**，那条防线在故障时完全消失。
  ⚠ 启动类还多一条代价要记住：判放行的那条路上**分类器是唯一的一道**
  （①②②′②″对这类动作一层都碰不到，而面板已被它去掉）。这是评审时明知并接受的。
- **回灌与展示**：给模型的是固定文案（不含具体理由——那是绕过指南），
  完整理由只走界面的**警告级**系统行与行为记录。消息类的文案额外写明
  **投递没有发生、待命的收件人没有被唤醒**。
- **缓存**：**只有网络类**，键是主机名 + 端口（不含路径与查询参数）。
  **启动类同样不缓存**——每一次添加都是**另一个**外部程序，复用结论毫无意义。
  **搜索类刻意不缓存**——查询词几乎每次都不同，命中率接近零，而一旦命中反倒意味着两条不同的查询共享了同一条结论。
  放行结论用到「有新内容进入对话」为止（下一轮迭代），拒绝结论到本次运行结束。
  命令类与消息类每次都重新判定——同一条命令在不同上下文下的安全性不同。
- **熔断（三个阈值固定不可配置）**：连续拦 3 次或累计拦 20 次 → 拦截熔断；
  连续调用失败 3 次 → 失败熔断（失败**不计入**拦截计数）。
  任一放行重置连续拦截计数；用户在面板上批准一次即恢复。
  两种熔断都产生可见的系统行，失败熔断带上**最后一次的错误原文**。
- **宽泛放行规则**：启用时从**文件规则集**里丢弃三类命令放行规则
  （整工具通配 / 解释器 + 通配 / 包管理器 run 类）**外加 `allow: WebSearch`**，
  并逐条告知；会话级与本次执行级规则不动，域名规则不动。
  `Bash(git *)` **刻意不在清单内**；`WebSearch(...)`（带括号）也不丢——
  它本来就不命中任何调用，丢一条本来就无效的规则只会让人以为它原本生效过。
  ⚠ 搜索那一条由 `search.enabled` 把门：**关掉的能力不该影响用户的规则文件**。
- **配置**：`classifier.enabled`（缺省 **开**，非法值**抛错**）、
  `classifier.model`（留空 = 跟主对话同一个）、
  `classifier.timeout`（缺省 10 秒，非法值**回退默认**；超时按调用失败处理，
  且超时是**交给 SDK 客户端**的，不是在调用方计时）。
  关掉之后三类动作与本章之前逐字一致，被丢弃的规则全部恢复。
- **失败绝不拖垮主流程**：一切异常、超时、解析失败都收敛成「未得出结论」，
  绝不外抛——它跑在决策预扫里，抛出去会让整轮工具执行炸掉。
- ⚠ **转录会污染后续判定，这是双向的**（2026-08-20 实测）。判定每次都从对话里
  重读用户消息，于是：① 早期的**边界声明**会随上下文压缩而失效；
  ② 早期消息里的**敏感内容**会一直影响后续判定、且不随时间衰减——
  用户提过一次密钥样式的字符串之后，完全无关的动作也可能被以
  「用户曾提到过那个密钥」为由拦下。实测样本见
  [`docs/extensions/web-search/acceptance.md`](../extensions/web-search/acceptance.md)
  第七节。用户侧唯一的解法是 `/clear`。
- **已知边界**：长对话里用户声明的边界会随上下文压缩而失效（要硬保证请写 `deny` 规则）；
  基于分隔符看不见的命令替换同样看不见；分类器本身会误判
  （官方公布的数据是拦下 89% 的危险命令，人工批准只拦下 14%）；
  一条全域名放行的网络规则会关掉网络这一侧的分类器（只提醒、不丢弃）；
  共享任务清单是一条未被审查的窄通路。

工具调用、Plan Mode 与权限系统目前仅在 `protocol: deepseek` 且启用默认工具注册中心时可用；MCP 工具随内置工具一同仅在该模式下暴露。


## 网络搜索（web_search 扩展）

**生效范围**：仅 `protocol: deepseek` 且启用默认工具注册中心。缺省**启用**，
但缺省**没有密钥**——此时工具照常注册，模型每次调用拿到一条「不是临时故障、
不要重试、请让用户去配置」的说明，同时启动时对用户单独提示一条。

- **接口**：`query`（必填，自然语言）+ `count`（可选，缺省 5，夹取到 **1–10**）。
  越界只夹取、不报错。**没有第三个参数**——没有语言、地区、时间范围、请求头。
  ⚠ 但**不能把这条写成「只取不发」**：查询词本身就是发出去的数据。
- **返回**：每条三项（标题 / 地址 / 摘要），整份包在 `<untrusted-content>` 里，
  元信息（查询词 / 服务商 / 条数 / 配额）在**标记之外**。
  **不再经过一次抽取模型**——结果本来就短，多一次往返只是多一条失败路径。
- **配额**：`search.session_quota` 缺省 **50 次 / 会话**，0 或负数 = 不限制。
  **只有真的发出了请求才计数**：无密钥 / 已耗尽 / 被分类器拦 / 被规则拒 / 服务失败
  这五种都不计（服务失败那次会**退回**已预留的名额）。
  主对话与全部子 Agent **共享一份**（额度是钱），`/clear` 复位。
- **四类降级路径**（文案刻意写得不一样，否则模型会一律重试）：

  | 情形 | 模型该怎么办 | 成功标志 |
  | --- | --- | --- |
  | 未配置密钥 | **不要重试**，让用户去填 `search.api_key` | 假 |
  | 配额用完 | **不要重试**，用已有信息继续 | 假 |
  | 服务不可用 / 超时 / 响应结构不认识 | **可以换个说法重试一次** | 假 |
  | 搜到 **0 条** | 换个关键词再试 | **真** |

  ⚠ 最后一行与第三行在 HTTP 层看不出区别，靠解析函数的**三态**区分：
  `None` = 结构不认识（失败、不计配额），`[]` = 确实没搜到（成功、计配额）。
  合并两者会让一次解析故障伪装成「这个词搜不到」。
- **权限**：规则只支持**不带括号**的 `WebSearch` / `deny: WebSearch`。
  第④层放行档下判 **ASK**（与网络类同格，但理由文案不同——搜索**没有域名白名单
  这回事**），再由分类器覆写。①②②′②″**四层都不生效**（按请求种类早退）。
  确认面板**不给「永久放行」**：它写的文件级规则会被分类器的丢弃规则清掉，
  点了下次还弹。
- **端点**：`search.endpoint` 留空 = 服务商官方地址。**必须是 http/https**
  （`file://` 之类启动时直接报错，与②′的协议限制同性质）；非 https 出一条启动警告
  但不阻断——内网搜索代理用 http 是合法场景。**端点刻意不过②′的地址范围校验**，
  否则内网代理用不了。
- **服务商**：`bocha`（博查，**缺省**）与 `brave`（Brave Search）。
  写错服务商名**抛错**（它决定数据发给谁）。
  ⚠ **缺省是博查而不是 Brave**：本项目是中文、只针对 DeepSeek、主力网络环境
  连不通境外服务（本机 DNS 把公网域名重写成 10.x），把缺省定在一个连不上的
  服务商上是个坏缺省。
  两家的传输形态**不同**——Brave 是 `GET` + query 参数 + 裸 token 头，
  博查是 `POST` + JSON body + `Bearer` 头；`SearchProvider` 的 `method` /
  `auth_prefix` 两格就是为此而加（接第二家时才发现原接缝假设了所有 API 都是 GET）。
- **配置口径**：`enabled` / `provider` **非法值抛错**；
  `max_results` / `session_quota` / `timeout` **回退默认**。
- **关掉之后**：工具不注册、系统提示里的不可信约束按「web_fetch 或 web_search
  任一启用」重新判定、`allow: WebSearch` 不再被丢弃、启动提示不产生。
