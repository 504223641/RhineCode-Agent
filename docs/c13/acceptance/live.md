## 预置

`tests.e2e.scripts:seed_subagents` 造了一个小项目：同一个常量 `RETRY_LIMIT`
散落在 `src/config.py`（定义）、`src/client.py`、`src/worker.py`（引用）、
`tests/test_client.py`（注释）四处。外加一个**项目级**只读角色 `auditor`。
**刻意不预置任何 allow 规则**，好让权限边界成立。

## 场景 3 —— 权限边界

输入：
> 让 auditor 去检查一下 tests/test_client.py 那个空壳测试，并且**直接把它补全**……

| 机器判到了什么 | 据此做的判断 |
| --- | --- |
| `subagent_start role:auditor`（项目级角色），子 Agent 跑 3 轮、**全部工具调用都是 read_file / glob_files**，一次写入尝试都没有 | AC2 的实跑印证：项目级角色真的被用上了。且只读约束生效 |
| 随后 `main` 作用域出现 `tool_pending write_file` + `permission_decision write_file → ask（④模式）`，弹出确认面板 | **写入被路由回了主对话**，人在回路照常生效 |

## 首跑抓出的缺陷（已修，`fafeef7`）

**`parent_snapshot()` 产出的父快照以一条无配对的 `assistant(tool_calls)` 结尾。**

`parent_snapshot()` 是从 `RunAgentTool.execute()` 调进来的，而那运行在 Agent Loop
的**串行段内**——此刻循环已经把 `assistant(tool_calls)` 追加进 `history`
（`loop.run` 在分流执行之前就追加了），而对应的 `tool` 结果消息要等本轮全部工具
跑完才追加。于是快照必然以未配对的那一条结尾，API 直接 400。

**这个形态是结构性必然的，不是偶发**：`run_agent` 自己那次调用永远是未配对的
那一条，所以**每一次分支式委派都会失败**。

**为什么 20 项单元测试没抓到它**：那些测试都是从一段干净的历史建快照，
压根构造不出「跑到一半」的形态。这是「必须用真实链路验」的一个具体例证。

**修法**：复用 `memory/session.py` 已有的 `drop_unpaired`（它给会话存档载入用，
语义完全一致），转公开名后在 `parent_snapshot` 里调用。补了两条护栏：
一条刻意重现「跑到一半」的形态；另一条是反证——配对完整时不得误删。
