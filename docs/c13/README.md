# C13 子 Agent 系统

**一句话**：让主 Agent 把子任务委派给独立上下文的子 Agent，只拿回结论——
一次「找出项目里所有用到 X 的地方」不再把二十个文件的内容堆进主对话。

## ⚠️ 术语：本章的「分支式」与 C11 的 `context: fork` 语义相反

两处都叫 fork，但方向恰好相反，**读文档时必须分清**：

| | C11 的 `context: fork` | C13 的 `type: branch` |
| --- | --- | --- |
| 子对话的初始历史 | **空白**（只有一条自包含的 Skill 调用文本） | **继承父对话的完整历史快照** |
| 谁承载它 | 一个写好的 Skill | 模型临时委派，无需任何定义 |
| 阻不阻塞主对话 | 同步阻塞 | **强制后台** |

因此 spec 里一律写「定义式 / 分支式」，不用 fork 这个词。
trace 作用域也刻意分开：Skill 子对话是 `isolated:<name>`，子 Agent 是 `subagent:<name>`。

## 七个由用户拍板的设计决策

它们决定了本章的形态，读代码前先看这几条：

1. **全程非交互**——子 Agent 的工具调用判 ASK 时一律自动拒绝，永远不弹面板。
   代价写在 spec F15：**缺省配置下子 Agent 实际只能做只读的事**。
2. **权限只能收紧不能放宽**——实际生效档位 = min(主对话档, 角色声明档)。
   与 C12「Hook 只能收紧」同一条原则，安全论证直接沿用。
3. **结论完成即注入全文**——追加进主历史（不是一次性的系统提醒），
   因此模型在第三轮、第五轮仍能引用它。
4. **界面只占一行任务状态**——子 Agent 内部的工具行与正文不渲染，只进 trace。
   由此定死线程模型：子 Agent 一律独立线程，「前台」只是主 Worker 选择阻塞等待。
5. **系统提示照 Claude Code 口径**——只给角色正文 + 环境信息，不给八模块。
   一处例外：工具集含网络访问工具时追加「外部不可信内容」段。
6. **Hook 工具级全量生效**，复用回合级事件，不新增事件类型。
7. **只内置 `explorer` 一个角色**（只读调研）。

## 实现期发现的三处「必须改既有代码」

读 plan 之前先知道这三条，它们都是**界面上完全看不出来**的那类问题：

1. **`PermissionEngine` 的 `mode` / `turn_rules` 是可变字段且实例共享**。
   子 Agent 若为了落实自己的档位去写 `engine.mode`，改掉的是**主对话的档位**——
   而它跑在后台线程里。故新增 `derive()`。
2. **Agent Loop 现有的 ASK 拒绝路径对子 Agent 是错的**：它回灌
   「这是用户的决定，不要重试不要绕」（可子 Agent 面前没有用户），
   并硬性禁掉下一轮的全部工具（它应该改用只读方式继续）。故新增
   `RunOptions.interactive` 与独立的回灌文案。
3. **`ContextManager` 持有无锁的估算锚点**，并发共享会互相污染。
   故每个子 Agent 一个新实例。

## 本章刻意保留的一处「空实现」

`toolset.BACKGROUND_DENIED_TOOLS` 是**空集**，不是没写完。

Claude Code 里这一层的存在理由是「后台 agent 无法交互，因此摘掉需要交互的工具」；
而本章已定为全程非交互，前台与后台面对的约束完全相同。保留结构位置但不填内容，
是为了不造「同一个角色在两种场景下行为不同、而用户从配置上看不出来」的人为差异。
`tests/test_subagent_toolset.py::BackgroundLayerTest` 有一条断言钉住「前后台结果一致」。
