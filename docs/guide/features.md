# 完整能力清单

> RhineCode 用户手册 · [返回手册目录](README.md) · [返回项目 README](../../README.md)

## 功能

- **Skill 系统**（已对齐 Agent Skills 开放标准）：把可复用的 AI 操作封装成 Markdown 文件，三级存放同名覆盖；启动只注入名字与说明、用时由 `load_skill` 按需加载完整 SOP；`context: fork` 可开子对话只回流结论；`allowed-tools` 是**预授权**（列出的操作免确认，不限制模型能调什么）；自动注册 `/<name>` 短命令并进 Tab 补全，`/skills reload` 热更新；内置 commit / review / test 与 skill-creator 四个样板。详见 [Skill 系统](skills.md#skill-系统)。
- **Hook 系统**：在生命周期的固定节点上挂**你自己声明**的自动化动作。一条规则 = 事件 + 条件（可省）+ 动作，写在 `hooks.yaml` 里。十二个事件覆盖会话 / 回合 / 消息 / 工具四层加三个系统级；四种动作（跑 shell 命令 / 注入提示词 / 发 HTTP / 子 Agent 占位）；`once` / `async` / `timeout` 三种执行控制。`pre_tool_use` 可以**拦截**工具调用——但它**只能收紧不能放宽**（没有 allow）。`/hooks` 查看规则与触发情况。详见 [Hook 系统](hooks.md#hook-系统)。
- **子 Agent 系统**：主 Agent 可以把子任务**委派**给独立上下文的子 Agent，只拿回一段结论——一次「找出项目里所有用到 X 的地方」不再把二十个文件的内容堆进你的对话。角色用 Markdown + frontmatter 定义（工具白黑名单、模型、轮次上限、权限档位），三级存放同名覆盖。委派**永不阻塞**，多个子 Agent 天然并行；结论跑完后自动回到主 Agent 手里，不需要你插话。子 Agent 的能力**只会比主对话小**（工具集三层过滤、权限只能收紧、判 ASK 一律自动拒绝）。`/agents` 查看角色与任务。详见 [子 Agent 系统](subagents.md#子-agent-系统)。
- **子 Agent 工作区隔离**：给角色加一行 `isolation: worktree`，它的每次委派就在一个**独立的 Git 工作目录**里跑（`.rhinecode/worktrees/<名字>`，共享版本库、各自一个分支、基于当前 HEAD）。这样你手上改到一半的文件和子 Agent 改的文件**不会互相覆盖**，成果通过一个分支交回来、你 `git merge` 收下。隔离是**物理的不是约定的**——它的每一次路径请求都在权限管线第②层以它自己的工作区为界量过，越界一律拒绝。**创建失败就明确失败、绝不降级成不隔离**；结束时没变更就自动回收，启动时清理过期的（**有未提交改动一律不删**）。详见 [工作区隔离](subagents.md#工作区隔离)。
- **ReAct Agent Loop**：自动执行“调用模型 → 执行工具 → 回灌结果 → 再调用模型”的多轮循环。
- **流式输出**：正文与思考内容逐块渲染，后台 Worker 不阻塞 TUI 主线程。
- **DeepSeek 工具系统**：支持读文件、glob 找文件、grep 搜内容、写文件、精确编辑文件、运行命令；大文件读取需要显式行范围，文件发现类工具会逐文件尊重 `Read(...)` deny 规则。
- **MCP 客户端**：启动时按配置连接外部 MCP Server（stdio 子进程 / Streamable HTTP），自动发现并注册其工具（以 `mcp__<server>__<tool>` 为基础命名，必要时规范化为安全 function name），Agent 调用时无感；也支持用户直接说“帮我添加 context7 MCP”，由 Agent 解析候选、写入配置并在当前会话中重载；多 Server 连接缓存与隔离，单个挂掉不影响其它；底部状态栏显示连接状态，`/mcp` 查看明细。
- **记忆系统**：三层 RHINE.md 项目指令（用户级 → 项目 `.rhinecode` → 项目根，支持 `@include` 展开，`/init` 可让 Agent 探索项目自动生成）；每条消息即时 JSONL 存档，`/resume` 弹出交互式会话选择面板（上下键/回车/Esc，锁定会话与当前会话置灰跳过），载入后聊天区清空并回放全部历史、后续消息追加进该会话，`rhine --continue` 启动恢复同样回放；Agent Loop 自然停止后异步生成四类记忆（用户偏好/纠正反馈/项目知识/参考资料），索引注入系统提示、正文按需读取；多实例锁文件防护；`/memory` 查看全部状态。RHINE.md 与会话存档/恢复对所有 Provider 生效，自动记忆与 `/init` 仅 DeepSeek 工具模式。
- **网络访问**：`web_fetch` 工具让模型能读取公开网页——你在对话里给一个地址（「抓一下 https://… 」），它取回正文并按你的提问抽取要点。**只取不发**（无请求体、无自定义头、无认证）。权限上新增**②′网络边界层**：协议与内网地址的硬校验不可被任何配置或模式放开；域名用 `WebFetch(domain:...)` 规则控制，**且该限制翻不过 auto 模式的放行档**。抓回的内容一律被标注为外部不可信数据。可用 `web_fetch_enabled: false` 整体关闭。
- **上下文管理（两层压缩）**：每轮请求前近似估算历史用量（锚点+增量）；第一层把过大的工具结果存盘、历史只留预览与路径；第二层在逼近窗口时调 LLM 把较早消息压成五段式结构化摘要、近期原文保留，并提示模型细节需重读文件；连续失败 3 次熔断，用户原文永不改写；`/context` 查用量、`/compact` 手动压缩，状态栏常驻用量指示。窗口大小由 `context_window` 配置（默认 65536）。
- **五层防御权限系统**：每个工具执行前由 `permission/` 包的纯逻辑引擎按固定顺序计算决定——①危险命令黑名单（不可被任何配置/模式放开）→ ②路径沙箱 → ③可配置规则（`Tool(模式)`，deny 永远优先）→ ④权限模式（严格/默认/放行；**缺省是放行档，运行期不可切换**）→ ⑤人在回路（确认面板四选项）。

- **保护路径 ②″**：`.rhinecode/` 下的配置（`permissions.yaml` / `hooks.yaml` / `mcp.yaml` / `agents/` / `skills/` / `memory/`）与 `.git/` 的**写入一律要你过目**——它们决定「以后会发生什么」，模型不该悄悄改自己的规则。它是**出口处的收紧器**：跑完上面五层之后，命中保护路径且结论不是「拒绝」时统一升级为「问用户」，因此**任何 `allow` 规则、任何权限档都消解不掉它**，也没有开关能关掉它。判定以**调用者的工作目录**为准，所以子 Agent 的隔离工作区（C14）完全不受影响。这个场景的确认面板**不提供「永久放行」**（那个选项写的是③层规则，而③层压不过本层，留着它就是一个点了没用的按钮）；「本会话放行」只记在内存里、精确到那一个文件，**不写任何配置文件**。⚠ 它管不住 `run_command` 跑起来的命令（`echo >> .rhinecode/hooks.yaml` 绕得过），那与 OS 级沙箱是同一个已知缺口。
- **可配置权限规则**：三层 YAML（用户级、项目级、本地级）声明 allow/deny；跨层合并后 deny 优先求值。
- **两个运行模式**：`Shift+Tab`（或 `/mode`）在 **auto** 与 **plan** 之间切换。`auto` 放手干活——工作区内的文件写入与命令执行都不弹面板；`plan` 先只允许只读调研和需求澄清，完整计划进入聊天记录，经用户批准后才进入执行阶段，**获批后自动回到 auto**。
- **人在回路确认**：判定为「问用户」时弹出内联确认面板，四选项——本次放行 / 本会话放行 / 永久放行 / 拒绝；计划获批不等于免确认。
- **明确停止原因**：支持自然完成、迭代上限、用户取消、计划拒绝、连续未知工具、流错误等停止路径。
- **Textual TUI**：历史区（含会话历史回放）、命令提示、工具行、彩色 diff、确认/澄清/会话选择面板、输入框和状态栏组合成终端界面。
- **结构化系统提示**：全局提示按身份、约束、任务模式、工具使用等模块拼装，稳定内容走可缓存通道，环境信息与 Plan Mode 提醒走 `<system-reminder>` 动态注入。
- **子 Agent 协作**：让 C13 那些互不相识的子 Agent **能一起干活**。三件事：一块所有人读写同一份的**共享任务看板**（任务带认领人与依赖，被挡住的谁都认领不了，队员据此自我调度）、**点对点消息**（按名字发，推送式送达、没有「查收件箱」这回事，队员之间直接说话不必经主 Agent 中转）、**唤醒续跑**（队员干完不消失而是待命，一条消息就把它从原上下文叫醒接着干，不必重新委派、不必重新交代背景）。主对话也在花名册上（叫 `main`），空闲时收到消息会**自动跑一轮**处理它——那一轮判「需要确认」的操作一律自动拒绝、确认面板一次都不弹，并有连锁上限防止两个 Agent 互相唤醒到天亮。队员之间**能说话但不能招人**（委派与 Skill 加载工具对子 Agent 仍然关闭）。`/tasks` 查看看板。详见 [子 Agent 协作](subagents.md#子-agent-协作)。
- **命令与网络的分类器审查（C16）**：给四类动作在执行前接一个**独立的分类器模型**——跑命令、访问网络、给队友发消息、上网搜索。它接在权限管线**第④层**（排在③之后），因此你写的 `deny` 仍压得过它、你写的 `allow` **直接短路**它（连模型调用都不会发生）。**两阶段判定**：先一次只输出一个词的快速过滤，只有被标记的才做带理由的复核，绝大多数日常命令只花一个 token。它**只喂用户消息 + 模型发起过的工具调用**，剥掉模型正文（防它说服分类器）与全部工具输出（外部内容从那里进来）。拦下或失败一律**拒绝**，给模型的是固定文案（具体理由是绕过指南，只给你看）；连续拦 3 次或累计 20 次、或连续失败 3 次即**熔断**并明确告知。⚠ 启用时会**丢弃过宽的命令放行规则**（`Bash(python *)` 这类等于对该类关掉整层）并逐条说明是哪一条、为什么。
- **网络搜索 `web_search`**：给一句话，返回若干条「标题 / 地址 / 摘要」。搜索给**路标**，`web_fetch` 才**取货**。⚠ 它与 `web_fetch` 最本质的差别是**往外发的是什么**：后者只发地址、且受域名白名单约束，前者发的是**你的问题本身**，原样进第三方服务商的日志。三道对冲全都依赖判断、没有一道是硬边界（工具描述里的约束、分类器审查、面板上完整不截断的展示）。真正的硬边界只有两个：`deny: WebSearch`（⚠ **必须不带括号**，带括号的写法一律不生效**且没有任何警告**）与配置里的 `search.enabled: false`。另有**会话级配额**（缺省 50 次，`/clear` 复位）。
- **主对话的待办清单 `todo_write`**：多步任务开工前模型列几条，做的过程中逐条更新，你在历史区**最底下**一直看得到「还剩什么」。接口是**整表覆写**（主对话只有一个写入方，不存在 lost update）。⚠ 三条约束：**规划阶段不可用**（清单一出现看起来就是「已经开始动手了」，而 Plan Mode 的承诺是「批准前不动手」）、**同一时刻只能有一条 in_progress**、**不许从 pending 直接跳到 completed**（不限制的话模型会一次全标 in_progress，然后中途一次不更新、最后一次性全标完）。⚠ **子 Agent 拿不到这个工具**（它们的进度已有活动区），**你也不能手动改**（整表覆写下模型下一次提交会把你的改动整个抹掉）。
- **澄清提问面板 `ask_user`**：模型卡在「有好几种都说得通的做法」上时，**任何阶段**都能弹面板让你点一下，而不是在正文里写一串问句然后干等你手打一大段。一次 1–4 个问题（串行弹）、每题 2–4 个候选项带说明、可多选，末尾由界面无条件追加一项「其它…」进自由输入。它的可见性判据是**「有没有人可问」**（即本次运行拿没拿到澄清回调），因此子 Agent 与无人值守轮**结构性地**看不到它。⚠ `Esc` 的语义按阶段分岔：规划阶段是「不想规划了、整轮停止」，其余任何时候是「我不选，你自己定」并继续跑，且一次运行里跳过 2 次即熔断、不再打扰。
- **行为记录（trace，测试设施）**：`--trace` 开启后，把运行中「实际发生了什么」按时间顺序写成三十一类结构化事件的 JSONL——模型收到的完整请求与响应、每次权限判定走到第几层、每个工具的参数结果耗时、界面上出现过的每行文字、上下文压缩与 Skill 激活的每次变化。配一个只读 CLI 阅读器（时间线摘要 / 按类型与作用域过滤 / 展开单条）。**内容完整、不做任何截断**——观测设施一旦自作主张地丢内容，从它得出的每个结论都要打折（读的人无从判断被切掉的部分里有没有答案）；少数工具会为省 token 裁剪给模型的那份输出，完整原文另存进记录。**缺省关闭且零侵入**：不开时链路上不存在任何中间层、不写一个字节；开启也只观测、不改变任何权限判定。用来验收既有能力，以及排查那类「界面上看不出、但行为确实不对」的问题。⚠️ 代价是产物可能很大（每次请求都携带完整历史），敏感性见下方安全须知。

> 工具调用、Plan Mode 与权限系统目前仅在 `protocol: deepseek` 且启用默认工具注册中心时可用；记忆系统的 RHINE.md 注入与会话存档/恢复对所有 Provider 生效。
