# RhineCode 工具系统 Spec

## 背景

RhineCode 当前是纯对话 MVP（c1/c2）：三层架构（TUI / ConversationManager / Provider），支持 anthropic/openai/deepseek 三个 Provider 的流式对话、思考模式、斜杠命令，但模型只能“动嘴”——无法读写文件、执行命令、检索代码。

c3 给 RhineCode 装上**工具系统**，让模型从聊天机器人变成能干活的 Agent：模型在回复中表明要调用哪个工具，RhineCode 执行后把结构化结果回灌对话历史，模型据此自动给出一次最终回答。本章聚焦 **DeepSeek** Provider（OpenAI 兼容协议，工具调用走 `tool_calls` 流式 JSON 碎片拼接）。

## 目标

- 定义统一的 Tool 抽象接口（名称 / 描述 / 参数 Schema / 执行方法），所有工具实现它
- 实现六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容
- 提供工具注册中心：集中登记、按名查找、转成 DeepSeek/OpenAI API 认得的工具列表
- DeepSeek Provider 能解析流式工具调用（拼接 JSON 参数碎片），执行后把结果回灌历史并自动触发一次最终回答
- 工具执行带超时与错误处理，失败包成结构化结果返回给模型（而非崩溃）
- 写/改文件、执行命令前在 TUI 弹 Yes/No 确认；只读工具不确认
- 改文件采用原文唯一匹配替换，匹配不到或匹配多次时给出清晰报错供模型重试
- 单次响应含多个工具调用时，并发执行只读工具、串行执行有副作用工具，避免资源冲突
- 工具执行期间实时显示耗时并以颜色区分执行中/完成/失败
- **本章不做**跨轮 Agent Loop（模型看到结果后即便想再调工具也不自动循环）

## 功能需求

- F1（Tool 抽象接口）：定义统一的工具接口，每个工具暴露四项元信息——名称、面向模型的描述、参数 Schema、执行方法；执行方法接收解析后的参数，返回结构化结果。

- F2（读文件工具）：给定文件路径，返回文件文本内容；文件不存在、路径是目录、读取失败时返回结构化错误。

- F3（写文件工具）：给定文件路径和内容，将内容写入文件（覆盖或新建），必要时创建父目录；返回成功结果或结构化错误。属于有副作用工具，执行前需确认。

- F4（改文件工具）：给定文件路径、原文片段、新片段，在文件中以**唯一匹配**方式将原文替换为新文；原文匹配 0 次或多于 1 次时返回清晰报错（说明匹配次数），供模型调整后重试；成功则写回文件。属于有副作用工具，执行前需确认。

- F5（执行命令工具）：给定 shell 命令，在项目工作目录下执行，捕获标准输出、标准错误和退出码并结构化返回；命令超时或执行异常时返回结构化错误。属于有副作用工具，执行前需确认。

- F6（按模式找文件工具）：给定 glob 模式，返回匹配的文件路径列表；无匹配时返回空结果而非错误。

- F7（搜代码内容工具）：给定正则/文本模式（可选限定文件范围），返回包含匹配的文件及匹配行；无匹配时返回空结果。

- F8（工具注册中心）：集中登记所有工具，支持按名查找；能把已注册工具批量转换成 DeepSeek/OpenAI API 所需的工具描述列表（含名称、描述、参数 Schema）。

- F9（流式工具调用解析）：DeepSeek Provider 在流式响应中识别工具调用，拼接分片到达的工具名与 JSON 参数碎片，流结束后产出完整的工具调用（工具名 + 解析后的参数 + 调用 ID）。单次响应可能包含多个工具调用，全部解析。

- F10（工具执行与结果回灌）：解析出工具调用后，按名查找并执行（有副作用工具先走确认）。模型通过单次响应返回多个工具调用来表达“并行意图”：RhineCode **并发执行只读工具**（读文件、找文件、搜代码）以提升效率，对**有副作用的工具（写、改、命令）串行执行**以避免对同一资源（尤其写操作）产生冲突。全部执行完成后，将每个工具的结构化结果按协议要求追加回对话历史，然后**自动再发起一次请求**，让模型基于结果流式产出最终文本回答。

- F11（执行前确认）：写文件、改文件、执行命令执行前，在 TUI 弹出 Yes/No 确认框，展示将要执行的工具与关键参数；选 Yes 执行，选 No 则把“用户拒绝执行”作为结构化结果回灌，模型据此给出回答。只读工具（读文件、找文件、搜代码）不弹确认。

- F12（工具调用的 TUI 呈现）：历史区可见模型发起的工具调用（工具名与关键参数）及其执行结果摘要，与普通文本回复在视觉上可区分。

- F13（错误隔离）：任一工具执行失败（异常、超时、参数非法、文件/命令错误）都被捕获并包成结构化错误结果回灌模型，程序不崩溃、TUI 保持运行。

- F14（工具执行实时计时与配色）：工具从开始执行到完成期间，TUI 实时显示已耗时（如“执行中… 3s”并随时间更新）；执行中状态用**橘色**字体，执行完成后该工具行变为**绿色**字体；失败时用既有错误色（红色）。

## 非功能需求

- N1（命令执行超时）：执行命令工具必须有超时上限，超时则终止子进程并返回结构化超时错误，不可无限期挂起阻塞界面。

- N2（不崩溃原则）：任何工具执行异常、API 错误、JSON 参数解析失败、流式中断，都不得使程序崩溃退出；统一转为可读的结构化错误或 TUI 错误提示，程序保持运行。

- N3（流式不阻塞 UI）：工具调用解析、执行、回灌后的二次请求、并发执行与计时刷新全过程，TUI 主线程不被阻塞，沿用现有 Worker + `call_from_thread` 的流式渲染机制。

- N4（结构化结果约定）：所有工具返回统一格式的结果（成功/失败标识 + 内容/错误信息），便于注册中心、Provider 回灌与模型理解；失败信息要对模型可读、可据此调整重试。

- N5（可扩展性）：新增工具只需实现 Tool 接口并在注册中心登记，无需改动 Provider、ConversationManager 与 TUI 的核心逻辑。

- N6（路径安全边界）：文件类工具与命令执行以项目工作目录为基准；本章不做沙箱隔离，但危险操作由 F11 的用户确认兜底。

- N7（确认交互不死锁）：确认弹窗在等待用户选择时不得卡死流式 Worker 或主线程，用户必须能正常选择 Yes/No 并让流程继续。

## 不做的事

- 不做跨轮 Agent Loop：模型基于工具结果给出最终回答后即停止；即便该回答里又包含工具调用，本章也不自动执行——自动循环留到下一章。

- 不支持 Anthropic / OpenAI 的工具调用：本章只让 DeepSeek Provider 具备工具能力；其余 Provider 维持纯对话，调用时不提供工具。架构上保留扩展口，实现留到后续。

- 不做沙箱 / 权限分级：文件与命令以项目工作目录为基准直接执行，危险操作仅靠 F11 用户确认兜底，不做容器隔离、路径白名单、命令黑名单等。

- 不做工具结果持久化与缓存：工具执行结果只回灌当前对话历史，不落盘、不缓存。

- 不做有副作用工具之间的并行：写/改/命令一律串行执行，靠串行（而非加锁）保证安全；本章不做细粒度资源依赖分析。

- 不扩充新的斜杠命令：本章不新增 `/think`、`/clear`、`/exit` 之外的命令。

- 不做工具的细粒度配置：超时时长、可用工具集等本章用合理默认值，不暴露为 YAML 配置项（留待后续）。

- 不做编辑工具的多片段批量替换：改文件工具一次只处理一组「原文→新文」的唯一匹配替换。

## 验收标准

- AC1（Tool 接口）：每个工具都能报出名称、描述、参数 Schema，并能用解析后的参数调用其执行方法返回结构化结果（验证：实例化任一工具，读取元信息并执行）。

- AC2（读文件）：对存在的文件返回其文本内容；对不存在路径返回结构化错误且不崩溃。

- AC3（写文件）：写入新文件或覆盖已有文件后，文件内容与传入内容一致；父目录不存在时能创建。

- AC4（改文件-唯一匹配）：原文在文件中唯一出现时替换成功；出现 0 次或多次时返回说明匹配次数的清晰错误，文件不被修改。

- AC5（执行命令）：执行一条简单命令能拿到标准输出、退出码；执行超长命令触发超时并返回结构化超时错误，程序不挂死。

- AC6（找文件）：给定 glob 模式返回匹配文件列表；无匹配返回空列表而非报错。

- AC7（搜代码）：给定模式返回命中文件与匹配行；无匹配返回空结果。

- AC8（注册中心）：注册中心能按名查到工具，并能输出 DeepSeek/OpenAI API 格式的工具描述列表（含六个工具）。

- AC9（流式工具调用解析）：DeepSeek 流式响应中分片到达的工具名与 JSON 参数碎片被正确拼接，产出完整工具调用；单次响应含多个工具调用时全部解析。

- AC10（单轮往返）：用户提问触发工具调用后，工具执行 → 结果回灌 → 模型自动再请求一次并流式给出最终回答 → 停止，不再自动执行后续工具。

- AC11（执行前确认-Yes）：写/改/命令工具执行前弹出 Yes/No 确认框并展示工具与关键参数；选 Yes 后正常执行。

- AC12（执行前确认-No）：确认框选 No 时不执行该工具，将“用户拒绝执行”作为结构化结果回灌，模型据此给出回答。

- AC13（只读不确认）：读文件、找文件、搜代码执行前不弹确认，直接执行。

- AC14（并发与串行）：单次响应含多个只读工具时并发执行；含多个有副作用工具时串行执行，写操作之间不产生冲突。

- AC15（实时计时与配色）：工具执行期间历史区实时显示已耗时且字体为橘色；完成后变绿色；失败显示为红色错误。

- AC16（错误隔离）：任一工具失败（异常/超时/参数非法/匹配失败）都被捕获为结构化错误回灌模型，TUI 保持运行。

- AC17（TUI 可见性）：历史区能看到模型发起的工具调用（名称+关键参数）与结果摘要，与普通文本回复可视觉区分。
