C14（子 Agent 工作区隔离）在分支 `c14` 上完成，2026-08-08 做完真实模型端到端验收
（DeepSeek，八个宿主会话），记录在 `docs/c14/acceptance/live-model.md`。
2001 项测试全绿。

**真跑抓出 7 个逻辑层测试与首轮验收都没抓到的问题**，全部已修并复验：
成果搁浅（主 Agent 会指使子 Agent「不要提交」）、Hook 负载 `cwd` 没跟着 Agent、
`worktree.link` 的软链被沙箱一律拒绝、搜索被 `.rhinecode/` 自身产物淹没并自放大、
子 Agent 环境信息段报主项目根、`/agents` 对已回收工作区仍报分支名、
「看不到你未提交的改动」没写进决策期文本。

**三条方法论教训**（下次验收直接照做）：

1. **验一个能力必须从模型实际会走的那条路上验。** 首轮把 `link` 判 ✅ 是因为用
   `Path.open` 直接读磁盘——而产品里没有任何路径是那样访问文件的，一切都过权限管线。
2. **一个字段有两处来源时，两处都要量。** 首轮 Hook 场景只量了子进程 cwd（对的），
   没量负载字段（错的）。
3. **单元测试验「代码做了它该做的」，真实模型验「模型会不会那么用」。**
   7 个里有 3 个属于后者：代码一行没错，是模型读到的文本让它走了岔路。
   这是 C11「Skill 欠触发」之后同一类问题的第三次。

「委派永不阻塞」的契约，改动前需单独决策）。
