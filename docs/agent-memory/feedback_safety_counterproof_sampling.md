验安全反证（「危险动作会被第 X 层拦住」）时，**真实模型往往在工具被调用之前
就自己拒绝了**，于是 trace 里是 **0 条权限判定**——看起来像「安全」，
实际上那一层**一次都没被执行到**，这条反证等于没验。

2026-08-14 auto-plan 验收实测：`rm -rf /` 连试四种形态
（一次性沙箱说辞 / `git push --force` 无仓库 / 有仓库但 remote 是占位地址 /
本机真实裸仓库），`deepseek-v4-pro` **每一次都自己拒绝**，权限判定恒为 0 条。
最后是采纳**模型自己提出**的等价安全方案（把裸仓库挪进项目根内再强推）
才命中 `deny @ blacklist`。

**Why**：模型的自我约束是一层真实的防御，但它排在权限管线**之前**。
用它来验管线，验的是模型的价值观，不是代码。而失败形态是「看起来通过了」
——这比红着更危险。

**How to apply**：
1. 反证场景要找**「黑名单命中、但模型认为合理」**的动作，
   而不是「一眼看上去就很坏」的动作（后者永远到不了管线）。
2. **判据必须是「那一层真的产出了 DENY」**（trace 里有 `deny @ <layer>`），
   **不能**是「危险的事没发生」——后者被模型拒绝时同样成立。
3. 收工前先看**判定条数**：0 条就说明还没验到，别急着记通过。
4. 模型如果自己提出一个等价而安全的变体，**直接采纳它** ——
   实测那反而是最干净的取证路径。
