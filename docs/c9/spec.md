# C9 记忆系统（项目指令 · 会话存档 · 自动记忆）Spec

## 背景

RhineCode 目前每次启动都是「失忆」的：C8 的上下文管理解决了**单次运行内**历史过长的问题，但进程一退出，一切归零——项目的技术栈约定要重新交代、用户纠正过的偏好会再犯、上次做到一半的任务无法接续。对话历史只存在于内存中的 `ConversationManager.history`，没有任何持久化。

业界成熟 Agent（以 Claude Code 为代表）用三套互补机制解决这个问题，分别对应三种「记忆」：

- **项目指令文件**（CLAUDE.md）——**用户手写**的长期记忆：技术栈、代码规范、注意事项，每次会话开始时注入上下文；
- **会话存档**（JSONL + `--resume`）——**工作记忆**的持久化：对话历史落盘，中断后可恢复接续；
- **自动记忆**（auto memory / MEMORY.md 索引）——**Agent 自己写**的长期记忆：从对话中沉淀用户偏好与项目知识，索引每次注入、正文按需读取。

本章（C9）为 RhineCode 实现同构的三套机制：**RHINE.md 三层项目指令**、**JSONL 会话存档与恢复**、**四类自动记忆 + 记忆索引**，并配套**锁文件并发防护**，保证多个 RhineCode 实例同时运行时记忆不被写坏。c5 的系统提示模块已为此预留了「自定义指令」（priority 110）与「长期记忆」（priority 130）两个空槽，本章正好填上；三层配置的加载合并模式复用 c6 权限 / c7 MCP 已验证的「用户级 + 项目级」心智模型。

## 目标

- 新会话启动时自动恢复项目知识与用户偏好：RHINE.md 与记忆索引在处理首个请求前就注入上下文，Agent 从「每次失忆」变成「越用越懂你」。
- 会话历史持久化为可恢复的存档：中断（正常退出、崩溃、断电）后能捞回旧会话平滑接着用。
- Agent 自动沉淀记忆，无需用户手动维护；去重与「值不值得记」交给 LLM 判断。
- 工作记忆（会话存档）与长期记忆（指令文件 + 自动记忆）分层管理，各自独立存储、互不耦合。
- 多实例并发运行时记忆不混乱：靠锁文件保证「写不坏」，拿不到锁时退让而非等待。
- 全程 fail-safe：任何记忆文件缺失、损坏、写入失败、锁不可用都不阻断启动与对话，最多退化为「没有这份记忆」。
- 用户能在会话内看到记忆系统的工作状态（加载了哪些指令文件、记了多少记忆）。

## 功能需求

### 一、项目指令文件（RHINE.md）

- **F1 三层加载**：依次读取 用户级 `~/.rhinecode/RHINE.md` → 项目级 `<项目根>/.rhinecode/RHINE.md` → 项目根 `<项目根>/RHINE.md`，按此顺序**拼接**（不覆盖）；越具体的层越靠后，利用近因效应让项目级指令在冲突时更占优（同 Claude Code 实测方案）。每层拼接时标注来源文件路径，让模型知道指令来自哪一层。缺失的层直接跳过；三层全缺时该部分为空、行为与 C9 之前完全一致。
- **F2 @include 引用**：指令文件内可用 `@相对路径` 语法引用其他文件，内容原地展开。规则：相对路径相对于**引用文件所在目录**解析；嵌套展开上限 **4 层**；用已访问集合（visited）防止循环引用（A 引 B、B 引 A 时第二次遇到即停）；引用目标解析后必须仍在宿主文件所属层的边界内（项目层文件只能引项目目录内的文件、用户层文件只能引用户目录内的文件），越界引用不展开；围栏代码块内的 `@` 不视为引用。
- **F3 加载 fail-safe**：单个文件读取失败、include 越界、超深度、循环，都只跳过出问题的部分并保留可读提示，不阻断启动与对话。
- **F4 注入位置**：拼接结果填入 c5 预留的系统提示「自定义指令」槽位（priority 110），在处理**首个请求前**就已生效（相当于模型「已经读过」，不需要也不应该再用工具去读一遍）。
- **F25 /init 生成 RHINE.md**：提供 `/init` 斜杠命令：以一条内置指令启动一次普通 Agent Loop，让模型探索项目（结构、技术栈、构建/测试命令、代码约定）后生成**项目根** `RHINE.md`；目标文件已存在时不覆盖，改为读取现有内容并提出补充改进（与 Claude Code 行为一致）。写盘经由普通 `write_file` 工具，走完整权限管线与人在回路确认。命令成对维护。依赖工具探索能力，仅 DeepSeek 工具模式生效。

### 二、会话存档（写）

- **F5 自动建档**：每次启动开启新会话时，在 `<项目根>/.rhinecode/sessions/` 下创建一个 JSONL 存档文件；会话 ID 格式 `YYYYMMDD-HHMMSS-xxxx`（时间戳 + 随机后缀防同秒撞车），文件名即会话 ID。
- **F6 追加写**：对话历史每新增一条消息（用户消息 / assistant 回复 / 工具结果），立即序列化为一行 JSON 追加到存档末尾；只追加、不回写、不重排，崩溃时最多丢失最后一行。写盘失败不阻断对话（本条丢失，后续继续尝试）。
- **F7 无独立 meta 文件**：不为会话维护单独的元数据文件；列表展示所需的 ID / 标题 / 消息数 / 最后时间，需要时直接扫描 JSONL 推导（标题取首条用户消息截断），少一份要保持同步的状态。
- **F8 /clear 开新档**：`/clear` 清空历史后，后续消息写入**新的**会话文件；旧存档保留不动。

### 三、会话恢复（读）

- **F9 /resume 命令**：无参数时列出最近若干个会话（编号、ID、标题摘要、消息数、时间）；`/resume <编号或ID>` 载入对应会话，替换当前历史。命令成对维护（`conversation.py` 逻辑 + 补全列表）。
- **F10 --continue 参数**：`rhine --continue` 启动时直接载入最近一次会话，进入界面即可接着聊。
- **F11 恢复的异常处理**：① 无法解析的坏行跳过，不因一行损坏放弃整个会话；② 工具调用消息没配上对应结果时做安全处理（截断或跳过该组），不让不成对的消息进入历史导致 API 报错；③ 载入后若估算 token 已逼近窗口上限，先走一次 C8 压缩再继续；④ 距存档最后一条消息超过 **24 小时**时，注入一条时间跨度提醒（告知模型「距上次对话已过去 X，环境可能已变化」）。
- **F12 恢复后接续写**：恢复的会话继续追加写入**同一个**存档文件；再次载入时对历史中间的不成对消息同样能安全处理。
- **F13 过期清理**：启动时静默删除最后修改时间超过 **30 天**的会话存档；清理时跳过被新鲜锁保护的会话，并顺带清理孤儿锁文件（有锁无档）。

### 四、自动记忆

- **F14 四类记忆**：用户偏好 / 纠正反馈 / 项目知识 / 参考资料。每条记忆一个带 frontmatter（名称、一行摘要、分类）的 Markdown 文件；**用户相关**（偏好、跨项目习惯）存用户级 `~/.rhinecode/memory/`，**项目相关**（项目知识、本项目约定）存项目级 `<项目根>/.rhinecode/memory/`，归属由 LLM 判断。
- **F15 触发与生成**：每轮 Agent Loop **自然停止**（最终回复不含工具调用）后，**异步**调一次 LLM 审视本轮新增对话，决定 新增 / 更新 / 删除 / 不动 记忆；「值不值得记」与去重全交给 LLM 判断。该请求**禁用工具**，LLM 只产出结构化的记忆内容与归类，**落盘由程序完成**（内部可信写盘，限定两个 memory 目录内，不经工具权限管线——LLM 说什么都跳不出目录边界）。异步执行不阻塞用户输入下一条消息。
- **F16 索引维护**：每个 memory 目录各有一份索引文件，每条记忆在索引中占一行（标题 + 文件名 + 一句钩子）；记忆变更后同步更新索引。索引超过 **200 行或 25KB**（先到为准）时只注入超限前的部分。
- **F17 记忆 fail-safe**：记忆 LLM 调用失败、返回不可解析、写盘失败，都静默跳过本轮更新（状态可在 `/memory` 中看到），不影响正常对话。

### 五、记忆索引注入与按需读取

- **F18 索引先注入**：两级索引内容在处理请求前注入 c5 预留的「长期记忆」槽位（priority 130）；记忆**正文不注入**，模型需要细节时按索引里的路径用读文件工具按需读取。用户级 memory 目录位于路径沙箱之外，须保证模型对它的**只读**访问不被沙箱拦截（具体机制 plan 阶段定），且仅放开这一个目录。

### 六、可观测

- **F19 /memory 命令**：只读报告——已加载的 RHINE.md 各层路径与大小、include 展开情况、两级记忆索引位置与是否超限、四类记忆数量、最近一次自动记忆更新的结果、当前会话 ID 与消息数、两级 memory 目录与当前会话的锁状态。命令成对维护。
- **F20 低打扰反馈**：自动记忆实际发生新增/更新时，界面给出一条低打扰的系统提示（类似 Claude Code 的「Writing memory」），让用户知道 Agent 记了东西；无变更的轮次不打扰。

### 七、生效范围

- **F21 按依赖分级**：RHINE.md 注入、会话存档/恢复、记忆索引注入 → 对**所有 Provider** 生效（不依赖工具）；自动记忆的生成与按需读取、`/init` 生成 → 仅 **DeepSeek 工具模式**（依赖工具与自然停止时机）。

### 八、并发防护（锁文件）

- **F22 记忆写入锁**：两个 memory 目录各设一个锁文件。每轮自动记忆要落盘（写/改记忆文件、重写索引）前，先**原子地**创建对应目录的锁文件（内容含持有者 PID 与时间戳）；创建失败说明另一实例正在写，**本轮记忆更新直接跳过、不等待**（记忆尽力而为，下轮再试）。写完（含失败路径）删除锁文件释放。锁只在一次写入期间短暂持有（秒级），不跨轮持有。
- **F23 会话独占锁**：会话存档处于**活跃写入**状态时（新建或恢复后），在 sessions 目录为其维护一个会话锁文件，每次追加消息时刷新其时间戳；正常退出时删除。`/resume` 与 `--continue` 载入目标会话前检查其锁：锁存在且仍然新鲜（近期有活动）→ **拒绝载入**并给出可读提示（「该会话正被另一个 RhineCode 实例使用」，`--continue` 时顺延到下一个最近的未锁定会话）；锁已过期（持有者崩溃残留）→ 清除后正常接管。新建会话因 ID 唯一天然无冲突，不需要锁检查。
- **F24 锁的 fail-safe 与自愈**：① 所有锁操作**非阻塞**——拿不到就退让（记忆跳过本轮、会话拒绝载入），绝不循环等待、绝不卡 UI、绝不崩溃；② 残留锁自愈——锁文件超过过期阈值视为崩溃残留，可被清除接管，不会把写入永久堵死；③ 锁文件自身损坏、无法创建或无法删除时，按「拿不到锁」的保守路径处理（宁可少写一次，不冒写坏记忆的风险）。

## 非功能需求

- **N1 低侵入**：三套机制各自封装为独立组件（对标 permission / mcp / context 的先例：纯逻辑 + 单点接入），只通过少量固定接入点挂进现有流程——启动时加载与清理、系统提示两个槽位的填充、历史新增消息时的追加写、Agent Loop 自然停止后的记忆钩子。Agent Loop 与 ConversationManager 的主流程不被打散、不为记忆铺满分支特例。
- **N2 fail-safe 全覆盖**：任何记忆文件缺失、损坏、读写失败、锁不可用，都降级为「没有这份记忆 / 本次不写」，绝不阻断启动、绝不中断对话、绝不崩溃（呼应 F3 / F6 / F11 / F17 / F24）。记忆是增强项，不是依赖项。
- **N3 性能**：启动时的同步工作（RHINE.md 加载展开、索引读取、过期清理、锁检查）都是轻量本地 IO，不显著拖慢启动；会话追加写是每条消息一次的常数级开销；记忆的 LLM 调用异步执行，不阻塞 UI 主线程，也不推迟用户下一条消息的处理。
- **N4 用户数据可读可编辑**：所有记忆文件都是纯文本（Markdown / JSONL），用户可以随时用任意编辑器查看、修改、删除任何一份；系统必须容忍外部修改——下次加载时按既有容错规则处理（坏行跳过、缺文件视为空），不因用户手动动过文件而出错。
- **N5 扩展兼容**：存储格式预留演进空间——JSONL 行与记忆 frontmatter 中出现**未知字段时忽略而不报错**（向前兼容：旧版本能读新版本写的文件）；新增记忆分类、新增存档字段不破坏已有文件的解析（向后兼容：新版本能读旧文件）。这是「坏行跳过」容错哲学的自然延伸：格式演进产生的「读不懂」和文件损坏产生的「读不懂」走同一条降级路径。
- **N6 安全与隐私**：① 会话存档含完整对话原文（可能包含被读过的敏感文件内容），`.rhinecode/sessions/` 与 `.rhinecode/memory/` 随 `.rhinecode/` 一并 git 忽略、勿提交；② 记忆落盘是**内部可信写盘**（同 c8 存盘先例）——不是模型发起的工具调用、不经权限管线，但写入路径由代码锁死在两个 memory 目录内；③ 用户级 memory 目录的只读放行是**精确到该目录**的例外，不扩大沙箱的其它任何面；④ 记忆与摘要类 LLM 请求一律禁用工具。
- **N7 教学可读**：新增代码遵循项目中文注释规范；关键流程（三层拼接与 include 展开、JSONL 追加与恢复的异常分级、记忆异步钩子与锁的获取释放、索引截断）注释清楚设计意图与边界条件。

## 不做的事

- 不做向量数据库 / RAG / embedding 语义检索——记忆召回只靠「索引注入 + 模型按路径读文件」，不做语义相似度匹配（留给后续章节或专门项目）。
- 不做团队记忆同步 / 跨机器共享——所有记忆都是本机文件；项目级文件随仓库提交与否由用户的 gitignore 决定，系统不做任何网络同步。
- 不做跨实例的实时一致性——锁文件只保证「写不坏」（文件不交错、索引不丢更新），不保证两个实例的记忆决策彼此实时可见：实例 A 刚记的记忆，实例 B 要到下次读索引才看到，期间可能产生语义重复的记忆，交给 LLM 去重在后续轮次收敛（F22–F24 划定的边界）。
- 不做记忆的会话内编辑命令——`/memory` 纯只读；增删改记忆、改 RHINE.md 都用编辑器直接操作文件（N4 已保证外部修改被容忍）。
- 不做记忆的自动清理与遗忘机制——30 天过期清理只针对会话存档；记忆不设过期，数量增长靠索引上限截断兜底，质量靠 LLM 去重收敛。
- 不做阈值可配置化——时间跨度提醒的 24 小时、会话过期的 30 天、索引的 200 行 / 25KB、锁过期阈值等均为固定常量（对齐 c8 惯例，可配置化留后续章节）。
- 不做存档格式的版本迁移工具——本章是存档格式的首个版本；未来格式演进靠 N5 的「未知字段忽略、坏行跳过」向前向后兼容，不做显式迁移。
- 不做会话存档的加密或压缩存储——纯文本 JSONL，安全靠 gitignore 与本机文件权限（N6）。
- 不改变「工具能力仅 DeepSeek 协议」的现状——自动记忆的生成与按需读取、`/init` 随之仅在该模式生效（F21）；Anthropic / OpenAI 享受 RHINE.md 注入与会话存档/恢复，但不产生记忆。

## 验收标准

### 项目指令文件（RHINE.md）

- **AC1**（F1）：三层各写入不同的可辨识内容后启动，系统提示的「自定义指令」槽位按 用户级 → 项目 `.rhinecode/` → 项目根 顺序包含全部三段、各自标注来源路径；删掉其中任意一层，其余两层仍正常注入。
- **AC2**（F2）：含 `@相对路径` 的指令文件被原地展开；构造 5 层嵌套时第 5 层不再展开；构造 A 引 B、B 引 A 的循环时加载正常结束、不死循环；构造指向层边界外的引用时不展开；围栏代码块里的 `@路径` 保持原文。
- **AC3**（F3）：include 指向不存在的文件、或某层文件不可读时，启动与对话正常，其余内容照常注入，问题位置留有可读提示。
- **AC4**（F4）：在 RHINE.md 写一条可观测指令（如「回复开头带固定标记」），启动后**首条**消息的回复即遵循——证明注入发生在首个请求前。
- **AC5**（F25）：在无 RHINE.md 的项目执行 `/init`，Agent 探索项目后经权限确认在项目根生成内容合理的 RHINE.md；在已有 RHINE.md 的项目执行 `/init`，原文件不被覆盖，得到的是补充改进建议。

### 会话存档与恢复

- **AC6**（F5/F6）：启动后聊若干轮，`<项目根>/.rhinecode/sessions/` 下出现 ID 符合 `YYYYMMDD-HHMMSS-xxxx` 的 `.jsonl`；行数与消息数一致、每行可独立解析；强杀进程后已写入的消息一条不丢。
- **AC7**（F7）：sessions 目录中无任何元数据文件；手工删除某个存档后 `/resume` 列表立即反映——证明列表信息来自现场扫描。
- **AC8**（F8）：`/clear` 后继续对话，消息写入新存档，旧存档内容不变。
