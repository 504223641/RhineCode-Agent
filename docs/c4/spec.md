# RhineCode Agent Loop Spec

## 背景

RhineCode 经过 c2（纯对话）、c3（工具系统）后，已经能让模型读写文件、执行命令、检索代码，但 c3 把工具编排写死成**单轮往返**：第一轮带工具请求 → 执行工具 → 第二轮强制产出最终回答，并丢弃第二轮里的任何工具调用。结果是模型「一步一停」——做完一步就必须等用户再催一句，无法自主完成多步任务。

c4 给 RhineCode 装上 **Agent Loop（ReAct 自主循环）**：模型先想、再调工具、看结果、边做边调整，一轮轮自动推进，直到任务完成或命中停止条件，从「被动应答」变成「能自主干活」的 Agent。同时引入与界面解耦的异步事件流、循环中的执行确认（含「本会话不再询问」），以及两段式 **Plan Mode**（先规划、按需澄清需求、用户审批后再执行）。

本章仍聚焦 **DeepSeek** Provider（c3 已实现工具能力的唯一 Provider）；Anthropic / OpenAI 维持纯对话。

## 目标

- 用真正的 ReAct 循环取代 c3 写死的单轮往返：循环调用模型、执行工具、回灌结果，直到模型不再要工具或命中停止条件。
- 提供多种明确、可区分的停止条件：模型自然完成、迭代上限（兜底安全网）、用户取消、连续未知工具、流出错。
- 引入一套与界面解耦的异步事件流（文本、思考、工具调用、工具结果、Token 用量、进度、结束），让 Agent 循环与 TUI 彻底解耦。
- 每轮流式响应走双路：一边实时把文本推给界面，一边攒出完整响应供循环判断是否续跑与如何回灌。
- 单轮多个工具调用按安全性分批：只读并发、有副作用串行（沿用 c3 规则，纳入循环每一轮）。
- 非 Plan Mode 下，有副作用工具执行前确认，提供「执行 / 本会话不再询问 / 取消」三态；选「不再询问」后本会话后续有副作用工具自动执行。
- 两段式 Plan Mode：`/plan` 开关切换，状态栏同步显示状态；开启时只放只读工具并引导模型先出计划，对不清楚的需求细节逐一弹多选面板向用户澄清，澄清完成（或需求明确）后询问是否开始执行，确认后本轮自动放开全部工具执行。
- **本章不做**：权限系统、上下文压缩、澄清面板的自由文本输入（详见「不做的事」）。

## 功能需求

- F1（Agent Loop）：用户一次请求触发一个自主循环——调用模型 → 若模型发起工具调用则执行并把结构化结果按协议顺序回灌对话历史 → 再次调用模型 → 重复，直到模型本轮不再发起工具调用，或命中某个停止条件。取代 c3 的写死单轮往返。

- F2（停止条件）：循环具备多种可区分的停止条件，每种停止都对应一个可观测的「结束原因」：
  - 自然完成——模型本轮不发起工具调用，产出最终文本后停止。
  - 迭代上限——累计迭代次数达到上限时强制停止（兜底安全网），并告知用户因达上限而停。
  - 用户取消——用户在循环运行中主动取消，循环在安全点停止。
  - 连续未知工具——模型连续多次（达到阈值）调用未知工具时停止，避免空转。
  - 流出错——底层流发生错误时终止本次循环并提示。

- F3（异步事件流）：Agent Loop 对外只产出一套与界面解耦的事件，至少涵盖：正文文本、思考内容、工具调用开始、工具执行结果、Token 用量、进度（当前处于第几轮迭代）、结束（携带结束原因）。界面只消费这些事件，不感知底层 Provider 流的细节。

- F4（双路流式收集）：每轮模型流式响应走双路——一边把文本与思考内容实时作为事件推给界面，一边在循环内部攒出该轮的完整响应（完整文本 + 完整工具调用列表），供循环判断是否继续、如何回灌历史。

- F5（多工具分批执行）：模型单轮发起多个工具调用时，按安全性分批：只读工具并发执行，有副作用工具串行执行（沿用 c3 规则，纳入循环的每一轮）。

- F6（执行前确认与「不再询问」）：非 Plan Mode 下，有副作用工具（写文件 / 改文件 / 执行命令）执行前弹出确认面板，提供三个选择——「执行」「执行且本会话不再询问」「取消」。选「执行」仅放行本次；选「不再询问」后，本会话（直到退出）后续所有有副作用工具自动执行、不再弹确认；选「取消」则把「用户拒绝执行」作为结构化结果回灌。只读工具不弹确认。

- F7（Token 用量呈现）：循环把每轮模型返回的 token 用量解析为用量事件，界面累计展示本次运行消耗的 token。

- F8（进度呈现）：循环每进入新一轮迭代产出进度事件，界面可见当前迭代序号（如「第 N 轮」），让用户感知自主循环的推进。

- F9（用户取消循环）：循环运行期间用户可触发取消；循环在当前安全点（不破坏正在进行的工具执行与历史回灌的一致性）停止，并以「用户取消」作为结束原因，TUI 随后恢复可用。

- F10（Plan Mode 开关与状态栏）：提供 `/plan` 斜杠命令切换 Plan Mode 开 / 关；状态栏实时显示当前是否处于 Plan Mode。仅在工具可用的 Provider（DeepSeek）下生效，其余 Provider 给出不支持提示。

- F11（Plan Mode 只读 + 引导）：Plan Mode 开启时，仅向模型暴露只读工具，并注入引导提示，要求模型先调研、产出计划、不要执行任何修改类操作。模型可在只读工具上循环调研后产出计划。

- F12（Plan Mode 需求澄清）：Plan Mode 规划期间，模型可就不清楚的需求细节逐一向用户提问。每个问题以面板形式呈现多个选项——每个选项含「概述」（一行，作为可上下导航选择的条目）与「详细描述」（说明该选项含义与取舍）；最推荐的选项排在第一位并带「推荐」标记；上下导航只在概述之间移动。用户选定后，所选项作为回答回灌模型，模型据此继续规划或继续提问。

- F13（Plan Mode 两段式执行）：所有需求细节澄清完成后（或需求本就明确、无需澄清时），模型向用户确认「是否开始执行」。用户确认后，本轮自动从「规划阶段」切换到「执行阶段」：放开全部工具、按计划自动执行（执行阶段不再逐个工具弹确认，计划审批本身即为放行）。Plan Mode 开关保持开启；本轮执行结束后，下一条用户消息重新回到规划阶段（重新只读、重新澄清、重新确认执行）。

- F14（纯对话与无工具兼容）：未启用工具的 Provider，或模型本轮不发起工具调用时，循环行为与一轮普通流式对话一致；不影响 `/think`、`/clear`、`/exit` 等既有斜杠命令。

## 非功能需求

- N1（不崩溃）：循环中任一环节出错（工具异常、JSON 参数解析失败、API / 流错误、用户取消）都被捕获，转为可观测事件或结束原因，程序不崩溃、TUI 保持运行。

- N2（不阻塞 UI）：整个循环（多轮请求、并发 / 串行执行、确认、澄清、取消）沿用现有 Worker + `call_from_thread` 机制，不阻塞主线程；确认与澄清等待用户输入时不得死锁流式 Worker 或主线程。

- N3（迭代上限兜底）：必须存在迭代上限，任何情况下循环都不会无限运行。

- N4（Agent 与界面解耦）：Agent Loop 不依赖 TUI 的具体实现，只通过事件流与必要的回调（确认、澄清）交互；新增或调整界面渲染不需改动循环核心逻辑。

- N5（历史一致性）：每轮的 assistant（含 tool_calls）消息与各 tool 结果消息按协议要求的顺序正确回灌历史，保证下一轮请求上下文完整、可被模型理解。

- N6（取消及时性）：用户取消应尽快生效（最迟在当前工具或当前轮结束后），不让用户长时间等待。

- N7（沿用 c3 安全边界）：文件 / 命令仍以项目工作目录为基准，不做沙箱隔离；危险操作由确认（非 Plan Mode）或计划审批（Plan Mode）兜底。

## 不做的事

- 不做权限系统 / 命令黑白名单 / 沙箱隔离（留待后续章节）。
- 不做上下文压缩 / 历史截断：循环可能让对话历史变长，本章不处理，靠迭代上限间接约束。
- 不做澄清面板的自由文本输入：只支持从预设选项中选择，不提供「其他 / 自定义输入」（留待后续）。
- 不扩展 Anthropic / OpenAI 的工具与循环能力：Agent Loop 与 Plan Mode 仍只在 DeepSeek 生效，架构保留扩展口。
- 不把迭代上限、连续未知工具阈值等暴露为 YAML 配置：本章用合理默认常量。
- 不做工具结果 / 计划 / 用量的持久化：只存在于本次运行的内存与对话历史中。
- 不做计划的结构化存档（如写入 `docs/`）：计划只作为模型的文本输出呈现给用户。
- 不做暂停 / 续跑 / 断点恢复：用户取消即终止本次循环。
- 不做有副作用工具之间的并行：写 / 改 / 命令一律串行执行。

## 验收标准

- AC1（自主多步循环）：提出一个需要多步工具的任务，模型连续多轮调用工具、每轮结果回灌、最终自动产出回答并停止，全程无需用户逐轮催促。（F1）

- AC2（自然完成停止）：模型某轮不再发起工具调用时，循环结束并给出最终文本回答。（F2）

- AC3（迭代上限兜底）：构造会持续请求工具的情形，累计达到迭代上限后强制停止并提示「因达上限停止」，程序不挂死。（F2 / N3）

- AC4（用户取消）：循环运行中触发取消，循环在安全点停止，结束原因为「用户取消」，TUI 仍可继续使用。（F2 / F9 / N6）

- AC5（连续未知工具停止）：模型连续调用未知工具达到阈值时停止，不空转。（F2）

- AC6（流出错停止）：底层流报错时循环终止并以错误事件提示，程序不崩溃。（F2 / N1）

- AC7（事件流可观测）：一次运行中能观察到文本、工具调用、工具结果、Token 用量、进度、结束等事件被界面消费。（F3）

- AC8（双路收集）：文本实时显示的同时，循环能基于攒出的完整响应正确识别本轮是否有工具调用并据此决定是否续跑。（F4）

- AC9（并发与串行）：单轮含多个只读工具时并发执行、含多个有副作用工具时串行执行，且纳入循环的每一轮。（F5）

- AC10（确认三态 + 不再询问）：非 Plan Mode 下有副作用工具弹出三选项（执行 / 不再询问 / 取消）；选「不再询问」后本会话后续有副作用工具自动执行、不再弹确认；选「取消」回灌「用户拒绝执行」。（F6）

- AC11（用量呈现）：运行中界面可见累计 token 用量。（F7）

- AC12（进度呈现）：运行中界面可见当前迭代轮次的推进。（F8）

- AC13（Plan 开关 + 状态栏）：`/plan` 切换 Plan Mode，状态栏同步显示开 / 关；非工具 Provider 给出不支持提示。（F10）

- AC14（Plan 只读 + 引导）：Plan Mode 下模型只能调用只读工具、不执行任何修改类操作，并产出计划。（F11）

- AC15（Plan 澄清面板）：Plan Mode 下模型可弹出多选澄清面板——选项含概述 + 详细描述、推荐项排首位带标记、导航在概述间移动；用户选择后所选项回灌模型，模型据此继续。（F12）

- AC16（Plan 两段式执行）：澄清完成后（或需求明确时）询问是否开始执行；确认后本轮自动放开全部工具执行且不再逐个确认；Plan Mode 仍保持开启；下一条用户消息重新进入规划阶段。（F13）

- AC17（纯对话兼容）：无工具 Provider 或模型不调工具时，循环等价于一轮普通流式对话；`/think`、`/clear`、`/exit` 不受影响。（F14）
