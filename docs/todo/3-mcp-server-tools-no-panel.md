# MCP Server 提供的工具在缺省预设下零面板

> 状态：待开工 · 预计半天～一天 · **优先级第三，因为它是 B4 修完之后剩下的那一半**
>
> 建议分支：`mcp-tool-confirm`（从 `main` 起）
>
> ⚠️ **这条是产品决策，不是补一个漏。** 开工第一件事不是改代码，
> 是先定「MCP Server 提供的工具该不该每次弹面板」，因为三种答案对应三种改法。

## 背景：它是 B4/B5 那次修复**没有**覆盖的那一半

2026-08-31 修 B4 时把 `mcp_add_server`（**添加** Server 这个动作）补回了人在回路确认，
新增了 `kind == "launch"` 这一类，接在权限管线第④层。

但 Server 添加进来之后，它**提供的那些工具**（`mcp__<server>__<tool>`）
在缺省预设下仍然是 `allow @ mode` —— **一次面板都不弹**。

B5 那一条审查项当时只要求「把不成立的文档改掉」，已照做：
`CLAUDE.md`、`docs/guide/mcp.md`、`docs/guide/permissions.md` 三处现在写的是实情。
**所以现在文档是诚实的，但那个缺口还在。**

## 为什么它是个真问题

`CLAUDE.md` 对 MCP 的定性一直是：

> 远端 Server 是外部程序、**不可信**

而在 C7 写下这条定性时，**唯一写明的缓解手段就是那句「每次调用都经人在回路确认」**。
auto-plan 扩展把缺省档换成放行档之后，兑现那句话的那一层没了。

⚠ **注意它与 B4 的差别**：B4 拦的是「把一个外部程序拉起来」这个**一次性**动作，
本条面对的是「那个程序注册进来的工具**此后每次被调用**」。
B4 修完之后，用户至少会在添加时看到一次面板 —— 但**他在那一次面板上批准的是
「让这个 Server 进来」，不是「它以后每次调用都不用问我」**。

## 三种可能的答案（先定这个）

| 答案 | 改法 | 代价 |
| --- | --- | --- |
| **A. 每次都问** | 给 MCP 工具一个自己的 `kind`，在第④层加一支（与 `launch` / `url` / `search` 同格） | 回到 C7 的原意；但常用 Server 会很吵，用户大概率会写 `allow` 规则一次性放开，等于绕回原点 |
| **B. 添加时问一次，之后放行** | 维持现状，但把「批准添加 = 批准它以后的全部调用」**在面板上写明白** | 最省事；但那句话一旦写明白，用户就会发现自己批准的东西比想象的大 |
| **C. 按工具只读与否分档** | 只读的放行、有副作用的问 | 最贴近本项目其余部分的口径（引擎本来就有只读短路）；但 MCP 工具的 `read_only` 由**远端自己声明**，而远端不可信 |

⚠ **C 那个「不可信的一方自己声明自己无害」的形态，本项目在别处已经明确拒绝过**
（`CLAUDE.md`：MCP 工具一律 `read_only=False`，理由逐字就是这个）。
所以选 C 的话必须先解释为什么这次可以信 —— **不能默认它是折中方案就是对的**。

## 要做什么

1. **先定答案**，把理由写下来。三选一，或提出第四种。
2. 若选 A：参照 B4 那次 `launch` 的落点（`permission/adapter.py` 的 `_TOOL_MAP` →
   `engine.py` 第④层 PERMISSIVE 分支 → `to_allow_rule` → 确认面板的补充展示行），
   **形态完全同格，照抄即可**。⚠ 那是一处四点成对维护点，见 `paired-maintenance`。
3. 若选 B：改的是 `tui/widgets.py` 里 `launch` 那段补充展示文案，
   把「批准之后会发生什么」写全。**这条改动最小但最容易被低估** ——
   它是唯一让用户知道自己批准了什么的地方。
4. 无论选哪个，**护栏都要钉「缺省预设下的实际判定」**，且判定链要
   **从 `presets.py` 现算**（`PRESET_AXES[DEFAULT_PRESET]`），不要硬编码档位名。
   B4 的成因就是「换缺省档时没人回来看这条承诺」，护栏必须挡住第二次。

## 判据

- 缺省预设下 `mcp__<server>__<tool>` 的判定符合你选的那个答案，且有护栏钉着
- 变异实测：把修复撤掉，护栏**真的会红**
- `CLAUDE.md` 那份「缺省下仍然会弹面板的只剩四类」清单跟着更新
- `python -m tests.run_parallel` 全绿
